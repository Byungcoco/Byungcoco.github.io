## 1. 개요

<Chips items={frontmatter.chips} />

이벤트 버스는 보내는 쪽과 받는 쪽이 서로를 모른 채 "이벤트 종류"만으로 이어지게 하는 구조입니다. 보내는 쪽은 Broadcast만 하고, 받을 쪽은 미리 Subscribe해 두었다가 Broadcast가 오면 호출됩니다. Subscriber 목록을 들고 한 번에 여러 함수를 부르는 부품이 Multicast Delegate이고, 이벤트 버스는 이 델리게이트를 이벤트 종류마다 하나씩 보관하는 전역 관리자입니다.

개인 프로젝트에서 만든 이 구조를 팀 프레임워크의 공용 통신 수단으로 가져왔습니다. 보스가 그로기에 빠지면 Broadcast만 하고, 약점 UI와 체력바 UI는 각자 Subscribe해서 반응하므로 보스 코드는 UI를 전혀 참조하지 않습니다. 같은 델리게이트 클래스를 모델이 직접 멤버로 두어 애니메이션 노티파이도 같은 방식으로 전달합니다.

## 2. 문제

> 팀 프로젝트에서는 한 사건에 반응해야 하는 쪽이 여러 사람의 코드에 흩어져 있었습니다. 보스가 그로기 상태가 되면 약점 UI가 떠야 하고, 사망 연출이 시작되면 체력바가 꺼져야 하며, 애니메이션 특정 프레임에서는 기믹·판정·이펙트·사운드·카메라가 동시에 움직여야 했습니다. 보스가 UI를 직접 찾아 호출하거나 UI가 매 프레임 보스 상태를 확인하면, 기능이 늘어날 때마다 서로의 코드를 고쳐야 합니다. 또 콜백 안에서 다른 Subscribe를 추가하거나 Unsubscribe하는 일이 생기는데, 이때 순회 중인 Subscriber 배열이 바뀌면 반복자가 깨집니다. 여러 사람이 이벤트를 정의하는 만큼, 콜백 함수의 형식이 이벤트와 맞지 않는 실수도 실행해 보기 전에 잡아야 했습니다.

## 3. 구조 요약

세 층으로 나눴습니다. `CMulticastDelegate`는 Subscriber 목록과 Broadcast만 담당하고, `CEventBus_Manager`는 이벤트 태그 타입마다 델리게이트를 하나씩 채널로 보관합니다. 게임 코드는 `CGameInstance`의 위임 함수로만 Subscribe·Broadcast합니다. 특정 객체에만 묶인 이벤트는 버스를 거치지 않고 델리게이트를 멤버로 직접 둡니다.

이벤트는 문자열이나 번호 대신 빈 태그 구조체로 구분합니다. 태그의 `type_index`가 채널의 키이고, 태그 안의 `Signature`가 그 채널의 콜백 형식입니다.

#### A. 태그 채널과 형식 검사

<Editor file="EventBus_Manager.h" fn="IChannel, Channel, CEventBus_Manager">

```cpp
struct IChannel
{
	virtual ~IChannel() = default;
};

// 멀티캐스트 래핑
template<class Signature>
struct Channel : IChannel
{
	CMulticastDelegate<Signature> multicast;
};

NS_BEGIN(Engine)

// ... 코드 중략

class CEventBus_Manager final : public CBase
{
	// ... 코드 중략
public:
	template<typename Tag, typename Func>
	DelegateHandle Add_Lambda(Func&& func)
	{
		using Sig = typename Tag::Signature;
		return Subscribe<Tag>(std::function<Sig>(std::forward<Func>(func)));
	}

	template<typename Tag>
	DelegateHandle Add_Static(typename Tag::Signature* pFunc)
	{
		using Sig = typename Tag::Signature;
		return Subscribe<Tag>(std::function<Sig>(pFunc));
	}

	template<typename Tag, typename T, typename... Args>
	DelegateHandle Add_MemFunc(T* pObj, void (T::* memFunc)(Args...))
	{
		using Sig = typename Tag::Signature;
		static_assert(std::is_same_v<Sig, void(Args...)>, "signature not match");
		return Subscribe<Tag>([pObj, memFunc](Args... args)
			{
				(pObj->*memFunc)(std::forward<Args>(args)...);
			});
	}
	// ... 코드 중략
	template<typename Tag, typename... Arg>
	void Broadcast(Arg&&... a)
	{
		auto itr = m_channels.find(std::type_index(typeid(Tag)));
		if (itr == m_channels.end()) return;

		auto* pChannel = static_cast<Channel<typename Tag::Signature>*>(itr->second);
		pChannel->multicast.Broadcast(std::forward<Arg>(a)...);
	}
	// ... 코드 중략
private:
	template<typename Tag>
	DelegateHandle Subscribe(std::function<typename Tag::Signature> func)
	{
		auto* channel = GetOrCreate<Tag>();
		return channel->multicast.Subscribe(std::move(func));
	}

	template<typename Tag>
	Channel<typename Tag::Signature>* GetOrCreate()
	{
		const std::type_index key{ typeid(Tag) };
		auto itr = m_channels.find(key);
		if (itr != m_channels.end())
			return static_cast<Channel<typename Tag::Signature>*>(itr->second);

		auto* pChannel = new Channel<typename Tag::Signature>();
		m_channels.emplace(key, pChannel);
		return pChannel;
	}
private:
	std::unordered_map<std::type_index, IChannel*> m_channels;
	// ... 코드 중략
};
```

</Editor>

채널마다 델리게이트의 형식이 다르므로 한 컨테이너에 그대로 담을 수 없습니다. 그래서 가상 소멸자만 있는 `IChannel`을 공통 부모로 두고, 꺼낼 때는 태그로 형식을 알고 있으므로 `static_cast`로 되돌립니다. 키가 `type_index`인 `unordered_map`이라 채널 탐색은 평균 O(1)이고, 채널은 처음 Subscribe될 때 만들어집니다. 아무도 Subscribe하지 않은 이벤트를 Broadcast하면 채널이 없으므로 바로 돌아옵니다.

멤버 함수 Subscribe는 `static_assert`로 멤버 함수의 형식이 태그의 `Signature`와 정확히 같은지 검사합니다. 이벤트 정의를 바꾸고 Subscribe하는 쪽을 고치지 않으면 실행 전에 컴파일 오류로 드러납니다. 람다와 정적 함수는 `std::function<Sig>`로 바로 변환하므로, 변환이 안 되는 형식이면 마찬가지로 컴파일되지 않습니다.

<Editor file="MulticastDelegate.h" fn="CMulticastDelegate<void(Args...)>">

```cpp
template<class T>
class CMulticastDelegate;

template<class... Args>
class CMulticastDelegate<void(Args...)>
{
	// ... 코드 중략
	struct Slot
	{
		bool bAlive = { false };
		DelegateHandle key = {};
		std::function<void(Args...)> func;
	};
public:
	CMulticastDelegate()
	{
		m_vecSlots.reserve(20);
		m_vecPending.reserve(10);
	}
	DelegateHandle Subscribe(std::function<void(Args...)> func) noexcept;
	bool Unsubscribe(DelegateHandle _handle) noexcept;
	void Clear() noexcept;

	// 타입일치 검사위해 A
	template<typename... A>
	void Broadcast(A&&... args)
	{
		static_assert(sizeof...(A) == sizeof...(Args), "Broadcast argument count must match the delegate signature");

		m_iBroadcastDepth++;
		for (size_t i = 0; i < m_vecSlots.size(); ++i)
		{
			if (!m_vecSlots[i].bAlive)
				continue;

			m_vecSlots[i].func(std::forward<A>(args)...);
		}
		m_iBroadcastDepth--;

		if (!IsBroadcasting())
			Apply_Pending();
	}

private:
	bool IsBroadcasting() const { return m_iBroadcastDepth > 0; }
	void Apply_Pending();
private:
	uint32_t m_iBroadcastDepth = { 0 };
	uint64_t m_iNextID = { 1 };
	std::vector<Slot> m_vecSlots;
	std::vector<Slot> m_vecPending;
};

template<class ...Args>
inline DelegateHandle CMulticastDelegate<void(Args...)>::Subscribe(std::function<void(Args...)> func) noexcept
{
	Slot slot = {};
	slot.bAlive = true;
	slot.key.iGeneration = 1;
	slot.key.iID = m_iNextID++;
	slot.func = std::move(func);

	if (IsBroadcasting())
		m_vecPending.emplace_back(std::move(slot));
	else
		m_vecSlots.emplace_back(std::move(slot));

	return slot.key;
}
```

</Editor>

주 템플릿은 선언만 하고 `void(Args...)` 형식에 대해서만 부분 특수화해, 반환값 없는 함수 형식만 받도록 했습니다. Subscribe 하나는 살아 있는지 여부(`bAlive`), Unsubscribe용 핸들, 콜백을 담은 슬롯입니다. 슬롯을 연속된 `vector`에 두어 Broadcast할 때는 앞에서부터 순서대로 훑기만 합니다. Broadcast 중에 Subscribe가 들어오면 본 목록이 아니라 대기 목록(`m_vecPending`)에 넣습니다.

#### B. Broadcast 중 Unsubscribe와 지연 반영

<Editor file="MulticastDelegate.h" fn="Unsubscribe(...), Apply_Pending()">

```cpp
template<class ...Args>
inline bool CMulticastDelegate<void(Args...)>::Unsubscribe(DelegateHandle _handle) noexcept
{
	bool bReturn = { false };

	if (IsBroadcasting())
	{
		for (auto& slot : m_vecSlots)
		{
			if (slot.bAlive && slot.key == _handle)
			{
				slot.bAlive = false;
				bReturn = true;
				break;
			}
		}

		for (auto& slot : m_vecPending)
		{
			if (slot.bAlive && slot.key == _handle)
			{
				slot.bAlive = false;
				bReturn = true;
				break;
			}
		}
	}
	else
	{
		auto itr = std::remove_if(m_vecSlots.begin(), m_vecSlots.end(),
			[&](const Slot& s) -> bool
			{
				return (s.bAlive && s.key == _handle);
			});

		if (itr != m_vecSlots.end())
		{
			bReturn = true;
			m_vecSlots.erase(itr, m_vecSlots.end());
		}
	}

	return bReturn;
}

// ... 코드 중략

template<class ...Args>
inline void CMulticastDelegate<void(Args...)>::Apply_Pending()
{
	auto itr = std::remove_if(m_vecSlots.begin(), m_vecSlots.end(),
		[&](const Slot& s)->bool
		{
			return !s.bAlive;
		});

	m_vecSlots.erase(itr, m_vecSlots.end());

	for (auto& slot : m_vecPending)
	{
		if (slot.bAlive)
			m_vecSlots.emplace_back(std::move(slot));
	}
	m_vecPending.clear();
}
```

## 5. 피드백

**Broadcast 인자는 개수만 검사하고 형식은 검사하지 않습니다.** Subscribe 쪽은 `Signature`와 정확히 같은지 검사하지만, Broadcast 쪽 `static_assert`는 인자 개수만 비교합니다. 그래서 `int`를 받는 이벤트에 `float`를 넘기는 것처럼 암시적으로 변환되는 실수는 경고 없이 컴파일되고, 값이 잘린 채로 전달됩니다. 각 인자가 `Signature`의 매개변수로 변환 가능한지까지 검사하거나, Broadcast 함수의 매개변수를 `Signature`에서 직접 뽑아 쓰는 편이 Subscribe 쪽 검사와 짝이 맞습니다.

남은 개선점입니다.

- `Broadcast`가 같은 인자를 Subscriber마다 `std::forward`로 넘깁니다. 이동 가능한 값을 넘기면 두 번째 Subscriber부터 이미 옮겨진 빈 값을 받습니다. 지금은 포인터·정수·`const&`만 넘겨서 드러나지 않았습니다.
- Subscribe·Broadcast에 동기화가 없어 메인 스레드에서만 써야 하는데, 이 전제가 코드에 드러나 있지 않습니다.
