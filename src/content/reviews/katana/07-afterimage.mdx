## 1. 개요

<Chips items={frontmatter.chips} />

잔상은 지나간 프레임을 잠깐 남겨 두었다가 서서히 투명하게 지우는 연출입니다. 자주 생기고 금방 사라지기 때문에, 미리 잡아 둔 데이터를 재사용해 생성·삭제 비용을 없애고 색 변환처럼 비싼 처리는 로드 시점에 끝내 두는 것이 일반적입니다.

잔상을 애니메이터의 고정 크기 데이터로 두어 기록할 때 할당이 없고, 잔상이 오브젝트 매니저나 충돌 목록에 들어가지도 않습니다. 색은 로드 시점에 만든 시트로 해결해 실행 중에는 색을 계산하지 않습니다.

## 2. 문제

> 플레이어 구르기와 보스 공격에는 지나간 자리에 색이 입혀진 잔상이 남아야 합니다. 잔상이 생길 때마다 오브젝트를 만들면 0.03초마다 생성·삭제가 반복되고, 잔상까지 충돌·업데이트 목록에 들어갑니다. 잔상마다 GDI+로 색을 바꿔 그리면 매 프레임 색 변환 비용이 들고, 기존 시트에는 투명도 정보가 없어 반투명하게 그릴 수도 없었습니다.

## 3. 구조 요약

잔상은 오브젝트가 아니라 애니메이터가 가진 고정 크기 데이터입니다. 이미지를 복사하지 않고 "어느 시트의 어느 칸을 어디에" 그릴지만 기록하며, 색은 로드 시점에 만든 시트로 해결합니다.

잔상 데이터를 크기 15의 `m_AfterImageDataPool`로 미리 잡아 두고, 활성 개수 `m_iActiveCount`로 사용 중인 구간을 나눕니다. `Write`는 활성 구간 끝에 기록하고, `Update`는 다 사라진 잔상을 회수하며, `Draw`는 색 시트를 `AlphaBlend`로 반투명하게 그립니다.

```cpp
void CAfterImage::Write(const Vector2 &_iPos, const Vector2 &_iRectSize, CAnimationBitmap *_pAnimationBmp)
{
	if (m_iActiveCount >= m_AfterImageDataPool.size())
		return;

	m_AfterImageDataPool[m_iActiveCount].pAnimationBmp = _pAnimationBmp;
	m_AfterImageDataPool[m_iActiveCount].iPos_x = (int)_iPos.x;
	m_AfterImageDataPool[m_iActiveCount].iPos_y = (int)_iPos.y;
	m_AfterImageDataPool[m_iActiveCount].iSheet_x = (int)_iRectSize.x;
	m_AfterImageDataPool[m_iActiveCount].iSheet_y = (int)_iRectSize.y;
	++m_iActiveCount;
}
```

잔상 한 장은 위치·시트 좌표·시트 포인터·알파만 가진 작은 구조체입니다. 이미지를 복사하지 않고 리소스 매니저가 보관한 시트를 가리키기만 합니다. 기록은 활성 구간 끝에 쓰고 개수만 늘리므로 할당이 일어나지 않습니다.

#### B. swap 회수

<Editor file="CAfterImage.cpp" fn="Update(...)">

```cpp
void CAfterImage::Update(const float _fDeltaTime)
{
	for (int i = 0; i < m_iActiveCount; ++i)
	{
		if (m_AfterImageDataPool[i].fAlpha <= 0.1f)
		{
			--m_iActiveCount;
			std::swap(m_AfterImageDataPool[i], m_AfterImageDataPool[m_iActiveCount]);
			m_AfterImageDataPool[m_iActiveCount].Clear();
			--i;
		}
	}
}
```

</Editor>

<Fig n={2} white max={440} src="/img/reviews/katana/07-afterimage/pool.png" caption="활성 개수와 swap 회수" />

알파가 0.1 이하로 떨어진 잔상은 마지막 활성 칸과 자리를 바꾸고 개수를 줄입니다(<FigRef n={2} />). 바꿔 온 칸도 검사해야 하므로 `i`를 하나 되돌립니다. 순서는 바뀌지만 잔상끼리는 순서가 상관없어서 O(1)로 회수할 수 있습니다.

#### B. AlphaBlend용 DIB

<Editor file="CMyBitmap.cpp" fn="CreateDIB(...)">

```cpp
void CMyBitmap::CreateDIB(Gdiplus::Bitmap *pSrcSheet, TintColor _e)
{
	UINT w = pSrcSheet->GetWidth();
	UINT h = pSrcSheet->GetHeight();

	// DIBSection 생성 (top-down)
	BITMAPINFO bmi = {};
	bmi.bmiHeader.biSize = sizeof(bmi.bmiHeader);
	bmi.bmiHeader.biWidth = w;
	bmi.bmiHeader.biHeight = -static_cast<LONG>(h);
	bmi.bmiHeader.biPlanes = 1;
	bmi.bmiHeader.biBitCount = 32;
	bmi.bmiHeader.biCompression = BI_RGB;

	void *pvBits = nullptr;
	HBITMAP hDib = CreateDIBSection(nullptr, &bmi, DIB_RGB_COLORS, &pvBits, nullptr, 0);

	// GDI+ LockBits 로 ARGB 데이터 복사
	Gdiplus::BitmapData bd;
	Gdiplus::Rect       rc(0, 0, w, h);
	pSrcSheet->LockBits(&rc, Gdiplus::ImageLockModeRead, PixelFormat32bppPARGB, &bd);

	for (UINT y = 0; y < h; ++y) {
		BYTE *srcRow = static_cast<BYTE *>(bd.Scan0) + bd.Stride * y;
		BYTE *dstRow = static_cast<BYTE *>(pvBits) + w * 4 * y;
		memcpy(dstRow, srcRow, w * 4);
	}
	pSrcSheet->UnlockBits(&bd);

	m_AlphaBitmaps[(uint8_t)_e] = AlphaBitmapData(hDib);
}
```

</Editor>

`AlphaBlend`에는 픽셀마다 투명도가 들어 있는 32비트 이미지가 필요합니다. 일반 시트는 투명도 없이 만든 비트맵이라, 색 시트는 DIB로 따로 만들고 GDI+의 픽셀 데이터를 그대로 복사해 둡니다.

## 5. 피드백

**그리기 함수가 잔상의 상태까지 바꾸고 있었습니다.** `Draw`가 그린 뒤 알파를 깎고 `Update`는 회수만 하니, 그리기가 상태를 바꾸는 구조가 됐습니다. 그리기가 호출되지 않으면 잔상도 줄어들지 않습니다. 알파 감소는 `Update`로 옮기고, `Draw`는 그리기만 하도록 나눴어야 했습니다.

남은 개선점입니다.

- 잔상 색이 풀의 칸 번호로 정해져, swap 회수 때 떠 있던 잔상의 색이 바뀔 수 있습니다. 색은 기록할 때 정해 `AfterImageData`에 저장해야 합니다.
- 색 시트 생성 코드가 시트 생성 함수마다 반복되므로, 색 행렬 목록을 받아 한 번에 만드는 함수로 묶을 수 있습니다.
