## 1. 개요

<Chips items={frontmatter.chips} />

메멘토 패턴은 객체의 내부 상태를 밖으로 드러내지 않은 채 스냅샷으로 저장했다가, 나중에 그 상태로 되돌리는 패턴입니다. 이 스냅샷을 일정 간격으로 쌓아 되감기와 리플레이를 만들고, 슬로모션은 시간 배율로 연출했습니다.

스냅샷의 내용은 오브젝트 계열만 다루므로 저장 항목이 바뀌어도 매니저는 영향을 받지 않고, `deque` 덕분에 되감기와 리플레이 모두 O(1)로 꺼냅니다.

## 2. 문제

> 원작의 되감기·리플레이를 구현하려면 오브젝트의 상태를 시간 순서대로 기록하고, 앞뒤 양쪽에서 꺼낼 수 있어야 합니다. 처음에는 오브젝트가 자기 상태를 직접 `vector`에 저장했는데, 저장 대상이 늘수록 저장 로직이 중복되고 책임이 섞였습니다. 슬로모션 중에도 **실제 시간으로 흘러야 하는 값**(능력 게이지, 제한 시간)을 따로 다룰 방법도 필요했습니다.

## 3. 구조 요약

오브젝트는 자기 상태를 담은 스냅샷(`CMemento`)을 만들고 복원하는 일만 합니다. 언제 기록하고 어느 쪽에서 꺼낼지는 매니저와 씬이 정합니다. 슬로모션은 시간 배율로 처리하면서, 배율과 무관한 실제 시간 델타를 따로 제공합니다.

오브젝트 한 프레임의 위치·방향, 애니메이션 키와 프레임(`AnimKey`·`FrameIndex`), 풀 안의 위치(`VisibleIndex`)를 담는 스냅샷입니다. 내용은 `friend`로 지정한 오브젝트 계열만 읽고 쓰며, 저장 항목이 다른 타입은 `CreateMemento()`·`Restore()`를 오버라이드합니다.

스냅샷을 타입별 `deque`(`m_Snapshots`)에 쌓아 두고, 되감기와 리플레이 순서에 맞춰 꺼냅니다. `Store()`는 뒤에 쌓고, `Restore()`는 뒤에서, `Replay()`는 앞에서 꺼냅니다. 플레이어 기록이 비면(`IsEmpty()`) 재생이 끝납니다.

처음에는 `vector`를 썼습니다. 되감기처럼 맨 뒤에서 빼는 것은 문제없었지만, 리플레이처럼 맨 앞에서 빼면 O(n)이었습니다. `deque`로 바꾼 뒤로는 뒤에 쌓고, 되감기는 뒤에서, 리플레이는 앞에서 모두 O(1)로 꺼냅니다(<FigRef n={2} />).

<Editor file="CScene.cpp" fn="Store(), Rewind(...), Replay(...)">

```cpp
void CScene::Store()
{
	m_fElapsedTime += CTimeManager::Get_Instance()->GetDeltaTime();
	if (m_fElapsedTime >= CAPTURETIME)
	{
		CTimeManager::Get_Instance()->SetState(TimeState::NORMAL);
		CMementoManager::Get_Instance()->Store();
		m_fElapsedTime -= CAPTURETIME;
	}
}

void CScene::Rewind(float _fDeltaTime)
{
	if (!CMementoManager::Get_Instance()->IsEmpty())
	{
		m_fElapsedTime += _fDeltaTime;
		if (m_fElapsedTime >= CAPTURETIME)
		{
			CMementoManager::Get_Instance()->Restore();
			m_fElapsedTime -= CAPTURETIME;
		}
	}
}

void CScene::Replay(float _fDeltaTime)
{
	if (!CMementoManager::Get_Instance()->IsEmpty())
	{
		m_fElapsedTime += _fDeltaTime;
		if (m_fElapsedTime >= CAPTURETIME)
		{
			CMementoManager::Get_Instance()->Replay();
			m_fElapsedTime -= CAPTURETIME;
		}
	}
}
```

</Editor>

스냅샷을 델타타임마다 기록했을 때는 오버헤드가 있었습니다. 그래서 델타타임을 누적하다 1/60초를 넘을 때마다 한 번씩 기록하도록 바꿔, 프레임 간격과 상관없이 기록 횟수를 일정하게 맞췄습니다(<FigRef n={3} />). 되감기와 리플레이도 같은 간격으로 꺼내므로 기록할 때와 같은 속도로 재생됩니다.

`SetState`로 시간 상태를 배율 `m_fTimeScale`(보통 1, 슬로우 0.3, 빠름 2, 정지 0)에 반영합니다. 게임 로직이 쓰는 배율 적용 델타 `GetDeltaTime()`과, 슬로모션과 무관한 실제 시간 델타 `GetUnscaledDeltaTime()`을 함께 제공합니다.

#### A. 배율과 두 가지 델타

```cpp
inline void CTimeManager::SetState(const TimeState &_eState)
{
	if (_eState >= TimeState::NONE || _eState == m_eState)
		return;

	switch (_eState)
	{
	case TimeState::NORMAL:
		m_fTimeScale = 1.f;
		break;
	case TimeState::SLOW:
		m_fTimeScale = 0.3f;
		break;
	case TimeState::FAST:
		m_fTimeScale = 2.0f;
		break;
	case TimeState::PAUSE:
		m_fTimeScale = 0.f;
		break;
	}

	m_eState = _eState;
}
// ... 코드 중략

void CTimeManager::Update()
{
	::QueryPerformanceCounter(reinterpret_cast <LARGE_INTEGER *>(&m_tCurTime));

	float fElapsed = (m_tCurTime - m_tPrevTime) / static_cast<float>(m_tFreq);
	m_tPrevTime = m_tCurTime;
	m_fUnscaledDeltaTime = fElapsed;
	m_fScaledDeltaTime = fElapsed * m_fTimeScale;
	m_fTotalTime += m_fUnscaledDeltaTime;
```

한 프레임의 실제 경과 시간을 먼저 구하고, 거기에 배율을 곱한 값을 따로 둡니다. 게임 로직은 배율이 적용된 시간을, 게이지와 제한 시간은 실제 시간을 씁니다(<FigRef n={4} />). 오브젝트는 기본으로 배율 적용 델타를 받으므로, 슬로모션이 걸리면 오브젝트 전체가 함께 느려집니다.

## 5. 피드백

**저장·되감기·리플레이가 타입별로 복사한 루프를 각자 들고 있었습니다.** 매니저의 세 함수마다 몬스터 타입별 루프가 세 번씩 들어 있어서, 몬스터 종류가 하나 늘면 세 함수를 모두 고쳐야 합니다. 기록 대상 타입 목록을 루프 하나로 순회해 세 함수가 같은 코드를 쓰게 했어야 했습니다.

남은 개선점입니다.

- 이펙트용 스냅샷(`CEffectMemento`)과 저장·복원 함수는 틀만 있고 내용이 비어 있어, 되감기 중에는 이펙트가 복원되지 않습니다.
- 되감기·리플레이에서 풀의 오브젝트 목록을 값으로 복사해 쓰고 있어, 참조로 받아야 합니다.
