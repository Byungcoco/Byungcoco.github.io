## 1. 개요

<Chips items={frontmatter.chips} />

컬링은 화면에 보이지 않는 대상을 그리기 전에 걸러 내는 기법입니다. 2D에서는 카메라가 보는 사각형과 오브젝트의 사각형(AABB)이 겹치는지 비교하는 것이 가장 단순한 방법이고, 대상이 많아지면 공간 분할 구조로 비교 횟수 자체를 줄입니다.

화면 밖 오브젝트의 렌더 호출을 건너뛰면서, 모든 오브젝트를 그리던 초기에 떨어지던 프레임 문제를 줄였습니다.

## 2. 문제

> 맵은 화면보다 훨씬 크고, 그 위에 지형·몬스터·이펙트가 넓게 깔려 있습니다. GDI는 CPU로 그리기 때문에 그리기 호출 하나하나가 비싼데, 처음에는 화면 밖의 오브젝트까지 모두 그려 실제로 프레임이 떨어졌습니다. 카메라는 플레이어를 따라가되, 맵 가장자리에서는 맵 밖이 보이지 않도록 멈춰야 했습니다.

## 3. 구조 요약

카메라 매니저는 화면 오프셋 하나만 관리하고, 모든 오브젝트는 이 오프셋으로 화면 좌표를 구합니다. 오브젝트 매니저와 풀은 그리기 직전에 카메라에게 화면 안인지 묻고, 밖이면 렌더 호출을 건너뜁니다.

화면 왼쪽 위의 월드 좌표인 오프셋 `m_Diff` 하나로 월드 좌표와 화면 좌표를 오가고, `IsInCamera`로 화면 안에 있는지 판정합니다. 오프셋은 `CalDiff()`가 따라갈 대상 `m_pTarget`을 기준으로 계산하고, 맵 크기 `m_CurMapSize` 안으로 제한합니다.

#### A. 오프셋과 맵 경계 고정

<Editor file="CCameraManager.cpp" fn="Update(...), CalDiff()">

```cpp
void CCameraManager::Update(const float _fDeltaTime)
{
	if (m_pTarget)
	{
		m_LookAt = m_pTarget->GetPos();
	}

	// 화면 중앙좌표와 카메라 LooAt좌표간의 차이값 계산
	CalDiff();
}
// ... 코드 중략

void CCameraManager::CalDiff()
{	
	m_Diff = { m_LookAt - Constants::Resolution_Half };
	m_PrevLookAt = m_LookAt;
	if (m_Diff.x < 0)
		m_Diff.x = 0.f;
	else if (m_Diff.x > m_CurMapSize.x - Constants::Resolution.x)
		m_Diff.x = m_CurMapSize.x - Constants::Resolution.x;

	if (m_Diff.y < 0)
		m_Diff.y = 0.f;
	else if (m_Diff.y > m_CurMapSize.y - Constants::Resolution.y)
		m_Diff.y = m_CurMapSize.y - Constants::Resolution.y;
// ... 코드 중략
}
```

바라보는 점이 화면 가운데에 오도록, 그 위치에서 화면 절반을 뺀 값을 오프셋으로 씁니다. 오프셋이 0보다 작거나 맵 크기에서 화면 크기를 뺀 값보다 크면 그 값에 고정하므로, 맵 가장자리에서는 카메라가 멈추고 플레이어만 움직입니다(<FigRef n={2} />).

#### B. 화면 안 판정

<Editor file="CCameraManager.cpp" fn="IsInCamera(...)">

```cpp
bool CCameraManager::IsInCamera(const Vector2 &Pos, const Vector2 &Size)
{
	Vector2 RenderPos = Pos - m_Diff;
	float fDistance = 100.f;

	return !(RenderPos.x + Size.x * 0.5f + fDistance < 0 || RenderPos.x - Size.x * 0.5f - fDistance > Constants::Resolution.x
		|| RenderPos.y + Size.y * 0.5f + fDistance < 0 || RenderPos.y - Size.y * 0.5f - fDistance > Constants::Resolution.y);
}
```

</Editor>

#### B. 풀 오브젝트

<Editor file="CObjectPool.h" fn="Render(...)">

```cpp
template<IsObject T>
inline void CObjectPool<T>::Render(HDC hDC)
{
	for (int i = 0; i <= m_iActiveTopIndex; ++i)
	{
		if (CCameraManager::Get_Instance()->IsInCamera(m_Objects[i]->GetPos(), m_Objects[i]->GetSize()))
		{
			m_Objects[i]->Render(hDC);
		}
	}
}
```

풀은 활성 구간(`0 ~ m_iActiveTopIndex`)만 돌면서 같은 판정을 거칩니다. 회수된 오브젝트는 애초에 순회하지 않고, 활성 오브젝트도 화면 밖이면 그리지 않습니다.

## 5. 피드백

**컬링 비용이 오브젝트 수만큼 그대로 늘어납니다.** 매 프레임 모든 오브젝트를 하나씩 검사하므로, 판정 자체는 가벼워도 맵이 커질수록 화면 밖 오브젝트를 걸러 내는 데만 드는 시간이 늘어납니다. 공간을 격자나 트리로 나눠, 화면과 겹치는 칸의 오브젝트만 꺼내 검사했어야 했습니다.

남은 개선점입니다.

- 가장 큰 그림인 배경은 맵 전체 크기로 `TransparentBlt`를 호출합니다. 오프셋 위치에서 화면 크기만큼만 잘라 그려야 합니다.
- 레이어마다 같은 판정 코드가 반복되므로, 레이어 배열을 순서대로 도는 루프 하나로 묶을 수 있습니다.
