## 1. 개요

<Chips items={frontmatter.chips} />

스프라이트시트는 여러 프레임 이미지를 한 장에 모아 두고, 그릴 때 잘라 올 영역만 바꿔 프레임을 넘기는 방식입니다. 이미지를 바꾸지 않고 위치 계산만으로 애니메이션을 재생할 수 있고, 반전·회전처럼 비싼 가공도 미리 끝내 둘 수 있습니다.

반전·회전을 미리 그려 둔 시트 덕분에, 실행 중에는 이미지를 돌리지 않고 잘라 올 위치만 계산해 그립니다.

## 2. 문제

> 원작 리소스는 애니메이션마다 폴더 하나에 프레임 PNG가 번호별로 나뉘어 있습니다. 이 PNG를 매 프레임 GDI+로 그리면 느리고, 베기 이펙트처럼 방향에 따라 돌려 그려야 하는 이미지는 실시간 회전 비용까지 더해집니다. 게다가 폴더의 파일을 이름 순서로 읽으면 `0, 1, 10, 11, 2, …` 순서가 되어, 프레임이 10장을 넘는 애니메이션은 순서가 뒤섞였습니다.

## 3. 구조 요약

파일 매니저는 정렬된 프레임 목록까지만 만들고, 시트 합성과 보관은 리소스 매니저가 키 단위로 맡습니다. 애니메이터는 시트 종류와 상관없이 프레임 번호·방향·각도로 잘라 올 위치만 계산합니다.

`SetAnimDataFromFolder`는 애니메이션 폴더를 받아, 번호 순으로 정렬한 프레임 비트맵 목록을 돌려줍니다. 파일명은 `AnimPathParts`에 태그·이름·번호로 나눠 담고, `PathSorter`가 번호를 정수로 바꿔 비교합니다.

#### A. 수집과 파일명 분해

<Editor file="CFileManager.cpp" fn="SetAnimDataFromFolder(...)">

```cpp
// 해당 파일 기준 폴더에 접근하기 위한 iterator
std::filesystem::directory_iterator dir_Begin{ relPath_in };
std::filesystem::directory_iterator dir_End{};

// vector reserve용 폴더 내 파일카운팅
size_t FileCount = std::count_if(dir_Begin, dir_End,
    [](const std::filesystem::directory_entry &entry)->bool
    { return entry.is_regular_file(); });

// itr 다시 지정
dir_Begin = std::filesystem::directory_iterator{ relPath_in };
vector<AnimPathParts> Paths(FileCount);
// ... 코드 중략

std::wregex rule1{ L"^([[:alpha:]]+)_(.+)_([[:digit:]]+)$" };
// ... 코드 중략

for_each(Paths.begin(), Paths.end(), [&wstr_End, &rule1](AnimPathParts &element_in)->void {
    std::wstring tmp{ element_in.wPath.stem() };

// ()를 캡쳐단위로보고, 해당 캡쳐단위 만큼 wsmatch 배열에 저장
if (std::wsmatch match; std::regex_match(tmp, match, rule1))
{
    // 0부터가 아닌 1부터 index 시작, 0은 문자열 전체
    element_in.wTag = match[1];
    element_in.wIndex = match[3];
// ... 코드 중략
}
    });
```

#### B. 번호 정렬

```cpp
    typedef struct tagPathSorter
    {
        bool operator ()(AnimPathParts &data1, AnimPathParts &data2)
        {
            return std::stoi(data1.wIndex) < std::stoi(data2.wIndex);
        }
    }PathSorter;
    // ... 코드 중략
    // 문자열 정렬 오류는 10개이상일때만 일어나니 이때 체크!
    if (Paths.size() > 10)
        std::sort(Paths.begin(), Paths.end(), PathSorter());

    // Gdiplus를 통해 PNG Bitmap 임시 로드
    vector<Bitmap *> tmpBitmaps;
    for (const auto &framePath : Paths)
    {
#undef new
        Bitmap *bmp = new Gdiplus::Bitmap(framePath.wPath.c_str());
#define new DBG_NEW
        if (bmp->GetLastStatus() != Gdiplus::Ok)
            throw std::runtime_error("Failed to load File!");

        tmpBitmaps.push_back(bmp);
    }
```

```cpp
// 회전시 이미지 잘려나가는거 방지를 위함
int iDiag = sqrt(iFrameWidth * iFrameWidth + iFrameHeight * iFrameHeight);
int iPaddedSize = static_cast<int>(ceil(iDiag)) + 1;
// ... 코드 중략

const int iRowCount = (int)(360.f / _fAngleStep);

const int sheetWidth = iPaddedSize * iFrameCount;
// 24방향
const int sheetHeight = iPaddedSize * iRowCount;
// ... 코드 중략

for (int iRow = 0; iRow < iRowCount; ++iRow)
{
    // 15도씩 24개
    float destAngle = (float)(iRow * _fAngleStep);

    for (int i = 0; i < iFrameCount; ++i)
    {
        int destX = i * iPaddedSize;
        int destY = iRow * iPaddedSize;
        // 회전용 임시
        Bitmap RotatedBmp{ iPaddedSize, iPaddedSize, PixelFormat32bppPARGB };
        Gdiplus::Graphics g(&RotatedBmp);
        g.Clear(Gdiplus::Color::Transparent);

        g.SetSmoothingMode(Gdiplus::SmoothingModeHighQuality);
        g.SetInterpolationMode(Gdiplus::InterpolationModeHighQualityBicubic);

        // 회전 중심
        g.TranslateTransform(iPaddedSize * 0.5f, iPaddedSize * 0.5f);
        g.RotateTransform(destAngle);
        // 원본 이미지 중심
        g.TranslateTransform(-iFrameWidth * 0.5f, -iFrameHeight * 0.5f);

        // bitmap 회전시키고 그리기 (회전이 적용된 상태에서 그림)
        g.DrawImage(_Bitmaps[i], 0, 0, iFrameWidth, iFrameHeight);

        // 시트에 그리기
        sheetG.DrawImage(&RotatedBmp, destX, destY);
    // ... 코드 중략
    }
}
```

#### A. 각도 → 행

<Editor file="CAnimationBitmap.h" fn="GetRowFromAngle(...)">

```cpp
int GetRowFromAngle(float _fAngle) const
{
	while (_fAngle < 0.f) _fAngle += 360.f;
	while (_fAngle >= 360.f) _fAngle -= 360.f;

	return (int)(_fAngle / m_fAngleStep) % m_iAngleCount;
}
```

</Editor>

음수나 360도를 넘는 각도도 0도 이상 360도 미만으로 맞춘 뒤, 각도 단계로 나눠 행을 정합니다. 각도를 행으로 바꾸는 규칙(행 = 각도 ÷ 단계)이 시트를 만들 때의 규칙과 같은 클래스 안에 있습니다.

## 5. 피드백

**시트 생성 함수 다섯 개가 거의 같은 코드를 나눠 갖고 있었습니다.** 크기 계산, 프레임 정보 설정, 반전 행 그리기, `HBITMAP` 변환이 함수마다 들어 있어서 한 곳을 고치면 나머지도 모두 찾아 고쳐야 했습니다. 공통 단계를 함수로 빼고, 시트마다 프레임을 그리는 방식만 다르게 했어야 했습니다.

남은 개선점입니다.

- 실행할 때마다 시트를 다시 합성하므로 리소스가 늘수록 로딩이 길어집니다. 한 번 만든 시트는 파일로 저장해 읽는 편이 낫습니다.
- 정렬은 10장을 넘을 때만 하지만, 폴더를 읽는 순서는 표준이 보장하지 않으므로 항상 정렬하는 편이 안전합니다.
- 반복 재생 여부가 공유 시트(`CAnimationBitmap`)에 들어 있어, 오브젝트마다 다른 재생 상태는 애니메이터의 `PlayState`로 옮겨야 합니다.
