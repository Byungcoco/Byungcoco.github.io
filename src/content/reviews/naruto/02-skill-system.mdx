## 1. 개요

<Chips items={frontmatter.chips} />

이벤트 버스는 보내는 쪽과 받는 쪽이 서로를 모른 채 이벤트 종류만으로 이어지게 하는 구조입니다. 여기에 데이터 주도 설계를 더하면 공통 흐름은 코드 한 곳에 두고, 객체마다 다른 동작은 커맨드 목록 같은 데이터로 정의할 수 있습니다.

스킬마다 다른 부분을 커맨드 데이터로 빼서, 새 스킬은 파츠 구성과 커맨드 목록만 정하면 붙습니다. 캐릭터 상태도 스킬 오브젝트를 직접 참조하지 않습니다.

## 2. 문제

> 나선수리검·나선환·화둔·치도리는 모양이 제각각이지만, 흐름은 모두 "나타남 → 발동 → 사라짐"으로 같습니다. 다른 것은 단계마다 어떤 파츠(코어·회전 메시·바람·충돌체)를 켜고, 키우고, 돌릴지뿐입니다. 이 흐름을 스킬마다 파생 클래스에 직접 짜면 같은 전환 코드가 스킬 수만큼 반복됩니다. 게다가 단계가 바뀌는 시점은 캐릭터의 애니메이션 상태가 알고, 실제로 보여 줄 대상은 따로 생성된 스킬 오브젝트라서, 둘을 직접 참조로 묶으면 상태 코드가 스킬 종류를 알아야 했습니다.

## 3. 구조 요약

공통 흐름과 스킬별 차이를 나눴습니다. 단계 전환은 스킬 기반 클래스 하나가 처리하고, 스킬마다 다른 부분은 "어느 단계에 어떤 파츠를 어떻게 움직일지"를 담은 커맨드 목록(프리셋)으로만 정의합니다. 캐릭터 상태와 스킬 오브젝트 사이는 이벤트 버스로만 이어집니다.

이벤트를 태그 타입으로 구분하는 전역 버스입니다. 태그 구조체의 `Signature`가 곧 콜백 형식이고, 태그 타입마다 채널(`m_channels`)을 하나씩 두어 `Add_MemFunc`로 구독하고 `Broadcast`로 호출합니다. 방송 중에 들어온 구독은 방송 깊이(`m_iBroadcastDepth`)를 보고 대기 목록(`m_vecPending`)에 모아 둡니다.

```cpp
class CEventBus_Manager final : public CBase
{
	// ... 코드 중략
public:
	// ... 코드 중략
	template<typename Tag, typename T, typename... Args>
	DelegateHandle Add_MemFunc(T* pObj, void (T::* memFunc)(Args...))
	{
		using Sig = typename Tag::Signature;
		static_assert(std::is_same_v<Sig, void(Args...)>, "signature not match");
		return Subscribe<Tag>([pObj, memFunc](Args... args)
			{
				(pObj->*memFunc)(std::forward<Args>(args)...);
			});
	}
	// ... 코드 중략
	template<typename Tag, typename... Arg>
	void Broadcast(Arg&&... a)
	{
		auto itr = m_channels.find(std::type_index(typeid(Tag)));
		if (itr == m_channels.end()) return;

		auto* pChannel = static_cast<Channel<typename Tag::Signature>*>(itr->second);
		pChannel->multicast.Broadcast(std::forward<Arg>(a)...);
	}
	// ... 코드 중략
private:
	// ... 코드 중략
	template<typename Tag>
	Channel<typename Tag::Signature>* GetOrCreate()
	{
		const std::type_index key{ typeid(Tag) };
		auto itr = m_channels.find(key);
		if (itr != m_channels.end())
			return static_cast<Channel<typename Tag::Signature>*>(itr->second);

		auto* pChannel = new Channel<typename Tag::Signature>();
		m_channels.emplace(key, pChannel);
		return pChannel;
	}
private:
	std::unordered_map<std::type_index, IChannel*> m_channels;
	// ... 코드 중략
};
```

#### B. 방송 중 구독 변경

<Editor file="MulticastDelegate.h" fn="CMulticastDelegate<void(Args...)>">

```cpp
template<class... Args>
class CMulticastDelegate<void(Args...)>
{
	// ... 코드 중략
public:
	// ... 코드 중략
	template<typename... A>
	void Broadcast(A&&... args)
	{
		static_assert(sizeof...(A) == sizeof...(Args), "Broadcast argument count must match the delegate signature");

		m_iBroadcastDepth++;
		for (size_t i = 0; i < m_vecSlots.size(); ++i)
		{
			if (!m_vecSlots[i].bAlive)
				continue;

			m_vecSlots[i].func(std::forward<A>(args)...);
		}
		m_iBroadcastDepth--;

		if (!IsBroadcasting())
			Apply_Pending();
	}
	// ... 코드 중략
};
// ... 코드 중략

template<class ...Args>
inline DelegateHandle CMulticastDelegate<void(Args...)>::Subscribe(std::function<void(Args...)> func) noexcept
{
	Slot slot = {};
	slot.bAlive = true;
	slot.key.iGeneration = 1;
	slot.key.iID = m_iNextID++;
	slot.func = std::move(func);

	if (IsBroadcasting())
		m_vecPending.emplace_back(std::move(slot));
	else
		m_vecSlots.emplace_back(std::move(slot));

	return slot.key;
}
// ... 코드 중략

template<class ...Args>
inline void CMulticastDelegate<void(Args...)>::Apply_Pending()
{
	auto itr = std::remove_if(m_vecSlots.begin(), m_vecSlots.end(),
		[&](const Slot& s)->bool
		{
			return !s.bAlive;
		});

	m_vecSlots.erase(itr, m_vecSlots.end());

	for (auto& slot : m_vecPending)
	{
		if (slot.bAlive)
			m_vecSlots.emplace_back(std::move(slot));
	}
	m_vecPending.clear();
}
```

</Editor>

구독자 콜백 안에서 다시 구독하거나 해제하면 순회 중인 배열이 바뀌어 반복자가 깨집니다. 그래서 방송 중에는 새 구독을 대기 목록에 넣고 해제는 표시만 해 두었다가, 가장 바깥 방송이 끝날 때 한꺼번에 반영합니다. 방송 깊이를 세므로 방송 안에서 다시 방송해도 안전합니다.

```cpp
void CSkillBase::On_SkillEvent(ESkillEventID eID)
{
	auto itr = m_pPreset->umapEventToCommands.find(ENUM_TO_UINT(eID));
	if (itr == m_pPreset->umapEventToCommands.end())
		return;
```

```cpp
void CSkillStateContainer::Update(const _float fTimeDelta)
{
	if (m_iCurrentSkillState < 0 || m_iCurrentSkillState >= m_vecSkillStates.size())
		return;

	if (!m_vecSkillStates[m_iCurrentSkillState])
		return;

	Super::Update(fTimeDelta);

	if (m_vecSkillStates[m_iCurrentSkillState]->Is_FinishedState())
	{
		if(Goto_NextSkillState(nullptr))
			return;
		else
		{
			if (m_iCurrentSkillState + 1 >= m_vecSkillStates.size())
			{
				Request_Change_State(m_iRootState /* 0 = Idle */);
				return;
			}
		}
	}

	m_vecSkillStates[m_iCurrentSkillState]->Update(fTimeDelta);
}
```

## 5. 피드백

**한 캐릭터의 스킬 단계를 전역 방송으로 알렸습니다.** 모든 스킬 컴포넌트가 같은 채널을 구독하고, 각자 "내 캐릭터인가"를 비교해 걸러 냅니다. 받을 쪽이 정해진 호출에 방송을 썼기 때문에 캐릭터가 늘수록 쓸모없는 호출도 함께 늘어납니다. 스킬 컴포넌트를 직접 호출하거나 캐릭터별 채널을 두었다면 걸러 내는 비용과 잘못 받을 가능성이 함께 사라졌을 것입니다.

남은 개선점입니다.

- 치도리 상태들이 `(1, 1)`처럼 슬롯 번호를 직접 적고 있어, 슬롯 배치가 바뀌면 함께 고쳐야 합니다. 컨테이너가 자기 슬롯 번호를 하위 단계에 넘겨 주는 편이 낫습니다.
- `Broadcast`가 같은 인자를 구독자마다 `std::forward`로 넘깁니다. 이동 가능한 값을 넘기면 두 번째 구독자부터 빈 값을 받게 됩니다(지금은 포인터·정수뿐이라 문제 없음).
- 구독 핸들의 세대 값이 항상 1로 고정되어 핸들 재사용을 구분하지 못합니다.
- 소리 재생 커맨드(`PlayOneShot`)는 종류만 있고 처리 코드가 비어 있습니다.
