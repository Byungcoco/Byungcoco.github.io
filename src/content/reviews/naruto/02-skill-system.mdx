## 1. 개요

<Chips items={frontmatter.chips} />

데이터 주도 설계를 쓰면 공통 흐름은 코드 한 곳에 두고, 객체마다 다른 동작은 커맨드 목록 같은 데이터로 정의할 수 있습니다. 캐릭터 상태와 스킬 오브젝트 사이는 이벤트 버스로 이어서, 보내는 쪽과 받는 쪽이 서로를 모른 채 이벤트 종류만으로 연결됩니다.

스킬마다 다른 부분을 커맨드 데이터로 빼서, 새 스킬은 파츠 구성과 커맨드 목록만 정하면 붙습니다. 캐릭터 상태도 스킬 오브젝트를 직접 참조하지 않습니다.

## 2. 문제

> 나선수리검·나선환·화둔·치도리는 모양이 제각각이지만, 흐름은 모두 "나타남 → 발동 → 사라짐"으로 같습니다. 다른 것은 단계마다 어떤 파츠(코어·회전 메시·바람·충돌체)를 켜고, 키우고, 돌릴지뿐입니다. 이 흐름을 스킬마다 파생 클래스에 직접 짜면 같은 전환 코드가 스킬 수만큼 반복됩니다. 게다가 단계가 바뀌는 시점은 캐릭터의 애니메이션 상태가 알고, 실제로 보여 줄 대상은 따로 생성된 스킬 오브젝트라서, 둘을 직접 참조로 묶으면 상태 코드가 스킬 종류를 알아야 했습니다.

## 3. 구조 요약

공통 흐름과 스킬별 차이를 나눴습니다. 단계 전환은 스킬 기반 클래스 하나가 처리하고, 스킬마다 다른 부분은 "어느 단계에 어떤 파츠를 어떻게 움직일지"를 담은 커맨드 목록(프리셋)으로만 정의합니다. 캐릭터 상태와 스킬 오브젝트 사이는 이벤트 버스로만 이어집니다.

| 클래스 | 책임 |

| `CEventBus_Manager` | 상태가 Broadcast한 스킬 단계 이벤트를 Subscribe한 스킬 컴포넌트에 전달 |
| `CSkillComponent` | 슬롯별 쿨타임, 스킬 오브젝트 생성, 단계 이벤트를 해당 스킬에 전달 |

| `CSkillBase` · `SKILL_PRESET` | 단계 전환, 이벤트에 등록된 커맨드를 파츠에 실행 |
| `CSkillMeshPart` | 켜기·회전·크기 변화 같은 커맨드를 받아 스스로 갱신 |

```cpp
_bool CSkillComponent::CanUse(_uint iType, _uint _iIndex)

void CSkillComponent::Use(_uint iType, _uint _iIndex, void* pArg)
{
	_uint iIndex = iType * 3 + _iIndex;
	if (iIndex >= m_vecSkill.size())
		return;

	Spawn_SkillEffect(iIndex, pArg);
	m_vecSkillRemaintimes[iIndex] = m_vecSkillCooltimes[iIndex];

void CSkillComponent::Spawn_SkillEffect(_uint iIndex, void* pArg)
{
	_uint iLevelIndex = m_pGameInstance->Get_CurrentLevelIndex();
	CGameObject* pGo = m_pGameInstance->Add_GameObject(0, m_wstrSkillEffectTag[iIndex], iLevelIndex, g_wszSkillLayer, pArg);
	if (pGo == nullptr)
		return;
	m_vecActiveSkillEffect[iIndex] = static_cast<CSkillBase*>(pGo);
}
```

```cpp
void CSkillBase::On_SkillEvent(ESkillEventID eID)
{
	auto itr = m_pPreset->umapEventToCommands.find(ENUM_TO_UINT(eID));
	if (itr == m_pPreset->umapEventToCommands.end())
		return;

	switch (eID)
	{
	case Client::ESkillEventID::AppearBegin:
	{
		Change_State(CSkillBase::EState::Appear);
		m_pGameInstance->Play_OneShot(L"SkillUse", 0.25f);
	} break;
	case Client::ESkillEventID::ActiveBegin:
		Change_State(CSkillBase::EState::Active);
		break;
	case Client::ESkillEventID::DisappearBegin:
		Change_State(CSkillBase::EState::Disappear);
		break;
	}

	for (auto& cmd : itr->second)
		Execute_Command(cmd);
}
// ... 코드 중략

void CSkillBase::Execute_Command(const SKILL_CMD& cmd)
{
	CSkillPart* pSkillPart = { nullptr };
	if ((pSkillPart = Get_Part<CSkillPart>(cmd.iPartID)) == nullptr)
		return;

	switch (cmd.eType)
	{
	case Client::ESkillCommandType::EnablePart:
		pSkillPart->Set_Enable(cmd.iEnable);
		break;
	case Client::ESkillCommandType::Rotate:
	case Client::ESkillCommandType::PulseScale:
	case Client::ESkillCommandType::TweenScale:
	case Client::ESkillCommandType::PlayOneShot:
		pSkillPart->Execute_Command(cmd);
		break;
	}
}
```

스킬 하나를 이루는 애니메이션 단계들(`m_vecSkillStates`, 예: 시작 → 충전 → 돌진 → 공격)을 묶은 상태입니다. 상태 머신에게는 상태 하나지만, `Update`에서 하위 단계를 순서대로 진행하고 마지막 단계가 끝나면 기본 상태로 돌아갑니다.

#### A. 하위 단계 진행

<Editor file="SkillStateContainer.cpp" fn="CSkillStateContainer::Start(...), CSkillStateContainer::Update(...)">

```cpp
HRESULT CSkillStateContainer::Start(void* pArg, _bool bForce)
{
	if (m_vecSkillStates.size() <= 0)
		return E_FAIL;

	m_iCurrentSkillState = 0;
	m_vecSkillStates[m_iCurrentSkillState]->Start(nullptr);
	Setup_SkillState(m_vecSkillStates[m_iCurrentSkillState]);
	return S_OK;
}

void CSkillStateContainer::Update(const _float fTimeDelta)
{
	if (m_iCurrentSkillState < 0 || m_iCurrentSkillState >= m_vecSkillStates.size())
		return;

	if (!m_vecSkillStates[m_iCurrentSkillState])
		return;

	Super::Update(fTimeDelta);

	if (m_vecSkillStates[m_iCurrentSkillState]->Is_FinishedState())
	{
		if(Goto_NextSkillState(nullptr))
			return;
		else
		{
			if (m_iCurrentSkillState + 1 >= m_vecSkillStates.size())
			{
				Request_Change_State(m_iRootState /* 0 = Idle */);
				return;
			}
		}
	}

	m_vecSkillStates[m_iCurrentSkillState]->Update(fTimeDelta);
}
```

상태 머신은 스킬 슬롯 하나를 상태 하나로만 보고, 스킬 안의 여러 애니메이션 단계는 컨테이너가 진행합니다. 마지막 단계가 끝나면 컨테이너가 기본 상태로 돌려보내므로 스킬마다 복귀 코드를 따로 쓰지 않습니다.

## 5. 피드백

**한 캐릭터의 스킬 단계를 전역 Broadcast로 알렸습니다.** 모든 스킬 컴포넌트가 같은 채널을 Subscribe하고, 각자 "내 캐릭터인가"를 비교해 걸러 냅니다. 받을 쪽이 정해진 호출에 Broadcast를 썼기 때문에 캐릭터가 늘수록 쓸모없는 호출도 함께 늘어납니다. 스킬 컴포넌트를 직접 호출하거나 캐릭터별 채널을 두었다면 걸러 내는 비용과 잘못 받을 가능성이 함께 사라졌을 것입니다.

남은 개선점입니다.

- 치도리 상태들이 `(1, 1)`처럼 슬롯 번호를 직접 적고 있어, 슬롯 배치가 바뀌면 함께 고쳐야 합니다. 컨테이너가 자기 슬롯 번호를 하위 단계에 넘겨 주는 편이 낫습니다.
- 소리 재생 커맨드(`PlayOneShot`)는 종류만 있고 처리 코드가 비어 있습니다.
