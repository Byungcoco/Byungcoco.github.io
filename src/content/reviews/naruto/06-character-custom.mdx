## 1. 개요

<Chips items={frontmatter.chips} />

캐릭터 커스텀은 하나의 뼈대(스켈레톤)에 머리·얼굴·옷 같은 파츠 메시를 바꿔 끼워 외형을 조합하는 기능입니다. 파츠가 모두 같은 뼈대 기준으로 스키닝되어 있으면, 어떤 조합이든 뼈대에 재생한 애니메이션 하나로 함께 움직입니다.

뼈대와 애니메이션은 마스터 하나로 두고 파츠는 메시만 바꾸게 해, 어떤 조합이든 같은 애니메이션으로 움직이고 레벨 사이에는 태그만 넘깁니다. 같은 조립 경로로 적의 외형도 추가 리소스 없이 만들었습니다.

## 2. 문제

> 게임을 시작하기 전에 플레이어가 머리·얼굴·상의·하의(또는 한 벌 옷)를 골라 캐릭터를 꾸미는 화면이 필요했습니다. 파츠는 각각 따로 만든 모델이지만, 조합한 캐릭터는 하나의 몸처럼 같은 애니메이션으로 움직여야 합니다. 파츠마다 뼈대와 애니메이션을 따로 가지면 같은 동작을 파츠 수만큼 계산해야 하고, 파츠끼리 동작이 어긋날 수도 있습니다. 또 커스텀 화면에서 고른 결과는 다음 레벨에서 만들어지는 플레이어에게 전달되어야 하는데, 커스텀 화면의 미리보기 오브젝트는 레벨이 바뀌면 사라지므로 무엇을 넘길지 정해야 했습니다.

## 3. 구조 요약

고르는 일과 만드는 일을 나눴습니다. 커스텀 화면은 미리보기 오브젝트의 파츠만 바꿔 보여 주고, 확정하면 "무엇을 골랐는가"(프로토타입 태그)만 남깁니다. 게임 레벨의 모델은 그 태그를 받아 마스터 뼈대 위에 파츠 메시를 조립해 만듭니다.

```cpp
void CCustomSystem::Set_Event()
{
    m_ChangePartHandle = m_pGameInstance->Subscribe<ChangePart>(this, &CCustomSystem::On_ChangePart);
}

void CCustomSystem::Change_Part(EModelParts ePart, _uint iIndex)
{
    if (ePart >= EModelParts::END || iIndex >= m_Parts[ENUM_TO_UINT(ePart)].size())
    {
        MSG_BOX("CCustomSystem::Change_Part, parameter was overvalue");
        return;
    }

    if (ePart == EModelParts::ONESET)
        m_bSelectedOneset = true;
    else if (ePart == EModelParts::UPPER || ePart == EModelParts::LOWER)
        m_bSelectedOneset = false;

    m_iSelectedIndex[ENUM_TO_UINT(ePart)] = iIndex;
    m_pGameInstance->Broadcast<ChangePart>(ENUM_TO_UINT(ePart), iIndex);
}
// ... 코드 중략

void CCustomSystem::On_ChangePart(_uint iModeType, _uint iIndex)
{
    m_pTarget->Change_Model(static_cast<EModelParts>(iModeType), m_Parts[iModeType][iIndex]);
}
```

</Editor>

버튼은 `Change_Part`만 부르고, 실제 교체는 `ChangePart` 이벤트를 받은 쪽이 합니다. 선택을 기록하는 일과 모델을 바꾸는 일이 이벤트 버스로 나뉘어 있어서, 버튼 코드는 미리보기 오브젝트를 몰라도 됩니다. 한 벌 옷을 고르면 상의·하의 선택이 무효가 되고, 상의나 하의를 고르면 반대로 한 벌 옷이 무효가 됩니다.

```cpp
void CCustomObject::Change_Model(EModelParts ePart, CModel* pModel)
{
    switch (ePart)
    {
    case Client::EModelParts::UPPER:
        m_vecPartObjects[UPPER]->Change_Component(pModel);
        m_eState = state::NOT_ONESET;
        break;
    case Client::EModelParts::LOWER:
        m_vecPartObjects[LOWER]->Change_Component(pModel);
        m_eState = state::NOT_ONESET;
        break;
    case Client::EModelParts::ONESET:
        m_vecPartObjects[ONESET]->Change_Component(pModel);
        m_eState = state::CHOOSE_ONESET;
        break;
    case Client::EModelParts::FACE:
        m_vecPartObjects[FACE]->Change_Component(pModel);
        break;
    case Client::EModelParts::HEAD:
        m_vecPartObjects[HEAD]->Change_Component(pModel);
        break;
    default:
        MSG_BOX("CCustomObject::Change_Model, invalid ModelParts type");
        break;
    }

    Safe_AddRef(pModel);
}
```

```cpp
HRESULT CCustomObject::Render()
{
    if (FAILED(Super::Render()))
        return E_FAIL;

    CShader* pShader = Get_Component<CShader>();
    CModel* pModel = Get_Component<CModel>();

    pModel->Bind_Bones(pShader, 0, 2);
    Get_Component<CTransform>()->Bind_ShaderResource(pShader);
    if (FAILED(m_vecPartObjects[HEAD]->Render()))
        return E_FAIL;
    if (FAILED(m_vecPartObjects[FACE]->Render()))
        return E_FAIL;
    switch (m_eState)
    {
    case Client::CCustomObject::CHOOSE_ONESET:
    {
        if (FAILED(m_vecPartObjects[ONESET]->Render()))
            return E_FAIL;
    } break;
    case Client::CCustomObject::NOT_ONESET:
    {
        if (FAILED(m_vecPartObjects[UPPER]->Render()))
            return E_FAIL;
        if (FAILED(m_vecPartObjects[LOWER]->Render()))
            return E_FAIL;
    } break;
    }

    return S_OK;
}
```

미리보기는 부위마다 파츠 오브젝트를 하나씩 두고, 교체할 때는 그 오브젝트의 모델 컴포넌트만 갈아 끼웁니다. 그릴 때는 마스터 모델이 계산한 본 행렬을 셰이더에 한 번만 넘기고, 각 파츠는 메시만 그립니다. 파츠의 셰이더 컴포넌트가 같은 이펙트를 공유하므로, 한 번 넘긴 본 행렬을 모든 파츠가 함께 씁니다(<FigRef n={3} />). 한 벌 옷 상태면 상의·하의 대신 한 벌 옷만 그립니다.

```cpp
HRESULT CModel::Combine_Model(const MODELPARTS_PROTOTYPETAGS* pPrototypeTags)
{
	m_vecMeshes.reserve(50);
	m_vecMaterials.reserve(50);

	// Master
	{
		CModel* pMaster = { nullptr };
		if (!(pMaster = Get_Clone(L"Prototype_Component_Model_Master")))
			return E_FAIL;
		m_vecBones.resize(pMaster->m_vecBones.size());
		for (size_t i = 0; i < pMaster->m_vecBones.size(); ++i)
		{
			m_vecBones[i] = pMaster->m_vecBones[i]->Clone();
		}
		m_vecAnimations.resize(pMaster->m_vecAnimations.size());
		for (size_t i = 0; i < pMaster->m_vecAnimations.size(); ++i)
		{
			m_vecAnimations[i] = pMaster->m_vecAnimations[i]->Clone();
		}

		m_pMasterMesh = static_cast<CMesh*>(pMaster->m_vecMeshes[0]->Clone(nullptr));
		if (!m_pMasterMesh)
			return E_FAIL;
		Safe_Release(pMaster);
	}


	// Head
	{
		if (FAILED(Add_Parts(pPrototypeTags->wstrHead)))
			return E_FAIL;
	}

	// Face
	{
		if (FAILED(Add_Parts(pPrototypeTags->wstrFace)))
			return E_FAIL;
	}

	// Body
	if (pPrototypeTags->wstrOneset.empty())
	{
		if (FAILED(Add_Parts(pPrototypeTags->wstrUpper)))
			return E_FAIL;
		if (FAILED(Add_Parts(pPrototypeTags->wstrLower)))
			return E_FAIL;
	}
	else
	{
		if (FAILED(Add_Parts(pPrototypeTags->wstrOneset)))
			return E_FAIL;
	}

	return S_OK;
}
```

## 5. 피드백

**파츠 목록이 코드 여러 곳에 흩어져 있었습니다.** 후보 파츠의 태그는 `Ready_Uppper` 같은 부위별 함수에, 버튼에 보이는 이름은 UI 코드에, 프로토타입 등록은 로더에 각각 적혀 있습니다. 파츠 하나를 추가하려면 세 곳을 함께 고쳐야 하고, 시스템과 UI의 순서가 어긋나면 버튼 이름과 실제 모델이 달라집니다. 부위·태그·표시 이름을 데이터 파일 하나에 두고 세 곳이 그 목록을 읽는 구조였어야 합니다.

남은 개선점입니다.

- 미리보기는 파츠 오브젝트를 따로 그리고 게임은 `Combine_Model`로 합치므로 조립 코드가 둘입니다. 미리보기도 교체할 때마다 `Combine_Model`로 다시 조립하는 편이 일관됩니다.
- 한 벌 옷 여부를 시스템(`m_bSelectedOneset`)과 미리보기(`m_eState`)가 따로 기록합니다. 이벤트에 선택 결과를 담아 한쪽만 기준으로 삼는 편이 안전합니다.
- 파츠 메시가 마스터와 같은 본 순서라는 전제를 확인하지 않습니다. 조립할 때 본 이름 목록을 비교하면 잘못 만든 파츠를 로딩 시점에 잡을 수 있습니다.
