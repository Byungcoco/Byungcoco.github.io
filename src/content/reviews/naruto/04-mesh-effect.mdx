## 1. 개요

<Chips items={frontmatter.chips} />

메시 이펙트는 불꽃·리본·구체 같은 모양의 메시에 텍스처를 흘려보내고, 노이즈와 그라데이션으로 가장자리를 깎아 효과를 만듭니다. 입자를 하나씩 움직이는 파티클과 달리, 모양은 메시가 정하고 움직임과 소멸은 픽셀 셰이더가 표현합니다.

표현 방식은 패스로, 재료와 수치는 플래그·상수 버퍼·프리셋으로 나눴습니다. 효과를 조정하면 툴 미리보기에서 바로 확인할 수 있고, 무늬와 색은 아틀라스 안의 위치로 골라 씁니다.

## 2. 문제

> 뮬렛 매드잭 모작의 파티클은 움직임 모드를 하나만 고를 수 있어서, 원하는 모양이 안 나오면 모드를 새로 추가해야 했습니다. CPU에서 입자를 움직이는 방식이라 불꽃·물·번개처럼 면이 흐르다 사라지는 효과도 만들기 어려웠습니다. 이번 스킬들에는 메시 모양 위로 텍스처가 흐르고, 노이즈로 가장자리가 타들어 가고, 높이에 따라 색이 바뀌는 효과가 필요했습니다. 효과마다 셰이더 코드와 수치를 바꿔 가며 빌드하면 조정 한 번에 오랜 시간이 걸리므로, 표현 방식은 셰이더에 두고 수치·텍스처 조합은 툴에서 바로 보며 정할 수 있어야 했습니다.

## 3. 구조 요약

표현 방식과 수치를 나눴습니다. 불꽃·리본·번개처럼 계산 방식이 다른 효과는 셰이더 패스로 만들고, 어떤 텍스처를 쓰고 얼마나 흐르고 어떤 색을 입힐지는 상수 버퍼 하나로 넘깁니다. 이 수치 묶음은 툴에서 프리셋으로 만들어 미리보기로 확인하고, 게임은 프리셋 ID로 같은 값을 읽습니다.

텍스처는 `g_DefaultTextures` 배열의 정해진 칸(패턴·디졸브 노이즈·왜곡 노이즈·그라데이션·램프)에 들어가고, 어느 칸을 쓸지는 `iFlags` 비트로 알려 줍니다. 효과의 모양은 셰이더 패스로 고르고, 패스 안에서 쓸 텍스처는 비트로 켜고 끕니다(<FigRef n={2} />). 효과마다 셰이더를 따로 만들지 않고, 같은 셰이더에서 필요한 단계만 켜는 셈입니다.

#### B. 아틀라스·램프 샘플

<Editor file="Shader_VtxMesh_SkillEffect.hlsl" fn="SamplePattern(...), SampleGradation_Y(...), SampleGradationMap(...)">

```cpp
float4 SamplePattern(float2 vUV)
{
    vUV = vUV * SkillEffect.vPatternScale + SkillEffect.vPatternOffset;
    return g_DefaultTextures[PATTERN].Sample(LinearSampler, vUV);
}
// ... 코드 중략
// 세로 방향만
float SampleGradation_Y(float v01)
{
    return g_DefaultTextures[GRADATION].Sample(LinearClampSampler, float2(0.5f, v01)).r;
}
// ... 코드 중략

float3 SampleGradationMap(float t01)
{
    float fSlice = (1.f / SkillEffect.vGradationMap.y);
    float fY = SkillEffect.vGradationMap.x * fSlice;
    fY += SkillEffect.fGradationHeight * fSlice;
    return g_DefaultTextures[GRADATIONMAP].Sample(LinearClampSampler, float2(t01, fY)).rgb;
}
```

</Editor>

패턴 텍스처는 여러 무늬를 격자로 모은 아틀라스이고, 배율과 오프셋으로 그중 한 칸만 씁니다. 램프 텍스처도 여러 색 띠를 세로로 쌓은 한 장입니다. 행 번호(`vGradationMap.x`)와 행 개수(`.y`)로 한 줄을 고른 뒤, 가로 좌표에 0에서 1 사이 값을 넣어 색을 꺼냅니다. 무늬와 색을 효과마다 다른 텍스처로 두지 않고, 한 장 안의 위치로 고르는 방식입니다.

#### C. 불꽃 — 노이즈 × 그라데이션

<Editor file="Shader_VtxMesh_SkillEffect.hlsl" fn="PS_FIRE(...)">

```cpp
PS_OUT PS_FIRE(PS_IN_MESH input)
{
    PS_OUT output;
    float2 vBaseUV = input.vUV;
    float2 vScrolledUV = frac(input.vUV + float2(SkillEffect.vUVOffset.x, SkillEffect.vUVOffset.y));
    float2 vScrolledUV_Y = float2(vBaseUV.x, vScrolledUV.y);
    float2 vScrolledUV_X = float2(vScrolledUV.x, vBaseUV.y);
    
    float fNoiseR = 1.f;
    if (HasDissolve())
        fNoiseR = SampleDissolveNoise(vScrolledUV);
    
    float fPatternR = SamplePattern(vScrolledUV_X).r;
    fNoiseR *= fPatternR;
    
    float fAlpha = 1.f;
    float fGradationR = 0.f;
    if (HasGradation())
    {
        fGradationR = SampleGradation_Y(vBaseUV.y);
        fAlpha = smoothstep(fGradationR, fGradationR + SkillEffect.fEdgeWidth, fNoiseR);
    }
    
    if (ALPHA_TEST(fAlpha, 0.3f))
        discard;
    
    float4 vBaseColor = MIDesc.vTintColor;
    if (HasGradationMap())
    {
        float3 vRamp = SampleGradationMap(fNoiseR);
        vBaseColor.rgb = vRamp;
    }
    vBaseColor.rgb *= fAlpha;
    output.vColor = vBaseColor;
    return output;
}
```

</Editor>

<Fig n={3} white max={600} src="/img/reviews/naruto/04-mesh-effect/pixel.png" caption="스크롤된 UV로 노이즈·패턴 샘플 → 세로 그라데이션과 smoothstep으로 알파 → 램프 텍스처로 색" />

불꽃 패스의 계산 순서입니다(<FigRef n={3} />). UV에 스크롤 오프셋을 더해 노이즈와 패턴을 샘플하고 둘을 곱합니다. 세로 그라데이션 값을 기준선으로 `smoothstep`을 걸면 아래쪽은 남고, 위로 갈수록 노이즈 모양대로 끊기며 사라집니다. 기준선과의 차이가 `fEdgeWidth`보다 작은 곳은 부드럽게 흐려지고, 알파가 낮은 픽셀은 버립니다. 색은 같은 노이즈 값으로 램프에서 고르므로 진한 곳과 옅은 곳의 색이 달라집니다.

void CSkillMeshPart::Setup_RuntimeFlags()
{
	CTexture* pTexture = Get_Component<CTexture>();
	m_iRuntimeFlags = m_iBaseFlags;

	if ((m_iRuntimeFlags & Flags::Dissolve) && (pTexture->Is_Valid(ENUM_TO_UINT(ETextureType::DissolveNoise)) == false))
		m_iRuntimeFlags &= ~Flags::Dissolve;

	if ((m_iRuntimeFlags & Flags::Distortion) && (pTexture->Is_Valid(ENUM_TO_UINT(ETextureType::DistortionNoise)) == false))
		m_iRuntimeFlags &= ~Flags::Distortion;

	if ((m_iRuntimeFlags & Flags::Gradation) && (pTexture->Is_Valid(ENUM_TO_UINT(ETextureType::Gradation)) == false))
		m_iRuntimeFlags &= ~Flags::Gradation;

	if ((m_iRuntimeFlags & Flags::GradationMap) && (pTexture->Is_Valid(ENUM_TO_UINT(ETextureType::GradationMap)) == false))
		m_iRuntimeFlags &= ~Flags::GradationMap;

	m_skillEffectDesc.iFlags = m_iRuntimeFlags;
}

void CSkillMeshPart::Setup_PatternUV(const EFFECT_PRESET_SNAPSHOT& snapShot)
{
	_int iTotalCount = snapShot.iPatternCols * snapShot.iPatternRows;

	_int iPatternIndex = 0;
	if (iTotalCount > 1)
		iPatternIndex = m_pGameInstance->Rand_Int(0, iTotalCount - 1);
	else
		iPatternIndex = 0;

	_float2 vFrame = { (_float)(iPatternIndex % snapShot.iPatternCols), (_float)(iPatternIndex / snapShot.iPatternCols) };

	m_skillEffectDesc.vPatternScale.x = 1.f / snapShot.iPatternCols;
	m_skillEffectDesc.vPatternScale.y = 1.f / snapShot.iPatternRows;
	m_skillEffectDesc.vPatternOffset.x = vFrame.x * m_skillEffectDesc.vPatternScale.x;
	m_skillEffectDesc.vPatternOffset.y = vFrame.y * m_skillEffectDesc.vPatternScale.y;

	m_materialInstanceDesc.vTintColor = snapShot.vTintColor;
	m_materialInstanceDesc.fEmissivePower = snapShot.fEmissivePower;
}

void CLevel_Effect::On_PresetApplyRequested(CGameObject* pTarget, _uint iPresetID, EFFECT_PRESET_SNAPSHOT snapShot)
{
	if (EFFECT_PRESET* pPreset = Get_Preset(iPresetID))

	if (pTarget)
	{
		if (CSkillPreviewMesh* pPreview = dynamic_cast<CSkillPreviewMesh*>(pTarget))
		{
			if (pPreview->Get_PresetID() != iPresetID)
				pPreview->Set_PresetID(iPresetID);
		}
	}

	for (auto& pPreview : m_vecPreviewMeshes)
	{
		if (pPreview == nullptr)
			continue;

		if (static_cast<CSkillPreviewMesh*>(pPreview)->Get_PresetID() == iPresetID)
		{
			if (CMonoBehaviour* pOtherRetunred = pPreview->Get_Script_Component(L"PresetReceiver"))
			{
				static_cast<CPresetReceiver*>(pOtherRetunred)->Queue(snapShot);
			}
		}
	}

	m_bFileDirty = true;
}

## 5. 피드백

**셰이더 패스마다 같은 계산이 복사되어 있었습니다.** `PS_FIRE`와 `PS_WINDRING`은 램프 색을 대입하느냐 곱하느냐만 다르고, UV 스크롤·노이즈·그라데이션 계산은 기본 패스를 뺀 대부분의 패스가 똑같이 반복합니다. 공통 단계를 함수 하나로 모으고 패스에는 차이 나는 부분만 적었어야, 계산 하나를 고칠 때 패스 수만큼 고치지 않아도 됩니다.

남은 개선점입니다.

- 툴의 `CommitPreset`과 게임의 `Ready_ResourcesInfo`가 프리셋을 각자 상수 버퍼로 옮기다 보니, 디졸브 기준값(`fThreshold`) 처리가 이미 엇갈려 있습니다. 변환을 엔진 쪽 함수 하나로 모아야 합니다(지금은 셰이더가 그 값을 쓰지 않아 드러나지 않음).
- 왜곡(`Distortion`) 플래그와 노이즈 슬롯은 있지만 쓰는 패스가 없습니다. 툴에서 숨기거나 패스에 넣어야 합니다.
- `UVScrolling` 안에 키 입력으로 디졸브 기준값·밝기·가장자리 폭을 바꾸는 조정용 코드가 남아 있어, 게임 중 해당 키를 누르면 값이 함께 바뀝니다.
