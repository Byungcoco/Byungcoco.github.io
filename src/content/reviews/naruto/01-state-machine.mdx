## 1. 개요

<Chips items={frontmatter.chips} />

상태 패턴은 객체의 행동을 상태 객체로 나눠, 상태가 바뀌면 행동도 함께 바뀌게 합니다. 여기에 입력을 인터페이스로 추상화하면 사람이 조작하는 캐릭터와 AI가 조작하는 캐릭터가 같은 상태 코드를 공유할 수 있습니다.

입력과 행동을 나눈 덕분에 플레이어와 적이 같은 상태 클래스를 그대로 쓰고, 적은 입력 컴포넌트만 바꿔 붙여 움직입니다.

## 2. 문제

> 플레이어와 적 캐릭터는 이동·대시·점프·콤보·스킬을 같은 애니메이션 규칙으로 해야 했습니다. 이전 프로젝트처럼 캐릭터마다 상태 클래스를 따로 만들면 거의 같은 로직의 클래스가 캐릭터 수만큼 늘어납니다. 그렇다고 같은 상태 코드를 쓰면 상태 안에 "플레이어면 키 입력, 적이면 AI 판단" 같은 분기가 들어가, 뮬렛 매드잭 모작의 보스 AI에서 겪었던 것처럼 판단 로직이 상태 안에 섞입니다.

## 3. 구조 요약

입력의 출처와 행동을 나눴습니다. 상태는 입력 인터페이스에 의도만 묻고, 그 인터페이스를 플레이어는 키보드로, 적은 AI 판단으로 구현합니다. 그래서 플레이어와 적이 같은 상태 클래스를 그대로 공유합니다.

#### A. End → Start 전환

<Editor file="ActionState.cpp" fn="CActionState::Change_State(...)">

```cpp
HRESULT CActionState::Change_State(_uint iIndex, _bool bForce, void* pArg)
{
	if (iIndex >= m_vecStates.size() || m_vecStates[iIndex] == nullptr)
		return E_FAIL;

	if (m_iCurrentState == iIndex && bForce == false)
		return S_OK;

	if (m_iCurrentState >= 0 && m_iCurrentState < m_vecStates.size())
	{
		if (CStateBase* pPrevState = m_vecStates[m_iCurrentState])
		{
			if (FAILED(pPrevState->End()))
				return E_FAIL;
		}
	}

	if (FAILED(m_vecStates[iIndex]->Start(pArg, bForce)))
		return E_FAIL;
	m_iPrevState = m_iCurrentState;
	m_iCurrentState = iIndex;
	return S_OK;
}
```

적의 입력 인터페이스 구현입니다. 판단 주기(`m_fThinkDuration`)마다 `Reset_Decision()`이 거리와 공격 성향(`m_fAggressive`)으로 행동을 정하면, `Update_Attack` 등이 그 행동에 맞는 의도 플래그를 채웁니다. 플래그는 `Reset_Flag()`로 매 프레임 지워지므로 한 프레임짜리 입력처럼 동작합니다.

#### A. 주기적 판단

<Editor file="EnemyControlContext.cpp" fn="CEnemyControlContext::Update(...), CEnemyControlContext::Reset_Decision()">

```cpp
void CEnemyControlContext::Update(const _float fTimeDelta)
{
	if (!m_pTarget)
		return;

	CGameObject* pOwner = Get_Owner();
	CActionState* pOwnerActionState = pOwner->Get_Component<CActionState>();
	CActionState* pTargetActionState = m_pTarget->Get_Component<CActionState>();
	if (!pTargetActionState || !pOwnerActionState)
		return;

	Reset_Flag();

	m_fThinkElapsed += fTimeDelta;
	if (m_fThinkElapsed >= m_fThinkDuration || m_bForceRethink == true)
	{
		m_fThinkElapsed = 0.f;
		m_bForceRethink = false;
		Reset_Decision();
	}

	Update_AiState(fTimeDelta);
}
// ... 코드 중략

void CEnemyControlContext::Reset_Decision()
{
	// ... 코드 중략
	_vector vToTarget = vTargetPosition - vOwnerPosition;
	_float fDistance = ::XMVectorGetX(::XMVector3Length(vToTarget));
	_float fAttackChance = m_pGameInstance->Rand_Float(0.0f, 1.0f);
	
	AIState eTargetState = { AIState::IDLE };
	// 공격 가능할 때
	if (fDistance <= m_fAttackRange)
	{
		// 공격
		if (fAttackChance < m_fAggressive)
		{
			eTargetState = AIState::ATTACK;
		}
		else
		{
			eTargetState = AIState::BACKDASH;
		}
	}
	// 스킬 쓸수 있을 때
	else if (fDistance <= m_fSkillRange)
	{
		// 스킬 사용
		if (fAttackChance < m_fAggressive)
		{
			eTargetState = AIState::SKILL;
		}
		else if(fAttackChance < m_fAggressive * 1.5f)
		{
			eTargetState = AIState::CHASE;
		}
		else
		{
			eTargetState = AIState::IDLE;
		}
	}
	// 그 외의 거리
	else
	{
		if (fAttackChance < m_fAggressive)
		{
			eTargetState = AIState::CHASE;
		}
		else
		{
			eTargetState = AIState::IDLE;
		}
	}

	Change_AiState(eTargetState);
}
```


AI는 현재 상태의 행동 가능 플래그부터 확인해, 공격할 수 없는 상태(예: 피격 중)라면 다시 판단하도록 표시합니다. 공격할 수 있으면 "공격 버튼을 눌렀다"는 플래그만 세우고, 실제로 공격 상태로 넘어가는 일은 플레이어와 같은 상태 코드가 맡습니다.

## 5. 피드백

**전환 우선순위가 상태마다 따로 적혀 있었습니다.** 대기·달리기·착지 같은 상태마다 `Align_*` 호출 순서를 직접 적었기 때문에, "대시가 점프보다 먼저" 같은 규칙 하나를 바꾸려 해도 여러 상태를 함께 고쳐야 합니다. 공통 전환 규칙은 표나 우선순위 목록으로 빼고 상태에는 예외만 적게 했다면 규칙이 한곳에 모였을 것입니다.

남은 개선점입니다.

- 플레이어의 스킬 입력 함수가 쿨타임(`CanUseSkill`)까지 확인해, "눌렀는가"와 "쓸 수 있는가"가 한 함수에 섞여 있습니다.
- 적 AI의 상태별 갱신 함수가 매번 자신과 대상의 행동 플래그를 다시 가져옵니다. 판단을 시작할 때 한 번 구해 넘기면 반복이 줄어듭니다.
- 적 입력 구현은 점프·회피·두 번째 이후 스킬에 항상 `false`를 돌려줍니다. 행동을 늘리려면 AI와 입력 구현을 함께 고쳐야 합니다.
