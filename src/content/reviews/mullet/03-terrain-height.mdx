## 1. 개요

<Chips items={frontmatter.chips} />

3D 지형 위에 캐릭터를 세우려면 발밑의 높이를 알아야 합니다. 높이맵 지형은 격자 칸의 삼각형을 보간해 높이를 구하고, 여러 장의 평면으로 이뤄진 지형은 각 평면의 방정식으로 구합니다. 대상 평면을 빨리 찾으려고 직전에 밟은 면부터 확인하는 공간 연속성을 흔히 이용합니다.

무거운 계산을 로드 시점으로 옮기고 직전 패널 근처만 확인하게 하면서, 레이 교차 없이 바닥과 경사를 처리했고 모든 패널을 검사하던 때의 성능 문제도 없앴습니다.

## 2. 문제

> 스테이지 바닥은 높이맵 지형이 아니라 툴로 깐 여러 장의 바닥·경사 패널입니다. 캐릭터가 그 위에 서고 경사를 오르내려야 했습니다. 레이와 메시의 교차를 직접 구현해 매 프레임 검사하기에는 비용이 크다고 판단했습니다. 처음에는 모든 패널을 검사했는데, 패널 수가 늘자 실제로 성능 문제가 생겼습니다.

## 3. 구조 요약

무거운 계산은 로드 시점으로 옮겼습니다. 패널은 움직이지 않으므로 범위·평면·역행렬을 한 번만 구해 Z 순으로 정렬해 두고, 매 프레임에는 캐릭터마다 직전 패널 근처만 확인해 높이를 구합니다.

			D3DXVec3TransformCoord(&w, &l, &tEntry.matWorld);
			return w;
			};
		_vec3 w00 = Wof(0.f, 0.f);
		_vec3 w10 = Wof(fLenghtX, 0.f);
		_vec3 w01 = Wof(0.f, fLenghtZ);

		// 평면 저장(패널은 한 평면이라 가정)
		D3DXPlaneFromPoints(&tEntry.planeWorld, &w00, &w10, &w01);

		::D3DXMatrixInverse(&tEntry.matWorldInv, nullptr, pTransform->Get_World());

		m_vecSortedFloorEntries.push_back(tEntry);
	}

	Sort_List_ByZValue(m_vecSortedFloorEntries);

#### B. Z 기준 정렬

<Editor file="CGameDataManager.cpp" fn="CGameDataManager::Sort_List_ByZValue(...)">

```cpp
void CGameDataManager::Sort_List_ByZValue(vector<PANELENTRY> &_veclist)
{
	if (_veclist.size() <= 1)
		return;

	std::sort(_veclist.begin(), _veclist.end(),
		[](const PANELENTRY &a, const PANELENTRY &b)->bool
		{
			if (a.fMin_Z != b.fMin_Z)
				return a.fMin_Z < b.fMin_Z;

			// Z값이 동일할 경우를 대비
			return a.fMin_X < b.fMin_X;
		});
}
```

</Editor>

레벨을 Z 방향으로 길게 이어지도록 설계했기 때문에, Z로 정렬한 목록에서 번호가 이웃한 패널은 실제로도 이웃해 있습니다. 이 정렬 덕분에 캐릭터는 현재 패널의 앞뒤만 보면 됩니다(<FigRef n={2} />).

캐릭터마다 하나씩 붙는 컴포넌트입니다. 공유 패널 목록은 읽기만 하고, 직전에 밟은 패널 번호 `m_iCurrentIndex`만 기억합니다. `GetHeight`가 그 근처에서 패널을 찾고(바닥은 `IsInside`, 경사는 `IsInside_Slope`), 경사 높이는 `Y_OnPanelPlane`과 `Compute_Height`로 구합니다.

## 5. 피드백

**패널 탐색이 "정렬 순서상 이웃 = 공간상 이웃"이라는 가정 위에 서 있습니다.** 레벨이 Z 방향으로 길지 않거나, 캐릭터가 정렬 번호로 3칸 이상 떨어진 패널로 한 번에 이동하면 현재 패널을 놓칩니다. 계산을 가볍게 만든 대가로 맵 모양에 대한 가정이 생긴 셈입니다.

남은 개선점입니다.

- 같은 XZ 위치에 높이가 다른 패널이 겹치면(다리 아래 통로, 2층 구조) Z 정렬 순서만으로는 어느 패널인지 가릴 수 없습니다.
- 바닥 판정은 시작 위치에 (격자 수 − 1) × 간격을 더한 XZ 범위라 회전된 바닥 패널을 다루지 못합니다. 경사처럼 역행렬로 로컬 좌표에서 검사하면 같은 코드로 처리할 수 있습니다.
- `Bind_FloorList`와 `Bind_SideWallList`가 패널 정보 계산 코드를 반복합니다. 패널 하나를 `PANELENTRY`로 만드는 함수로 묶어야 합니다.
- `PANELENTRY`의 `fHalfX` / `fHalfZ` / `fLocalCenter`는 계산만 하고 쓰지 않습니다.
