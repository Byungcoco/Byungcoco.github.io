그렇다면 이부분에서 Entry.LayoutClass.Get()을 통해 가져오는게 진행이 안되고 있다는것이다.

일전에 강조했듯이 TSoftClassPtr은 경로만 가르키고있다. Get을 진행하기전에 Load를해서 메모리에 할당되어야 해당 CDO를 반환이 이루어지는것인데, 안된다는것은 Load가 이루어지지 않아 메모리에도 없다는것이다.

이와 비슷한 경우가 InputConfig 구현할 때 있었는데

<Fig n={8} src="/img/notes/lyra/asset-bundle/08.png" caption="" />

GameFeatureAction_InputConfig에서 해당 TSoftObjectPtr을 로드해서 넣어줬다. 그렇다면? Load를 저기서 진행해줘서 직접 넣어줘야하는것인가? 해당 방법을 쓰면 간편하겠지만 Lyra에서는 그렇게 하지않았다.

Lyra는 멀티플레이 환경이고, GameFeatureAction의 경우 서버든 클라이언트든 똑같이 발동이된다. 그러면 서버가 UI에 대한것을 로드해서 메모리에 올릴필요가 있을까?를 고민해야한다. 왜? 멀티플레이 환경개발이니까!

그래서 Lyra는 효율적으로 사용하기위해 Client들만 해당 Asset들을 로드해서 관리한다. 그렇다는것은 해당 함수 AddWidget이 들어오기전에 클라이언트만 로드가 완료 되어있어야 된다.

그럼 어떻게 Client들만 로드하게 가능할까? 라고 생각하면 예전에 Experience했을때 AssetBundle에 Server, Client에따라 불러올 Bundle에 해당 키워드를 업데이트 해줬던 적이있었다.

<Fig n={9} src="/img/notes/lyra/asset-bundle/09.png" caption="" />

ExperienceManagerComponent에서 다음과 같은 로직이 있었다. BundlesToLoad에 해당 FName 키워드를 추가하고, 맨아래 ChangeBundleStateForPrimaryAssets로 진행했었다. BundleAssetList는 UserExperienceDefinition이었고 해당 프로퍼티에서 Clinet, Server키워드가 있는 것들을 같이 로드한다는것이었다. 근데 왜 UserExperienceDefinition에는 해당 키워드가 추가되어있지않을까??

<Fig n={10} src="/img/notes/lyra/asset-bundle/10.png" caption="" />

생각해보면 따로 키워드를 정하지 않아도 로드 되었었다. 왜냐하면 TObjectPtr은 UObject기반 객체로 메모리에 이미 로드되어있어 강하게 참조를 하기때문이다. 생각해보면 별도의 로드 과정없이 NewObject를 통해 객체를 즉시 생성해서 메모리에 할당 가능하다. 즉, ExperienceDefinition의 Property들을 보면 서버와 클라이언트에 둘다 필요한 필수 데이터들이다.

하지만 Widget의 경우 서버에서 필요없는 정보이므로 선택적 로드를 위해 TSoftClassPtr로 지정해놓은것이다. 해당 키워드에 따라 로드하는 함수 ChangeBundleStateForPrimaryAssets를 내부적으로 디버그해보며 살펴보자.

<Fig n={11} src="/img/notes/lyra/asset-bundle/11.png" caption="" />
