## 1. 히프

히프 트리 구조에서는 루트 노드가 항상 최댓값 혹은 최솟값을 가진다. 이를 각각 <strong>최대 히프</strong>, <strong>최소 히프</strong>라 부른다.

- 최대 트리: 부모 노드가 항상 자식 노드들보다 크다. 최대 히프는 최대 트리의 속성을 가진다.
- 최소 트리: 부모 노드가 항상 자식 노드들보다 작다. 최소 히프는 최소 트리의 속성을 가진다.

그렇다면 이진 최대 트리나 이진 최소 트리이기만 하면 최대 히프, 최소 히프라 부를 수 있을까? 아니다. 히프는 이 속성에 더해 <strong>완전 이진 트리</strong>여야 한다.

- 포화 이진 트리: 모든 레벨에 노드를 꽉 채운 이진 트리
- 완전 이진 트리: 레벨 1~h-1까지는 꽉 채우고, 마지막 레벨에서는 왼쪽부터 채워진 이진 트리

포화 이진 트리도 완전 이진 트리이므로 히프가 될 수 있다. 최소한의 조건이 완전 이진 트리라는 것, 즉 <strong>중간에 빈 노드가 없어야 한다</strong>는 것이 중요한 포인트이다. 마지막 레벨에서 왼쪽부터 채워지는 구간 중간에 노드 하나가 빠져 빈 공간이 생기면 완전 이진 트리라 할 수 없고, 따라서 히프가 될 수 없다.

다시 말해 히프는 <strong>완전 이진 트리의 속성을 가지면서 최대 트리 혹은 최소 트리</strong>여야 한다.

<div class="tbl">

| 구분 | 조건 | 루트 노드의 키 값 |
|---|---|---|
| 최대 히프 | 부모 노드의 키 ≥ 자식 노드의 키 | 트리 전체 중 최댓값 |
| 최소 히프 | 부모 노드의 키 ≤ 자식 노드의 키 | 트리 전체 중 최솟값 |

</div>

여기서 초과/미만이 아니라 이상/이하이므로, 부모 노드와 키 값이 같아도 조건을 충족한다는 점을 눈여겨봐야 한다.

<Fig n={1} src="/img/notes/ds/tree-3/heaps.png" caption="최대 히프와 최소 히프의 예" max={740} />

<FigRef n={1} />의 최소 히프에서 루트 2는 레벨 2, 레벨 3의 모든 원소보다 작다. 하지만 루트 이외의 노드들에는 <strong>느슨한 정렬</strong> 기준만 주어진다. 예를 들어 레벨 2의 9는 자식들(9, 12)보다 작거나 같지만, 다른 쪽 레벨 2 노드 6의 자식인 8보다는 크다. 부모-자식 사이의 "크거나 같다" 혹은 "작거나 같다" 속성만 지켜지면 된다.

이 트리는 포화 이진 트리이므로, 노드가 추가된다면 다음 레벨의 가장 왼쪽에 추가해야 한다. 완전 이진 트리의 구조를 유지해야 하기 때문이다.

## 2. 히프의 추가 연산

먼저 <strong>완전 이진 트리 구조를 유지하는 자리</strong>(마지막 자리)에 노드를 추가한다. 그다음 부모 노드와 크기를 비교하며 타고 올라가고, 필요하면 루트 노드까지 교환한다(<FigRef n={2} />).

부모 노드는 이미 자식 노드보다 큰 값을 유지하고 있으므로, 새 노드가 부모보다 작거나 같아지는 순간 최대 트리 조건을 만족한다. 그래서 그 자리에서 멈추면 되고 많은 비교가 필요 없다.

## 3. 히프의 삭제 연산

히프의 삭제는 루트 노드에서 진행된다. 최댓값(루트)을 추출한 뒤 자식 중 큰 노드를 루트로 승격시키는 순서이다.

여기서 주의할 점은 <strong>완전 이진 트리 구조를 유지</strong>해야 하므로, 마지막 레벨의 가장 오른쪽에 있는 노드를 임시로 루트로 옮긴다는 것이다. 그다음 두 자식 중 더 큰 노드를 승격시킨다(<FigRef n={3} />). 이렇게 하면 완전 이진 트리 구조와 최대 트리 속성을 모두 유지하므로 최대 히프라 할 수 있다. 물론 한 번의 교환으로 정리되지 않을 수 있으므로, 자리를 찾을 때까지 같은 규칙으로 반복한다.

<Fig n={3} src="/img/notes/ds/tree-3/delete.png" caption="최대 히프에서 루트 삭제" max={740} />

자료의 개수를 n개라 할 때 추가 연산의 시간 복잡도는 `O(log₂n)`이다. 완전 이진 트리 구조를 유지하므로 트리의 높이가 약 `log₂n`이기 때문이다. 삭제 역시 `O(log₂n)`이다.

## 4. 배열로 구현한 최대 히프

배열로 최대 히프를 구현할 때 핵심은 트리 인덱스 공식이다. 특정 노드의 부모는 `index / 2`, 왼쪽 자식은 `index * 2`, 오른쪽 자식은 `index * 2 + 1`로 구한다. 이 연산을 유지하기 위해 <strong>배열의 0번 인덱스는 사용하지 않고 1번부터</strong> 채워 넣는다.

배열로 보면 완전 이진 트리 구조를 왜 유지해야 하는지 명확해진다. 중간에 빈 노드가 없어야 인덱스 1부터 n까지가 빈틈없이 채워지고, 새 노드는 항상 `n + 1`번에 들어간다.

추가와 삭제는 매번 교환(swap)하는 대신 <strong>삽입 정렬 방식</strong>으로 구현했다. 버블 방식이 편하긴 하지만 성능을 더 챙기기 위해서이다. 옮길 노드를 KeyNode로 따로 저장해 두고, 비교하면서 부모(또는 자식) 노드를 복사해 한 칸씩 옮긴다. KeyNode가 들어갈 자리를 찾으면 break하고 그 자리에 KeyNode를 넣는다.

```cpp
void CArrayHeap::InsertNodeToMaxArrayHeap(const HeapNode &tHeapNode_in)
{
	if (!m_pHeapArray)
		return;

	if (m_iCurrentElementCount == m_iMaxElementCount)
	{
		MoveArray();
	}

	++m_iCurrentElementCount;
	HeapNode KeyNode = tHeapNode_in;
	int iIndex = m_iCurrentElementCount;
	for (; iIndex != 1; iIndex /= 2)
	{
		if (KeyNode >= m_pHeapArray[iIndex / 2])
		{
			m_pHeapArray[iIndex] = m_pHeapArray[iIndex / 2];
		}
		else
			break;
	}
	
	m_pHeapArray[iIndex] = KeyNode;
}
```

```cpp
HeapNode *CArrayHeap::DeleteNodeInMaxArrayHeap()
{
	if (!m_pHeapArray || m_iCurrentElementCount <= 0)
	{
		std::cout << "힙배열이 존재하지않습니다.\n";
		return nullptr;
	}

	HeapNode *pReturnNode = new HeapNode;
	HeapNode KeyNode = m_pHeapArray[m_iCurrentElementCount];
	*pReturnNode = m_pHeapArray[1];

	int iParent(1);
	int iChild(2);
	while (iChild <= m_iCurrentElementCount)
	{
		if (m_pHeapArray[iChild] < m_pHeapArray[iChild + 1])
		{
			++iChild;
		}

		if (KeyNode >= m_pHeapArray[iChild])
			break;
		
		m_pHeapArray[iParent] = m_pHeapArray[iChild];
		iParent = iChild;
		iChild *= 2;
	}

	m_pHeapArray[iParent] = KeyNode;
	m_pHeapArray[m_iCurrentElementCount] = HeapNode();
	--m_iCurrentElementCount;
	return pReturnNode;
}
```

</Editor>

최소 히프는 비교 방향만 반대로 바꾸면 같은 구조로 구현된다. 추가할 때는 KeyNode가 부모보다 작거나 같으면 부모를 아래로 내리고, 삭제할 때는 두 자식 중 더 작은 쪽을 따라 내려간다.
