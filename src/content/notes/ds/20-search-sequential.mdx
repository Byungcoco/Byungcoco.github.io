## 1. 검색이란

검색이란? 정보 검색의 가장 기본이 되는 분야로, 기존 자료 중 원하는 자료를 찾는 것을 말한다. 이때 찾고자 하는 자료를 같이 저장된 다른 자료들과 구별시켜 주는 것을 <strong>검색 키(Search Key)</strong>라 칭한다.

보통 검색 엔진들은 <strong>랭킹 알고리즘</strong>을 이용하여, 검색된 자료를 필요에 부합하는 순서로 정렬하는 연산을 추가로 수행하기도 한다.

검색은 정렬과 마찬가지로 내부 검색과 외부 검색으로 나누어진다.

- 내부 검색: 검색 연산이 모두 메모리 내에서 수행되는 것
- 외부 검색: 디스크 등 보조 기억 장치를 이용하여 검색을 수행하는 것

또한 검색 위치뿐만 아니라 방법에 따라 나뉘기도 한다.

- 비교 검색: 검색 키를 비교하여 검색
- 계산 검색: 검색 키를 계산하여 검색

여기서 계산 검색은 키 값을 산술적으로 계산하여 검색하는 방법으로, <strong>해싱(Hashing)</strong>이 가장 대표적인 방법이다.

## 2. 순차 검색 (Sequential Search)

순차 검색은 일렬로 되어 있는 자료들의 검색 키 값을 차례대로 비교하는 검색 방법으로, 선형 검색이라고도 한다.

가장 단순하고 직관적인 검색 방법이지만, 자료의 양이 증가하면 효율성이 상당히 감소하기 때문에 자료가 적은 경우에만 사용할 수 있다는 단점이 있다. 접근은 쉽지만 자료의 양이 늘어나면 효율이 떨어진다.

이러한 순차 검색은 자료들이 미리 정렬되어 있다면 효율을 높일 수 있다.

<Fig n={1} src="/img/notes/ds/search-sequential/sequential.png" caption="정렬되지 않은 자료는 끝까지 비교해야 실패를 알고, 정렬된 자료는 중간에 실패를 판정할 수 있다" max={640} />

#### 자료가 미리 정렬되지 않은 경우

말 그대로 처음 원소부터 마지막 원소까지 Key 값이 일치하는 자료를 검색하는 것이다. 마지막까지 검색 키를 가지는 자료를 찾지 못하면 실패! 그래서 검색 실패 여부는 마지막 자료까지 비교가 이루어져야만 알 수 있다.

검색 키가 i번째에 있을 확률이 모두 같다면 평균 비교 횟수는 (1 + 2 + … + n) / n = (n+1)/2, 즉 평균 O(n)의 시간 복잡도를 가진다.

#### 자료가 미리 정렬된 경우

위 순차 검색과 마찬가지로 처음부터 차례대로 비교 연산을 해야 결과를 알 수 있지만, 실패 여부는 마지막 원소까지 찾지 않아도 알 수 있다는 점이 다르다.

당연하게도 오름차순(또는 내림차순)으로 정렬된 Key 값이라면, 검색 도중 검색 키보다 큰(내림차순이면 작은) 값을 만나는 순간 그 이후의 자료에는 일치하는 Key 값이 없기 때문이다.

성공 여부를 판단하려면 해당 자료까지 순차적으로 비교해야 하지만, 실패 여부는 조건에 따라 중간에 결과를 낼 수 있기 때문에 이런 부분이 개선된다고 보면 된다.

## 3. 색인 순차 검색 (Index Sequential Search)

미리 정렬된 자료에 대해 인덱스 테이블을 이용하여 검색의 효율을 높이는 검색 방법이다.

인덱스 테이블은 주먹구구식으로 저장하는 게 아니라 <strong>일정 간격</strong>으로 자료의 키와 위치를 저장하기 때문에, <strong>실제로 비교해야 하는 전체 자료의 개수를 줄이는 역할</strong>을 한다.

즉, 순차 검색처럼 모든 자료와 비교 연산을 진행하는 것이 아니라, 일정 간격의 자료들을 저장한 인덱스 테이블과 먼저 비교하여 연산 횟수를 줄이는 것이다.

<Fig n={2} src="/img/notes/ds/search-sequential/index-seq.png" caption="인덱스 테이블에서 50 ≤ 60 < 70 구간을 찾고, 그 범위만 순차 검색한다" max={640} />

모든 배열 원소와 비교하는 것과 달리, 일정 간격으로 나열된 인덱스 테이블의 요소들과 비교하며 50 &lt; 60 &lt; 70 이라는 검색 범위를 만들어 낸다. 이어서 50과 70 사이의 자료만 검색하면 되겠구나! 가 되는 것이다.

정리하면, Key 값이 인덱스 테이블의 두 항목 사이에 들어간다면 위치 또한 해당 인덱스 테이블 범위 내에 존재한다.

> IndexTable[i-1].key ≤ key &lt; IndexTable[i].key<br />
> ⇒ IndexTable[i-1].position ≤ 검색 범위 &lt; IndexTable[i].position

색인 순차 검색은 <strong>정렬된 자료</strong>를 기준으로 검색하는 것이며, 정렬된 자료의 순차 검색과 달리 인덱스 테이블을 통해 비교 연산 횟수를 줄이고 구간을 만들어, 검출된 구간에서 빠르게 찾아낼 수 있도록 한다.

```cpp
int CArrayForSearch::IndexSequentialSearch(const int &iKeyValue_in)
{
	int iReturnIndex(FAIL_NUM);

	if (!m_pArray)
		return iReturnIndex;

	if (iKeyValue_in < m_pArray[0] || iKeyValue_in > m_pArray[m_iSize - 1])
		return iReturnIndex;

	int iIndexTableSize = m_iSize / 2;
	IndexTable *pIndexTable = new IndexTable[iIndexTableSize];

	for (int i = 0; i < iIndexTableSize; ++i)
	{
		pIndexTable[i] = { i * 2, m_pArray[i * 2] };
	}

	int iStart(0);
	int iEnd(0);
	int iSearchIndex(0);

	for (iSearchIndex = 0; iSearchIndex < iIndexTableSize; ++iSearchIndex)
	{
		std::cout << "Search!\n";
		if (iKeyValue_in < pIndexTable[iSearchIndex].m_iKey)
			break;

		if (iKeyValue_in == pIndexTable[iSearchIndex].m_iKey)
		{
			return pIndexTable[iSearchIndex].m_iPosition;
		}
	}

	if (iSearchIndex >= (iIndexTableSize - 1))
	{
		iStart = pIndexTable[iSearchIndex - 1].m_iPosition;
		iEnd = m_iSize - 1;
	}
	else
	{
		iStart = pIndexTable[iSearchIndex - 1].m_iPosition;
		iEnd = pIndexTable[iSearchIndex].m_iPosition - 1;
	}

	for (int i = iStart; i <= iEnd; ++i)
	{
		if (iKeyValue_in == m_pArray[i])
		{
			iReturnIndex = i;
			break;
		}
	}


	delete[] pIndexTable;
	pIndexTable = nullptr;
	return iReturnIndex;
}
```

</Editor>

구현하며 놓쳤던 부분은 <strong>상단의 예외 처리</strong>다. 당연하게도 Key 값에 해당하는 자료를 검색하여 Index를 반환받는데, 해당 Key 값이 정렬된 자료의 <strong>범위(최솟값~최댓값)를 벗어나는 값</strong>이라면 <strong>바로 실패 처리</strong>를 해 주어야 한다.

## 4. 효율성과 한계

시간 복잡도는 전체 자료의 개수가 n개, 인덱스 테이블의 개수가 m개라 한다면, 키 값을 비교해야 하는 자료의 개수는 인덱스 테이블에서 평균 m개(테이블 항목 수)와 구간 안에서 평균 n/m개의 합으로

> O(m + n/m)

이 된다. 그래서 성능은 n과 m에 달려 있다. 한쪽 값이 편향적으로 크다면 성능 저하를 일으키기 때문이다. 자료의 개수가 증가하여 <strong>m마저 특정 개수 이상으로 커지면</strong>, 성능 향상을 위해 <strong>인덱스 테이블의 인덱스 테이블</strong>을 만들어야 하고... 또 2차 인덱스 테이블에서 성능 향상이 필요하다면? 3차까지...

조건 또한 <strong>자료가 정렬되어 있어야</strong> 하기 때문에, 기존 자료에 <strong>삽입/삭제가 이루어지면 인덱스 테이블을 새로 생성</strong>해야 하는 부담이 생긴다.
