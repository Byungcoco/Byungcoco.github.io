## 1. 플로이드(Floyd) 알고리즘

모든 시작점에서 최단 경로를 구하는 알고리즘이다. 기본적으로 플로이드는 다익스트라와 동일한 접근 방법을 사용한다. 즉, 최단 경로를 수정하는 전략이 동일하다.

다익스트라와 달리 시작 노드가 6개, 도착 노드도 각 5개(본인 제외)로, 정말 모든 최단 경로를 뜻한다. (앞 글의 노드 6개짜리 그래프 기준)

기존 최단 거리를 통해 목적 노드까지의 최단 거리를 산출해 내는 방식은 동일하지만, 다익스트라는 특정 노드를 대상으로 모든 노드까지의 최단 경로를 구했다면 플로이드는 모든 노드에서 모든 노드까지의 최단 경로를 구해야 하므로 <strong>2차원 배열</strong>에 표현해야 한다.

<Fig n={1} src="/img/notes/ds/floyd/via.png" caption="r에서 s로 갈 때 중간 노드 v를 거치는 쪽이 더 짧으면 갱신한다" max={640} />

시작 노드 r, 도착 노드 s, 중간 노드 v를 각각 그래프 G의 모든 노드로 돌릴 때 다음 수식이 나온다.

> y<sub>r,s</sub> = y<sub>r,v</sub> + c<sub>v,s</sub>,  if y<sub>r,v</sub> + c<sub>v,s</sub> &lt; y<sub>r,s</sub>

이를 의사 코드로 나타내면

```text
for (v : 그래프 G의 모든 노드)
    for (r : 그래프 G의 모든 노드)
        for (s : 그래프 G의 모든 노드)
            if (A[r][v] + A[v][s] < A[r][s])
                A[r][s] = A[r][v] + A[v][s]
```

다익스트라 알고리즘과 마찬가지로 도착 노드의 최단 경로를 구하기 위해, 중간 노드까지의 최단 경로와 부속 간선을 더한 값과 기존 경로 값을 비교하여 최단 경로를 변경한다.

## 2. 진행 과정

그냥 다익스트라를 여러 번 돌리면 되지 않나? 싶지만 자세한 순서를 살펴보며 파악해 보자. 다익스트라를 그냥 반복하면 시작 노드별로 한 줄씩 2차원 배열 표가 채워지겠지만, 플로이드는 그렇지 않다. 중간 노드를 하나씩 정해 두고, 그 노드를 거쳐 가는 경로로 표 전체를 갱신한다.

첫 초기화는 다익스트라와 같다. 부속 간선으로 바로 연결된 노드를 제외한 모든 거리는 무한대로 표시한다. (앞 글의 그래프: 간선 0-1(1), 0-2(4), 1-2(2), 2-3(1), 3-4(8), 3-5(3), 4-5(4))

<div class="tbl">

| 초기화 | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 0 | 0 | 1 | 4 | ∞ | ∞ | ∞ |
| 1 | 1 | 0 | 2 | ∞ | ∞ | ∞ |
| 2 | 4 | 2 | 0 | 1 | ∞ | ∞ |
| 3 | ∞ | ∞ | 1 | 0 | 8 | 3 |
| 4 | ∞ | ∞ | ∞ | 8 | 0 | 4 |
| 5 | ∞ | ∞ | ∞ | 3 | 4 | 0 |

- v = 0: 중간 노드 0을 노드 1에서 노드 2까지의 경로 A[1][2] 및 A[2][1]에 이용할 수 있지만, 1 + 4 = 5로 기존 2보다 단축되지 않아 반영하지 않는다.
- v = 1: 중간 노드 1을 노드 0에서 2까지의 경로에 이용할 수 있다. A[0][1] + A[1][2] = 1 + 2 = 3 &lt; 4 이므로 A[0][2], A[2][0]이 3으로 바뀐다.
- v = 2: A[0][3] = A[0][2] + A[2][3] = 3 + 1 = 4, A[1][3] = 2 + 1 = 3으로 무한대였던 값들이 채워진다.
- v = 3: 3을 거쳐 4, 5로 가는 경로가 채워진다. 예를 들어 A[0][4] = 4 + 8 = 12, A[0][5] = 4 + 3 = 7.
- v = 4, 5: 5를 거치면 A[3][4] = 3 + 4 = 7 &lt; 8 이 되는 식으로 남은 값들이 더 줄어든다.

모든 v를 마친 최종 표는 다음과 같다.

0번 행이 다익스트라로 구한 결과(1, 3, 4, 11, 7)와 같은 것을 볼 수 있다.

<Fig n={2} src="/img/notes/ds/floyd/loops.png" caption="중간 노드 v가 가장 바깥 반복문에 있는 이유" max={640} />

여기까지 보고 슬슬 감이 오기 시작한다. 가장 바깥쪽 for 문에 중간 노드 v가 위치한 이유는 해당 v를 중간 노드 기준으로 모든 탐색을 하기 위해서고, v 안쪽의 시작 노드 r은 말 그대로 v를 경유하는 시작 포인트를 순회하며, 가장 안쪽의 도착 노드 s는 r에서 v를 거쳐 도착할 노드를 순회한다. 그래서 삼중 for 문 구조가 나온다.

## 3. 다익스트라와 비교

다익스트라가 O(n²), 플로이드가 O(n³)이 되는데, 다익스트라를 n번 반복시켜도 성능상 동일하다. 하지만 그러려면 다익스트라를 구현해야 하므로, 비교적 간단한 알고리즘으로 구현 가능한 플로이드를 상황에 맞게 사용한다는 것이다. 모든 노드의 모든 경로를 탐색한다면 플로이드, 다익스트라가 이미 있다면 그냥 다익스트라 반복...

- <strong>다익스트라</strong>는 특정 노드에 해당하는 모든 경로의 최단 경로를 표현해 내야 하므로 결과가 1차원 배열로 나타난다. 그래서 특정 노드의 부속 간선으로 표현한 최단 거리를 시작으로 파고 들어가는 형식이다. 경로로 연결된 집합 S(V)를 만들어, 특정 노드 기준 최단 거리에 해당하는 Vertex를 빼면서 최단 거리를 계산해 나갔다. y<sub>w</sub> = y<sub>v</sub> + c<sub>vw</sub> (if y<sub>v</sub> + c<sub>vw</sub> &lt; y<sub>w</sub>) 같은 수식으로 나타낼 수 있는데, y<sub>v</sub>는 특정 노드 기준 최단 거리, c<sub>vw</sub>는 최단 거리 노드 v에서 목표 노드 w로 가는 부속 간선을 나타낸다.
- <strong>플로이드</strong>는 모든 경로의 모든 최단 거리를 찾아내다 보니 2차원 배열로 펼쳐 표현해야 한다. 기존 최단 거리에 부속 간선의 가중치를 더한 값이 더 작다면 최단 거리를 갱신하는 메커니즘은 똑같다. 하지만 플로이드가 간단한 알고리즘으로 나오는 이유는 2차원 배열에 모든 경로의 최단 경로가 기입되어 있기 때문이다. 다익스트라에서는 특정 노드를 시작으로 직접 산출해 내야 했지만, 플로이드는 표가 모두 포함하므로 아래와 같이 나타낼 수 있다.

## 4. 구현

<Editor file="MyListGraph.cpp" fn="CMyListGraph::GetAllMinPathByFloyd()">

```cpp
int **CMyListGraph::GetAllMinPathByFloyd()
{
	// ... 코드 중략
	for (int v = 0; v < m_iMaxVertexCount; ++v)
	{
		for (int r = 0; r < m_iMaxVertexCount; ++r)
		{
			if (r == v)
				continue;
			for (int s = 0; s < m_iMaxVertexCount; ++s)
			{
				if (r == s || v == s)
					continue;

				if (pReturnMatrix[s][r] > pReturnMatrix[s][v] + pReturnMatrix[v][r])
				{
					pReturnMatrix[s][r] = pReturnMatrix[s][v] + pReturnMatrix[v][r];
				}
			}
		}
		// ... 코드 중략
	}

	return pReturnMatrix;
}
```

</Editor>

코드 그대로, 초기화된 `pReturnMatrix`에서 출발 노드 → 도착 노드의 거리가 출발 노드 → 중간 노드, 중간 노드 → 도착 노드의 가중치를 더한 것보다 크다면 갱신해 준다. 다익스트라의 y<sub>w</sub> = y<sub>v</sub> + c<sub>vw</sub>와 같은 원리다.
