## 1. 재귀적 접근 방법

재귀 함수는 주로 비선형 자료구조에서 응용된다. 트리나 그래프에서 노드를 탐색하거나, 다원 탐색 트리에서 노드를 삭제하거나 병합할 때 활용된다.

재귀적 접근 방법은 큰 문제를 여러 개의 작은 문제로 나누는 것에서 시작한다. 여기서 중요한 전제는 <strong>나누어지는 작은 문제들이 모두 같은 타입</strong>이라는 것이다. 큰 정사각형을 같은 모양의 작은 정사각형으로 나누는 것이지, 직사각형이나 삼각형처럼 다른 타입으로 나누는 것이 아니다. 다른 타입으로 나누는 것은 재귀적 접근 방법에 위배된다.

재귀적 접근 방법의 또 다른 특성은 <strong>종료 조건</strong>이다. 문제를 끝없이 작게 나눌 수는 없으므로, 문제가 충분히 단순해져 바로 풀 수 있는 수준에 다다르면 더 나누지 않고 멈춰야 한다.

재귀적 접근 방법은 해결하기 힘든 큰 문제를 한 번에 해결하는 것이 아니라, 쉽게 풀 수 있는 작은 문제 여러 개로 쪼개어 해결한다는 뜻에서 <strong>분할 정복</strong>의 한 방법이라고 한다. 그래서 복잡한 문제도 간단한 원칙으로 손쉽게 해결할 수 있다는 장점이 있다.

이 때문에 개발 초기에는 재귀적으로 풀어 두고, 비재귀(단순 반복)로 해결이 가능하면 바꾸는 식으로 작업한다.

## 2. 팩토리얼

팩토리얼은 `n! = n × (n-1) × … × 2 × 1`이고, 재귀적으로 쓰면 다음과 같다.

- `n = 1`이면 `n! = 1`
- `n > 1`이면 `n! = n × (n-1)!`

여기서도 재귀 함수의 특징이 드러난다. 큰 문제를 작은 문제로 나누어 해결하므로, 처음 함수에 들어가는 숫자가 가장 큰 숫자이고, 더 작은 숫자로 쪼갤 수 없을 때 반환하는 구조로 이루어진다. `5!`이라면 5가 첫 함수 호출의 매개변수이다.

반환이 시작되면 재귀적으로 호출했던 <strong>역순으로 반환</strong>하며 결과를 가져온다(<FigRef n={1} />).

## 3. 재귀 호출의 내부 구현

재귀 호출은 <strong>스택</strong>을 이용해서 가능해진다. 함수를 호출할 때 그 함수에서 사용하는 지역 변수와 매개변수(Parameter) 등을 저장하는 공간을 <strong>활성 레코드</strong>라 한다. 함수가 호출되면 호출되는 함수별로 활성 레코드에 함수 관련 정보를 저장하고, 이 활성 레코드를 호출 순서대로 스택에 쌓는다.

그래서 활성 레코드를 쌓고 꺼내며 처리하는 과정에는 비용이 든다. 기존에 수행하던 함수의 지역 변수와 인자 대신 새로운 함수의 지역 변수와 인자를 적재해야 하기 때문이다. 즉, 문제의 크기가 커질수록 수행 시간이 점점 늘어난다.

- 스택의 크기는 한정되어 있기 때문에, 스택이 감당할 수 있는 이상으로 반복 호출하면 <strong>스택 메모리 부족</strong>(스택 오버플로우)이 발생한다.
- 앞에서 단순 반복문으로 바꿀 수 있으면 바꾸라고 한 이유도, 속도에서 현저한 차이가 나기 때문이다.
- 코드상으로는 하나의 함수를 재귀적으로 호출하지만, 실행 시에는 호출마다 별도의 활성 레코드를 가진 서로 다른 호출로 처리된다.
- 참고로, 재귀 호출이 2번인 함수를 반복문으로 바꾸려면 스택을 직접 이용해야 한다.

## 4. 피보나치 수열

피보나치 수열은 다음과 같이 정의된다.

- `n = 0`이면 `fib(n) = 0`
- `n = 1`이면 `fib(n) = 1`
- `n ≥ 2`이면 `fib(n) = fib(n-1) + fib(n-2)`

피보나치 수열은 재귀 함수로 쉽게 풀어낼 수 있지만, 그 함수가 효율적인 것은 아니다. `fib(6)`을 계산하려면 같은 값을 계산하는 <strong>불필요한 중복 호출</strong>이 여러 번 이루어진다(<FigRef n={2} />).

<Fig n={2} src="/img/notes/ds/recursion/fibtree.png" caption="fib(6)의 호출 트리 — 같은 색은 중복 계산" max={740} />
