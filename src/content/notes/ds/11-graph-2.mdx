## 1. 인접 리스트를 이용한 구현

그래프를 인접 리스트로 구현하는 방법은? 정점별로 연결된 정점을 연결 리스트로 저장하는 방식이다.

인접 행렬은 간선 저장을 통해 그래프를 나타내었다면, 인접 리스트는 특정 노드에 연결되는 노드를 저장하는 방식으로 그래프를 구현한다.

<Fig n={1} src="/img/notes/ds/graph-2/adj-list.png" caption="방향 그래프와 그 인접 리스트 — 정점 3의 리스트에는 진출 차수만큼 노드가 들어 있다" max={720} />

그림을 보면 3번 노드의 리스트에는 Out-Degree만큼 노드가 저장되어 있다. 즉, 3에서 나가는 간선의 종료 노드에 대한 정보가 있다. 방향 그래프이므로 대칭성이 존재하지 않는다.

가중치가 존재한다면? 저장된 노드에 가중치를 함께 저장한다. 간선 (3, 2)의 가중치가 5라면 3의 리스트에 있는 노드 2에 가중치 5 정보를 포함한다.

무방향 가중 그래프라면 (0, 1)이 있으면 (1, 0)도 있어야 하므로, 대칭성과 같은 가중치에 대한 정보가 양쪽 노드에 담겨 있어야 한다.

## 2. 인접 행렬과 비교

늘 있던 배열과 연결 리스트의 차이로, 고정된 메모리와 반대로 삽입이 자유롭고 불필요한 메모리 사용이 줄어든다.

이 장점이 극명하게 드러나는 것이 <strong>희소 그래프</strong>(간선의 개수가 가능한 최대 간선 수보다 훨씬 적은 그래프)다. 인접 행렬은 희소 그래프라 하더라도 노드 개수 n의 제곱만큼 메모리 할당이 필요했지만, 인접 리스트는 연결된 노드 정보만을 저장하기 때문에 아주 작은 메모리로 표현해낼 수 있다.

단, 늘 있던 장단점으로 연결 리스트로 인접 리스트를 구현할 경우 구현의 복잡성이 올라간다. 그리고 저장하는 그래프가 희소 그래프가 아니라면 메모리 효율성이 조금 떨어진다. 간선의 개수가 많고 표현할 데이터가 많다면? 인접 행렬이 훨씬 효율적이다.

또한 배열은 <strong>임의 접근</strong>으로 바로 <strong>간선에 접근</strong>할 수 있지만, 연결 리스트는 노드를 타고 가며 순회해야 한다. n개의 노드가 있을 때 특정 간선을 확인하는 시간 복잡도는

1. 리스트: 평균 O(n)
2. 행렬: O(1)

리스트의 경우 특정 시작 노드의 리스트에 접근하는 것은 O(1)로 쳐줄 수 있겠지만, 종료 노드를 찾기 위해 순회하는 연산이 평균 O(n)이다.

따라서 정리하면 다음이 정석이 되겠다.

- 노드만 덩그러니 많다 → 낭비될 메모리가 예상된다 → 인접 리스트
- 노드와 간선이 빼곡하다 → 메모리를 알차게 쓴다 → 인접 행렬

## 3. 그래프 탐색

평등한 객체의 탐색은 어떻게 이루어질까? 고속도로 지도를 예로, 지도상의 모든 도시를 방문하려면 어떤 순서로 방문이 이루어져야 할까?

그래프의 탐색(Search, Traversal)은 간선을 이용하여 그래프상의 모든 노드를 한 번씩 방문하는 것을 말한다. 수많은 방법이 있지만 가장 대표적인 두 가지 방법에 대해 알아보자.

1. 깊이 우선 탐색 (DFS)
2. 넓이 우선 탐색 (BFS)

<Fig n={2} src="/img/notes/ds/graph-2/dfs-bfs.png" caption="같은 그래프를 DFS와 BFS로 방문한 순서" max={740} />

0에서 시작해 현재 선택된 노드가 1이라고 했을 때, 다음 노드는 2 혹은 3이다. 그런데 노드 1은 2와 연결되어 있지 않다? 3과 1은 부모-자식 관계처럼 직접 연결되어 있지만, 2는 형제 관계처럼 노드 0을 서로 공유함을 인지해야 한다.

여기서 깊이가 우선이라면 3이 될 테고, 넓이가 우선이라면 2가 선택될 것이다. 즉, 깊이 우선이란 노드 간의 연결을 우선시하여 탐색하고, 넓이 우선은 이전 노드를 공유하는 형제 노드를 우선적으로 탐색한다.

## 4. 깊이 우선 탐색 (DFS)

0에서 연결된 노드 2, 1을 스택에 푸시한다. 이후 후입선출로 1을 팝하며 1에 연결된 노드 4, 3을 푸시하고 계속 이어 나간다. 이후 7까지 푸시하고 더 이상 자식 노드가 없으면? 자식 노드가 있는 노드를 찾을 때까지 팝을 해 나간다.

이러한 깊이 우선 탐색은 그래프의 모든 간선에 대해 조사를 진행하므로, 노드의 수가 n개, 간선의 수가 m개인 그래프의 경우 O(n+m)이 소요된다. 단, 그래프가 인접 리스트로 구현된 경우이며, 행렬을 사용하면 O(n²)이 된다.

<Editor file="MyListGraph.cpp" fn="CMyListGraph::DFS(...)">

```cpp
void CMyListGraph::DFS(const int &iStartIndex)
{
	if (iStartIndex >= m_iMaxVertexCount || !CheckVertexValid(iStartIndex))
		return;

	bool *pVisitedArray = new bool[m_iMaxVertexCount] {UNUSED};
	for (int i = 0; i < iStartIndex; ++i)
	{
		pVisitedArray[i] = USED;
	}

	LinkedListStack DstStack;
	ListStackNode *pPopNode = nullptr;
	LGNode *pSearchNode = nullptr;
	pVisitedArray[iStartIndex] = USED;
	DstStack.Push({ iStartIndex, });
	
	int iSearchIndex = iStartIndex;
	while (!DstStack.isEmpty())
	{
		pPopNode = DstStack.Pop();
		iSearchIndex = pPopNode->_iData;
		std::cout << "VisitedNode: " << iSearchIndex << '\n';

		if (pSearchNode = m_ppAdjEdge[iSearchIndex]->GetHeadNode()->m_pLink)
		{
			int iTmpID = 0;
			while (pSearchNode)
			{
				iTmpID = pSearchNode->m_tData.m_iVertexID;
				if (pVisitedArray[iTmpID] <= UNUSED)
				{
					std::cout << "Push  ";
					pVisitedArray[iTmpID] = USED;
					DstStack.Push({ iTmpID, });
				}
				pSearchNode = pSearchNode->m_pLink;
			}
			std::cout << '\n';
		}

		delete pPopNode;
	}

	delete [] pVisitedArray;
	pVisitedArray = nullptr;
}
```

</Editor>

직접 만든 코드에서는 Pop 연산 시 new로 새로 동적 할당한 노드를 넘겨준다. 그래서 건네받은 쪽에서 자료 삭제를 유념해야 하며, 방문 처리는 <strong>스택에 Push하면서</strong> 진행한다. 실제 방문(출력)은 Pop을 하며 이루어지지만 이 부분을 주의해야 한다. 이렇게 하는 이유는 무방향 그래프이기 때문에 각 간선이 인접 노드 리스트에 <strong>대칭적으로 모두 들어가</strong> 있기 때문이다.

만약 방문을 점검하지 않는다면?

1. 무한 루프에 빠진다. 그렇다고 단순 출력부(Pop 시점)에서 `pVisitedArray` 방문 처리를 진행하면?
2. Push 연산이 모든 간선, 즉 대칭적인 부분까지 Push하고 Pop하기 때문에 원래 간선보다 2배의 new, delete 연산이 진행된다.
3. 그럼 안쪽 반복문 바깥에서 체크를 하면? 원래 간선의 개수만큼 new, delete 연산이 수행된다.
4. 그런데 그래프 노드의 관계상 모든 간선을 탐색할 필요가 있을까? 아니다. 모든 간선을 사용하지 않아도 모든 노드의 방문 처리가 가능하다.
5. 테스트 기준 7개의 Vertex를 가지는 무방향 그래프에서 7번의 Push, Pop 연산으로 줄여 냈다. 스택에 Push된다는 것은 곧 방문이 예약되었다는 것이니, Push할 때 바로 USED로 처리해 준다.

그렇게 되면 이미 방문한 노드의 간선에는 접근하지 않게 되면서 Push, Pop 연산이 줄어든다. 기억해 두자.

<strong>깊이 우선 탐색은 깊은 곳을 우선적으로 탐색하는 것이 아니라, 자식 노드를 우선적으로 방문하며 탐색하기 때문에 Depth First Search가 되는 것이다.</strong> 헷갈리지 말자. 그럼 BFS는? 넓은 곳을 먼저 탐색하는 것이 아니라, 자식 노드보다 형제 노드의 탐색을 우선하는 것이다.

## 5. 넓이 우선 탐색 (BFS)

깊이 우선 탐색은 재귀 호출로도 구현할 수 있지만, 넓이 우선 탐색은 Queue를 활용하여 탐색이 이루어진다. 마찬가지로 방문 여부를 점검하는 1차원 배열과 함께 구현한다.

DFS와 마찬가지로 자료구조에 자식 노드를 집어넣으며 시작한다. 그런데 Stack은 LIFO 특성으로 자식 노드를 파고 들어가는 로직이 되는 것이고, Queue도 똑같이 자식을 넣지만 FIFO 특성 때문에 먼저 들어온 형제 노드가 먼저 나오면서 자연스럽게 넓이가 우선적으로 선택된다.

코드 또한 로직이 같아 Stack이 Queue로 바뀌면 된다.

<Editor file="MyListGraph.cpp" fn="CMyListGraph::BFS(...)">

```cpp
void CMyListGraph::BFS(const int &iStartIndex)
{
	// ... 코드 중략
	MyLinkedQueue MyQueue;
	QueueNode *pDequeueNode = nullptr;
	LGNode *pSearchNode = nullptr;
	MyQueue.Enqueue({ iStartIndex, });
	pVisitedArray[iStartIndex] = USED;

	int iSearchVertexID(0);
	while (!MyQueue.isEmpty())
	{
		pDequeueNode = MyQueue.Dequeue();
		iSearchVertexID = pDequeueNode->_iData;
		std::cout << "Visisted Node: " << iSearchVertexID << '\n';

		if (pSearchNode = m_ppAdjEdge[iSearchVertexID]->GetHeadNode()->m_pLink)
		{
			int iTmpVertexID = 0;
			for (; pSearchNode; pSearchNode = pSearchNode->m_pLink)
			{
				iTmpVertexID = pSearchNode->m_tData.m_iVertexID;

				if (pVisitedArray[iTmpVertexID] <= UNUSED)
				{
					std::cout << "Enqueue  ";
					MyQueue.Enqueue({ iTmpVertexID, });
					pVisitedArray[iTmpVertexID] = USED;
				}
			}
			std::cout << '\n';
		}

		delete pDequeueNode;
		pDequeueNode = nullptr;
	}

	delete[] pVisitedArray;
	pVisitedArray = nullptr;
}
```
