## 1. 리스트

자료를 순서대로 저장하는 자료구조이다. 일직선으로 서로 연결된 선형구조이며, 스택, 큐, 트리, 그래프 등 다른 여러 자료구조의 구현에도 응용된다.

배열에서 중간 삭제가 발생하면, 빈 공간을 처리하기 위해 뒷부분을 한 칸씩 옮겨서 배열의 마지막 공간을 확보해야 한다. 그래야 새로운 자료를 추가할 수 있다. 추가 또한 빈 공간을 만들기 위해 기준 위치부터 뒤의 원소가 모두 한 칸씩 물러나야 한다.

배열은 10개로 고정된 공간에 저장되는 반면, 연결 리스트는 10개의 자료가 각각 서로 연결되어 있을 뿐 개수에 제약이 없다. 포인터를 이용하여 구현되기 때문에 동적으로 할당하여 추가하면 되고, 중간을 제거할 때는 자료 사이의 연결 포인터만 재설정하면 된다.

#### 문자 리스트, 문자열 리스트, 행렬

- 문자 리스트: `D`, `a`, `t`, `a`가 차례대로 저장되어 순서대로 선형구조를 이룬다.
- 문자열 리스트: 문자열 자료를 차례대로 저장한다.
- 행렬(Matrix): 연속된 숫자들을 저장한다. 행렬은 각 행(Row)이 열(Col) 개수만큼의 자료를 가지는 리스트라고 볼 수 있다.

행렬의 구성 요소 중 0이 더 많은 경우를 <strong>희소 행렬</strong>이라 한다. 예를 들어 4×4 행렬에서 전체 원소는 16개인데 0이 아닌 원소는 3개뿐이라면 비효율적인 공간 활용이다. 그래서 0이 아닌 원소의 값과 위치 정보만 저장하여 저장 공간 효율을 높일 수 있다.

같은 방식으로 리스트를 활용하여 다항식을 저장할 수도 있다. `4x³ + 2x + 1`은 최대 차수가 3차이고, 3차의 계수가 4, 1차의 계수가 2, 상수항이 1이다. 차수를 인덱스로 삼으면 다음과 같이 저장된다.

- 첫 번째 공간(인덱스 0) → x⁰의 계수 1
- 두 번째 공간(인덱스 1) → x¹의 계수 2
- 네 번째 공간(인덱스 3) → x³의 계수 4

#### 리스트 추상 자료형

<div class="tbl">

| 이름 | 연산 | 설명 |
|---|---|---|
| 리스트 생성 | `createList()` | 최대 n개의 원소를 가지는 빈 리스트 생성 |
| 리스트 삭제 | `deleteList()` | 리스트 제거 |
| 원소 추가 가능 여부 | `isFull()` | 원소 개수가 최대 개수와 같은지 반환(배열 리스트에서만 의미 있음) |
| 원소 추가 | `addElement()` | 원소를 리스트의 위치 p에 추가 |

| 리스트 초기화 | `clearList()` | 모든 원소 제거 |
| 원소 개수 | `getListLength()` | 원소 개수 반환 |
| 원소 반환 | `getElement()` | 위치 p의 원소 반환 |

</div>

`addElement()`의 원소 위치 p는 어느 위치에 저장할지를 지정하는 값이다. 0부터 시작하는 인덱스 원칙을 따른다. 이때 그 위치 이후에 있던 자료들은 한 칸씩 뒤로 밀려난다.

이러한 리스트의 구현 방법은 배열을 이용한 <strong>배열 리스트</strong>와 포인터를 이용한 <strong>연결 리스트</strong>로 나눌 수 있다.

## 2. 배열 리스트와 연결 리스트

#### 배열 리스트

배열로 구현한 리스트로, 원소(Element)들이 메모리상에 순서대로 연속하여 저장된다. 그래서 <strong>논리적 순서와 물리적 순서가 같다</strong>는 특성이 있다(메모리의 연속성, 선형구조).

중간 삽입 시에는 그 위치를 기준으로 뒤의 원소를 모두 밀어내고 해당 인덱스에 데이터를 추가해야 한다(<FigRef n={1} />). 가장 오른쪽 원소부터 차례대로 옮기는 이유는 기존 원소가 덮어써져 사라지는 것을 막기 위해서이다. 따라서 가장 마지막에 원소를 추가하는 경우에는 기존 원소들의 이동이 필요 없다.

연속성을 유지해야 하는 제약 때문에, 원소의 개수가 많고 배열 중간에서 원소를 추가/삭제하는 일이 빈번하다면 상당한 부하가 발생할 수 있다.

#### 연결 리스트

포인터를 이용하여 구현하기 때문에 물리적으로 멀리 떨어져 있는 자료를 순서대로 연결해 놓는다(메모리 연속성 X). 그래서 연속성을 유지해야 하는 배열 리스트와 달리 최대 개수에 대한 제약이 없다. 새로운 메모리를 할당하고 연결해서 논리적인 연속성만 갖춰 주면 되기 때문이다.

연결 리스트는 자료(Data)와 링크(Link)로 이루어진 노드(Node)들로 구성된다. 배열 리스트에서는 자료만 저장하므로 원소와 노드가 같지만, 연결 리스트의 노드는 자료 + 링크를 뜻하므로 원소를 포함하는 개념이다. 링크는 다음 차례의 노드를 가리키고, 마지막 노드는 다음 노드가 없으므로 null을 가리킨다.

물리적인 제약이 없어지니 최대 개수 제한에서 자유롭고, 위치를 정확히 알고 있다는 가정하에 중간 삽입/삭제를 간단하게 구현할 수 있다.

- 삽입: 삽입할 위치의 이전 노드가 가진 링크를 끊고 새 노드를 가리키게 한 뒤, 새 노드가 원래 그 위치에 있던 노드를 가리키게 만든다(<FigRef n={1} />).
- 제거: 반대로 삭제할 노드를 가리키던 이전 노드의 링크와 삭제할 노드의 링크를 해제하고, 이전 노드의 링크가 다음 노드를 가리키게 하면 연결이 끝난다.

<Fig n={1} src="/img/notes/ds/linked-list/insert.png" caption="중간 삽입 — 배열은 원소를 밀고, 연결 리스트는 링크만 바꾼다" max={720} />

그래서 원소 이동이 빈번하거나 원소 개수를 예상하기 어려울 때는 연결 리스트로 구현하는 것이 바람직하다.

단점은 구현이 어렵고, <strong>탐색 연산의 비용이 높다</strong>는 것이다. 배열 리스트는 논리적·물리적으로 연속되기 때문에 원하는 인덱스로 바로 접근할 수 있다(`pElement[position]`). 반면 연결 리스트는 물리적으로 떨어져 있으므로 첫 번째 노드부터 링크를 따라 `position - 1`번 이동해야 한다. 그래서 위치로 원소에 접근하는 시간 복잡도는 배열이 `O(1)`, 연결 리스트가 `O(n)`이다.

## 3. 연결 리스트의 종류

<Fig n={2} src="/img/notes/ds/linked-list/kinds.png" caption="단순 · 원형 · 이중 연결 리스트" max={720} />

- <strong>단순 연결 리스트</strong>: 마지막 링크가 null을 가리킨다. 헤더 노드는 데이터 저장을 위한 노드가 아니라, 노드 추가/삭제를 간편하게 하기 위한 더미 노드이다.
- <strong>원형 연결 리스트</strong>: 마지막 링크가 첫 번째 노드를 가리킨다(순환 구조). 리스트는 헤더 노드가 아닌 헤드 포인터를 가진다.
- <strong>이중 연결 리스트</strong>: 노드마다 앞뒤를 가리키는 링크가 있으며, 첫 번째 노드의 앞 링크와 마지막 노드의 뒤 링크는 nullptr이 된다.

단순 연결 리스트에서 이전 노드를 확인하려면 처음부터 다시 탐색해야 한다. 원형 연결 리스트에서는 계속 순회하다 보면 이전 노드를 만나게 된다. 이런 단방향 연결 리스트와 달리, 이중 연결 리스트는 이전 노드와 다음 노드에 직접 접근할 수 있다.

#### 헤더 노드와 헤드 포인터

헤드 포인터는 연결 리스트의 첫 번째 노드를 가리키는 포인터이다. 헤드 포인터를 쓰면 첫 노드를 추가/삭제할 때처럼 고려해야 할 경우의 수가 늘어나서, 헤더 노드를 쓸 때보다 구현이 복잡해진다는 단점이 있다.

## 4. 연결 리스트 연산 구현

연결 리스트가 어디에 응용되는지 보기 전에, 순회 함수, 다른 연결 리스트를 연결하는 함수, 연결 리스트를 역순으로 만드는 함수부터 살펴본다.

#### 순회

`pNode = pNode->_pLink;`로 링크를 따라 이동한다.

#### 다른 연결 리스트 연결하기

헤더 노드가 아닌 B 리스트의 첫 번째 원소를 A 리스트의 마지막 노드와 연결하고, B 리스트 헤더 노드의 링크는 null로 처리한다. 원소의 총개수도 더해 주고 B 리스트의 개수는 0으로 만든다.

복사가 아니라 <strong>연결</strong>하는 함수이기 때문이다. 노드들은 동적 할당되어 있으므로, 주소만 복사해 두 리스트가 같은 노드를 가리키게 되면 메모리 해제 시점에 중복 해제가 발생한다.

<Editor file="MyLinkedList.h" fn="MyLinkedList<T>::Concat(...)">

```cpp
template<typename T>
void MyLinkedList<T>::Concat(MyLinkedList<T> &LinkedList_in)
{
	if (LinkedList_in._iTotalElement <= 0)
		return;

	GetLastNode()->_pLink = LinkedList_in._HeaderNode->_pLink;
	_iTotalElement += LinkedList_in._iTotalElement;

	LinkedList_in._HeaderNode->_pLink = nullptr;
	LinkedList_in._iTotalElement = 0;
}
```

</Editor>

#### 연결 리스트 역순으로 만들기

이전·현재·다음 세 포인터를 한 칸씩 전진시키면서, 현재 노드의 링크를 이전 노드로 돌린다(<FigRef n={3} />). `pPrevNode`는 과거, `pCurrentNode`는 현재, `pNextNode`는 순회를 위한 포인터이다. 반복이 끝나면 헤더 노드가 마지막으로 처리한 노드를 가리키게 한다.

<Fig n={3} src="/img/notes/ds/linked-list/reverse.png" caption="역순 만들기 — 세 포인터로 링크 방향을 하나씩 뒤집는다" max={720} />

<Editor file="MyLinkedList.h" fn="MyLinkedList<T>::ReverseElement()">

```cpp
template<typename T>
void MyLinkedList<T>::ReverseElement()
{
	if (_iTotalElement <= 1)
		return;

	Node<T> *pNextNode = _HeaderNode->_pLink;
	Node<T> *pPrevNode = nullptr;
	Node<T> *pCurrentNode = nullptr;

	while (pNextNode)
	{
		pPrevNode = pCurrentNode;
		pCurrentNode = pNextNode;
		pNextNode = pNextNode->_pLink;
		pCurrentNode->_pLink = pPrevNode;
	}

	_HeaderNode->_pLink = pCurrentNode;
}
```

</Editor>

## 5. 응용: 다항식 덧셈

연결 리스트를 응용하여 다항식을 표현하고 덧셈하는 예제이다.

다항식은 계수와 차수로 정의되는 항들의 집합을 말한다. `aₙ₋₁xⁿ⁻¹ + aₙ₋₂xⁿ⁻² + … + a₁x¹ + a₀x⁰`에서 첫째 항 `aₙ₋₁xⁿ⁻¹`의 계수는 `aₙ₋₁`, 차수는 `n-1`, x는 변수이다. 노드 하나가 항 하나(계수, 차수)를 저장한다.

`A(x) = 6x⁶ + 4x⁵ + 2x²`와 `B(x) = 1x⁵ + 2x⁴ + 3x² + 4`처럼 두 다항식의 구성이 다른데 어떻게 덧셈을 할까? 각 리스트가 <strong>차수 내림차순으로 정렬</strong>되어 있다는 가정하에 가능하다. NodeA, NodeB 모두 가장 높은 차수인 첫 원소(`_HeaderNode->_pLink`)에서 출발하고, 세 가지 경우로 나뉜다(<FigRef n={4} />).

1. <strong>A의 차수가 높은 경우</strong>: 결과 리스트에 A의 항을 그대로 새 노드로 추가한다. B의 노드는 그대로 두고, 계산이 끝난 A만 `NodeA = NodeA->_pLink`로 옮긴다.
2. <strong>차수가 같은 경우</strong>: 계수를 더하고 차수는 그대로 두어 추가한다. 이 경우 두 노드 모두 이동한다.
3. <strong>B의 차수가 높은 경우</strong>: A가 컸을 때와 마찬가지로 B의 계수·차수로 노드를 추가한 후 B를 이동한다.

둘 중 하나의 노드가 먼저 nullptr이 되면 루프를 빠져나오고, 각각 `while (NodeA)`, `while (NodeB)`로 남은 노드까지 결과에 추가한다.

<Fig n={4} src="/img/notes/ds/linked-list/polyadd.png" caption="다항식 덧셈 — 결과 노드가 어떤 경우로 만들어졌는지 색으로 구분" max={740} />

<Editor file="LinkedList_Test.cpp" fn="MyLinkedList_Test::PolyAdd(...)">

```cpp
MyLinkedList_Test *MyLinkedList_Test::PolyAdd(MyLinkedList_Test &LinkedList_in)
{
	if (!_HeaderNode || _iTotalElement < 0
		|| !LinkedList_in._HeaderNode
		|| LinkedList_in._iTotalElement < 1)
		return nullptr;

	MyLinkedList_Test *pReturnList = new MyLinkedList_Test();
	NodeType *NodeA = _HeaderNode->_pLink;
	NodeType *NodeB = LinkedList_in._HeaderNode->_pLink;

	while (NodeA && NodeB)
	{		
		if (NodeA->_iDegree > NodeB->_iDegree)
		{
			pReturnList->Push_Back({ NodeA->_fCoef, NodeA->_iDegree});
			NodeA = NodeA->_pLink;
		}

		if (NodeA->_iDegree < NodeB->_iDegree)
		{
			pReturnList->Push_Back({ NodeB->_fCoef, NodeB->_iDegree });
			NodeB = NodeB->_pLink;
		}

		if (NodeA->_iDegree == NodeB->_iDegree)
		{
			pReturnList->Push_Back({ NodeA->_fCoef + NodeB->_fCoef, NodeA->_iDegree });
			NodeA = NodeA->_pLink;
			NodeB = NodeB->_pLink;
		}
	}

	while (NodeA)
	{
		pReturnList->Push_Back({ NodeA->_fCoef, NodeA->_iDegree });
		NodeA = NodeA->_pLink;
	}

	while (NodeB)
	{
		pReturnList->Push_Back({ NodeB->_fCoef, NodeB->_iDegree });
		NodeB = NodeB->_pLink;
	}

	return pReturnList;
}
```

</Editor>
