## 1. 정렬이란

정렬은 가장 기본적인 알고리즘이다. 개발의 역사와 함께 발전되었고, 대용량 자료가 범람하는 오늘날 자료의 효과적인 정렬은 기본이며 필수다.

<strong>정렬이란 순서 없이 배열된 자료를 순서에 따라 재배열하는 것</strong>을 말한다. 윈도우 탐색기의 날짜, 이름, 크기별 정렬을 예로 들 수 있겠다. 이러한 정렬은 파일을 쉽게 찾고 분류하는 데 기대 효과가 있다.

자료를 정렬하는 데 사용하는 자료의 값을 <strong>키(Key)</strong>라고 한다.

- 오름차순: 작은 값부터 시작해서 큰 값으로 증가하는 순서대로 배열 1, 2, 3, 4, 5
- 내림차순: 큰 값부터 시작해서 작은 값으로 감소하는 순서대로 배열 5, 4, 3, 2, 1

정렬의 효율성은 얼마나 <strong>빠르게</strong> 정렬을 실시하는지를 나타내는데, 정렬 대상이 되는 자료가 n개일 때 필요한 비교 연산과 자료 이동 연산의 횟수에 의해 결정된다.

현재 가장 효율이 우수한 정렬 알고리즘 중 하나인 퀵 정렬은 평균 O(n log n)인 데 비해, 많은 정렬 알고리즘은 수행 속도가 O(n²)이다.

자료의 크기와 상관없이 모든 경우에 최고의 성능을 내는 정렬 방법이 최고라 할 수 있지만, 때로는 특별한 상황에서 좀 더 좋은 효율을 내는 정렬도 있다. 즉, <strong>저장된 자료의 상태에 따라 평균 효율성과 최악인 경우의 효율성에 차이</strong>가 있으므로 정렬 알고리즘 선택에 고려해야 한다.

## 2. 정렬의 안정성

추가로 정렬의 효율성뿐만 아니라 정렬의 <strong>안정성(Stability)</strong>도 고려해야 한다. 정렬의 안정성이란 같은 키 값을 가지는 자료들을 입력 순서 그대로 정렬하는지를 말한다.

<Fig n={1} src="/img/notes/ds/sort-selection/stability.png" caption="키가 같은 두 자료의 순서가 안정 정렬에서는 유지되고, 불안정 정렬에서는 바뀔 수 있다" max={700} />

가운데의 안정 정렬은 키가 같은 자료가 입력 순서 그대로 정렬되는 반면, 오른쪽은 순서가 바뀌어 버린 상황을 볼 수 있다. 이러한 차이를 정렬의 안정성으로 나타낼 수 있다.

이러한 안정성 여부는 정렬에 사용되는 키가 2개 이상인 경우에 의미가 있다. 키가 여러 개 있을 때를 <strong>다중 키(Multiple-Key) 정렬</strong>이라고 하는데, 안정성 여부는 이러한 다중 키 정렬에서 중요한 차이를 발생시킨다.

안정 정렬이라면 기존 정렬의 내용이 유지되므로, 우선순위가 낮은 키부터 높은 키 순으로 여러 번 정렬하기만 하면 다중 키 정렬이 가능하다. 반면 불안정하다면 정렬의 키 값 비교를 위한 별도의 비교 로직이 추가된다.

## 3. 정렬의 분류

정렬은 정렬이 시행되는 장소와 방법에 따라 분류된다.

- 컴퓨터 메모리 내부에서 정렬하는 내부 정렬 (Internal Sort)
- 외부 기억 보조 장치에서 정렬하는 외부 정렬 (External Sort)

내부 정렬은 정렬 전 모든 자료가 컴퓨터 메모리에 로딩되기 때문에 빠르게 정렬할 수 있지만, 메모리에 한 번에 로딩할 수 없을 만큼의 대용량 데이터는 정렬할 수 없다. 반면 외부 정렬은 내부 정렬에 비해 수행 속도는 느리지만 내부 정렬이 처리할 수 없는 대용량 데이터를 정렬할 수 있다.

내부 정렬은 방법에 따라 다시 다음처럼 나뉜다.

1. 교환 정렬(Exchange) — 키 값을 비교하여 자료 교환: 버블 정렬, 퀵 정렬
2. 삽입 정렬(Insertion) — 키 값을 비교하고 자료를 삽입: 삽입 정렬, 셸 정렬
3. 병합 정렬(Merging) — 키 값을 비교하고 자료를 병합: 2-way 병합, n-way 병합
4. 분배 정렬(Distribution) — 키 값을 여러 개의 부분집합으로 분배한 다음 정렬: 기수 정렬
5. 선택 정렬(Selection) — 트리 자료구조 등 특정 자료구조를 통해 정렬: 선택 정렬, 히프 정렬

## 4. 선택 정렬 (Selection Sort)

말 그대로 해당 위치에 맞는 자료를 선택하는 알고리즘이다. 정렬되지 않은 구간에서 가장 작은 키 값을 찾아, 그 구간의 첫 번째 자리와 교환한다.

<Fig n={2} src="/img/notes/ds/sort-selection/selection.png" caption="매 회전마다 남은 구간의 최솟값을 골라 앞자리와 교환한다" max={560} />

<Editor file="SelectSort.h" fn="SelectSort::Sorting()">

```cpp
template <typename T>
class SelectSort : public MySort<T>
{
public:
	// ... 코드 중략

	virtual void Sorting() final
	{
		T *pData = MySort<T>::GetData();
		if (!pData)
			return;
		const unsigned int iSize = MySort<T>::GetSize();
		if (iSize < 2)
			return;

		for (int iOuter = 0; iOuter < iSize - 1; ++iOuter)
		{
			int iIndex(iOuter);
			for (int iInner = iOuter+1; iInner < iSize; ++iInner)
			{
				if (pData[iIndex] > pData[iInner])
					iIndex = iInner;
			}

			MySort<T>::MySwap(pData[iOuter], pData[iIndex]);
		}

		MySort<T>::PrintMyArray();
	}
};
```

</Editor>

- <strong>비교 연산 횟수</strong>: 두 개의 루프를 돌며 실행되므로 (n-1) + (n-2) + … + 2 + 1 = n(n-1)/2, 즉 O(n²)
- <strong>이동 연산 횟수</strong>: 자료의 교환 횟수는 바깥 루프 횟수(n-1)와 같으며, 교환마다 3번의 이동이 있으므로 3(n-1), 즉 O(n)
- <strong>최선, 평균, 최악</strong>: 모두 O(n²)

매우 느린 알고리즘이다. 하지만 자료 이동 연산이 적으므로 <strong>크기가 매우 큰 자료형에 유리</strong>하다. 다만 <strong>정렬의 안정성을 보장하지 못한다</strong>는 단점이 있다.
