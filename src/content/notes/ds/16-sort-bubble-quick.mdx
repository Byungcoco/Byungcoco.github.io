## 1. 버블 정렬 (Bubble Sort)

버블 정렬은 인접한 두 자료의 키 값을 비교하여 위치를 교환하는 정렬 방식이다. 한 회전이 끝날 때마다 가장 큰 값이 맨 뒤로 밀려나 자리가 확정된다.

<Fig n={1} src="/img/notes/ds/sort-bubble-quick/bubble.png" caption="버블 정렬 1회전 — 인접한 두 값을 비교하며 큰 값을 뒤로 보낸다" max={600} />

<Editor file="BubbleSort.h" fn="BubbleSort::Sorting()">

```cpp
template <typename T>
class BubbleSort : public MySort<T>
{
public:
	// ... 코드 중략

	virtual void Sorting() final
	{
		T *pData = MySort<T>::GetData();
		if (!pData)
			return;
		const unsigned int iSize = MySort<T>::GetSize();
		if (iSize < 2)
			return;

		for (int iOuter = 0; iOuter < iSize - 1; ++iOuter)
		{
			for (int iInner = 0; iInner < iSize-iOuter-1; ++iInner)
			{
				if (pData[iInner] > pData[iInner + 1])
					MySort<T>::MySwap(pData[iInner], pData[iInner + 1]);
			}
		}

		MySort<T>::PrintMyArray();
	}
};
```

</Editor>

- <strong>비교 연산 횟수</strong>: 버블 정렬 또한 두 개의 루프를 순회하므로 (n-1) + (n-2) + … + 1 = n(n-1)/2, 즉 O(n²)
- <strong>이동 연산 횟수</strong>: 버블 정렬은 정렬 상태에 따라 이동 연산 횟수에 차이가 있다. 자료가 이미 완전히 정렬되어 있다면 이동 연산은 0회, 역순으로 정렬된 경우에는 n(n-1)/2회 교환한다. 최선은 0, 평균과 최악은 O(n²)
- <strong>결론</strong>: 최선, 평균, 최악 모두 O(n²)

정렬 전 자료의 상태에 따라 이동 연산 횟수에 차이가 있지만, 그래도 빠른 정렬은 아니다. 또한 이동 연산이 O(n²)이라 자료형의 크기가 크다면 매우 비효율적인 정렬 방법이 된다.

장점이 있다면? <strong>정렬의 안정성이 유지</strong>되기 때문에 같은 키 값의 자료 위치는 변경되지 않는다.

## 2. 퀵 정렬 (Quick Sort)

퀵 정렬은 피봇(Pivot)을 기준으로 두 자료의 키 값을 비교하여 위치를 <strong>교환</strong>하는 정렬 방식이다.

피봇 기준 위치 교환이 끝난 다음에는? 기존 자료 집합을 해당 피봇 기준으로 2개의 부분집합으로 나누고, 부분집합에 대해 다시 퀵 정렬을 실행하는 <strong>분할 정복 기법</strong>에 바탕을 둔다.

<Fig n={2} src="/img/notes/ds/sort-bubble-quick/quick-partition.png" caption="피봇 30을 기준으로 한 첫 번째 분할" max={640} />

- 피봇: 가장 오른쪽 자료 30
- Left: 가장 왼쪽에서 오른쪽으로 움직이며 피봇보다 큰 자료를 찾음
- Right: 가장 오른쪽에서 왼쪽으로 움직이며 피봇보다 작은 자료를 찾음

1. Left 80 발견, Right 20 발견 → 교환
2. Left 50 발견, Right 10 발견 → 교환
3. Left와 Right가 70에서 만나 더 이상 움직일 수 없으므로 피봇과 교환

이제 30을 기준으로 왼쪽 `[20, 10]`, 오른쪽 `[50, 60, 80, 40, 70]` 두 부분집합이 생긴다.

- 왼쪽 부분집합: 기존 피봇 30으로 분할된 곳에서 다시 피봇(10)을 정하고 정렬을 시행한다. Left, Right 둘 다 움직일 수 없으니 바로 교환하고 정렬을 마친다. → `[10, 20]`
- 오른쪽 부분집합: 피봇 70, Left가 80, Right가 40을 찾아 교환한 뒤 Left와 Right가 만난 자리(80)와 피봇을 교환하고 분할한다. → `[50, 60, 40]`, 70, `[80]`
- 70 기준 오른쪽은 원소가 하나뿐이라 더 나눌 부분집합이 없으므로, `[50, 60, 40]`에 대한 퀵 정렬을 실행한다. 이번에는 기존 피봇이 70이고 새 피봇은 40이다.

기존 피봇이 달라진 걸 볼 수 있다. 아하! 분할의 기준이 된 피봇이 다음 단계의 기준 피봇이 되는구나. 이렇게 반복하면 정렬이 완료된다.

<Editor file="CMySort.cpp" fn="CMySort::PartitionQuickSort(...)">

```cpp
int CMySort::PartitionQuickSort(const int &iStart, const int &iEnd)
{
	int iReturnPivot(iEnd);
	int iLeft(iStart);
	int iRight(iEnd);
	while (iLeft<iRight)
	{
		while ((m_pArray[iReturnPivot] > m_pArray[iLeft]) && (iLeft < iRight))
		{
			++iLeft;
		}


		while ((m_pArray[iReturnPivot] <= m_pArray[iRight]) && (iLeft < iRight))
		{
			--iRight;
		}

		if (iLeft < iRight)
		{
			MySwap(m_pArray[iLeft], m_pArray[iRight]);
		}

	}

	MySwap(m_pArray[iReturnPivot], m_pArray[iRight]);

	Print();
	return iRight;
}
```

</Editor>

<Editor file="CMySort.cpp" fn="CMySort::QuickSort(...)">

```cpp
void CMySort::QuickSort(const int &iStart, const int &iEnd)
{
	int iPivot(0);

	if (iStart < iEnd)
	{
		iPivot = PartitionQuickSort(iStart, iEnd);
		QuickSort(iStart, iPivot - 1);
		QuickSort(iPivot + 1, iEnd);
	}
}
```

</Editor>

피봇을 통해 분할시키고, 이를 재귀로 풀어낸다. 눈에 안 익으니 계속 보자.

## 3. 퀵 정렬의 효율성

퀵 정렬은 두 개의 부분집합으로 나누어 자료의 위치를 교환하기 때문에, n개의 자료를 평균 O(n log n)만에 정렬하는 효율성을 가진다. 부분집합이 균형 있게 나뉠수록 비교 횟수가 줄어들기 때문이다. 또한 비교 연산이 상대적으로 적게 발생한다.

하지만 부분집합이 한쪽으로만 계속 몰릴 경우 O(n²)의 효율성을 가질 수도 있다.

- 최선, 평균: O(n log n)
- 최악: O(n²)

퀵 정렬은 자료 형태에 따라 효율성에 차이가 있기는 하지만, 전체적인 효율성을 볼 때는 우수하다. 최악의 경우를 줄이기 위해 기존 자료 중 중간 값을 피봇으로 선택하여 퀵 정렬을 수행하는 방법이 사용된다.

단, <strong>정렬의 안정성은 유지되지 않는다.</strong>
