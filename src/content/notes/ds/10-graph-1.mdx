## 1. 그래프란?

그래프는 객체 사이의 연결 관계를 표현하는 자료구조로, 지금까지 다룬 자료구조 중 표현 능력이 가장 뛰어나다.

선형 자료구조는 자료를 순차적으로, 효율적으로 저장하는 것이 목적이었다. 비선형 자료구조인 트리는 상속 관계, 회사 조직도, 컴퓨터의 폴더 구조 등을 나타낼 수 있다. 하지만 부모-자식 관계는 잘 나타내도 일반적인 관계는 나타내지 못하는 한계가 있다.

고속도로 지도를 떠올려 보면, 그래프는 1:1로 대응하는 선형 구조와 달리 비선형 구조를 이룬다. 또한 각 지역은 상속 관계라기보다 일반적인 관계로 서로 연결되어 있다. 그리고 <strong>계층 구조가 아닌 순환 구조</strong>를 이룰 수 있다. 이는 선형 구조와 트리가 가지지 못하는 속성이다.

이처럼 표현력이 뛰어나고 자유도가 높기 때문에, 실제 현실 시스템을 모델링하여 문제를 해결하는 수단으로 활용된다.

그래프의 노드는 정점(Vertex)이라고도 부르며, 그래프는 정점과 간선(Edge)으로 이루어진다. 간선은 단방향과 양방향을 모두 나타낼 수 있어서, 내비게이션에서 일방통행 도로와 일반 도로를 구분해 표현할 수 있다.

앞서 히프에서 높이에 따른 최소·최대 노드 개수를 공식으로 나타냈던 것처럼, 그래프도 정점과 간선의 관계로 정의할 수 있다.

`G = (V(G), E(G)) = (V, E)`

그래프 G는 정점들의 집합 V(G)와 간선들의 집합 E(G)로 구성된다는 뜻이다.

<div class="tbl">

| 구분 | 종류 | 설명 |
|---|---|---|
| 간선의 방향성 | 무방향 그래프 | 간선에 방향이 없는 그래프 |
| | 방향 그래프 | 간선에 방향이 있는 그래프 |
| 간선의 가중치 | 가중 그래프 | 간선에 가중치가 할당된 그래프 |
| 구조적 특징 | 완전 그래프 | 연결 가능한 최대 간선 수를 가진 그래프 |
| | 부분 그래프 | 원래 그래프에서 일부 노드나 간선을 제외한 그래프 |
| | 다중 그래프 | 중복된 간선을 포함하는 그래프 |

</div>

## 2. 간선의 특성에 따른 종류

<Fig n={1} src="/img/notes/ds/graph-1/kinds.png" caption="무방향 · 방향 · 가중 그래프" max={740} />

#### 무방향 그래프 (Undirected Graph)

간선에 방향성이 없이 각 노드를 연결한다. <FigRef n={1} />의 G1을 식으로 나타내면 다음과 같다.

- `V(G1) = {0, 1, 2, 3, 4, 5}`
- `E(G1) = {(0,1), (0,2), (1,2), (2,3), (3,4), (3,5), (4,5)}`

간선에 방향성이 없으므로 (0, 1)과 (1, 0)은 같다. 즉 `(Vi, Vj) = (Vj, Vi)`이다.

#### 방향 그래프 (Digraph)

두 노드를 연결하는 간선에 방향이 있는 그래프이다. G2를 식으로 나타내면 다음과 같다.

- `V(G2) = {0, 1, 2, 3, 4, 5}`
- `E(G2) = {(0,1), (1,2), (2,1), (2,0), (2,3), (3,2), (3,4), (4,5), (5,3)}`

(1, 2)와 (2, 1)은 방향이 다르므로 다른 간선이다. 즉 `(Vi, Vj) ≠ (Vj, Vi)`이다. 방향 그래프는 모델링하려는 시스템의 구성 객체 사이의 연결 관계가 대칭적이지 않을 때 사용하고, 대칭적이라면 무방향 그래프로 나타낼 수 있다.

방향 그래프에서 간선의 시작점을 <strong>꼬리(Tail)</strong>, 종료점을 <strong>머리(Head)</strong>라 한다. 많이 헷갈리는 부분이니 주의하자.

#### 가중 그래프

간선에 가중치가 함께 있는 그래프이다. 가중치는 이동 비용(Cost), 거리(Distance) 등을 나타낼 수 있다. 가중 그래프는 무방향 또는 방향 그래프의 속성을 가질 수 있어 무방향 가중 그래프, 방향 가중 그래프라 부르며, 방향 가중 그래프를 <strong>네트워크</strong>라고도 한다.

## 3. 구조적 특징에 따른 종류

#### 완전 그래프 (Complete Graph)

그래프를 구성하는 모든 노드가 서로 1:1로 간선이 연결된 구조이다. 포화 이진 트리처럼 연결 가능한 최대의 간선을 가진 그래프이다. 노드의 개수를 n, 간선의 개수를 m이라 하면 다음과 같다.

- 무방향 그래프: `m = n(n-1) / 2`
- 방향 그래프: `m = n(n-1)`

방향 그래프는 두 노드 사이를 양방향으로 표현할 수 있으니 `n(n-1)`이고, 무방향은 두 노드의 관계가 하나의 간선으로 표현되므로 2로 나눈 것이라고 생각하면 된다. 노드가 6개라면 방향 완전 그래프는 간선이 30개, 무방향 완전 그래프는 15개이다.

#### 부분 그래프 (Sub Graph)

<strong>원래 그래프에서</strong> 일부 노드 및 간선을 제외하여 표현한 그래프이다. G의 부분 그래프 G'는 G의 노드 집합 V(G)와 간선 집합 E(G)의 부분집합으로 만들어진다.

- `G' = (V(G'), E(G'))`
- `V(G') ⊆ V(G)`, `E(G') ⊆ E(G)`

풀어서 말하면 부분 그래프의 노드 집합과 간선 집합은 각각 원래 그래프 G의 노드 집합과 간선 집합에 포함된다는 뜻이다.

예를 들어 G1에서 노드 0을 제외하고, 간선 (0,1), (0,2), (1,2), (3,4)를 제외하면 부분 그래프 G8이 된다.

- `V(G8) = {1, 2, 3, 4, 5} ⊆ V(G1) = {0, 1, 2, 3, 4, 5}`
- `E(G8) = {(2,3), (3,5), (4,5)} ⊆ E(G1)`

#### 다중 그래프 (Multi Graph)

두 노드 사이에 중복된 간선이 여러 개 있는 구조를 말한다.

## 4. 그래프 관련 용어

<Fig n={2} src="/img/notes/ds/graph-1/terms.png" caption="방향 그래프의 진입·진출 차수와 무방향 그래프의 경로" max={740} />

1. <strong>인접(Adjacent)</strong>: 두 노드를 연결하는 간선이 있으면 두 노드는 서로 인접했다고 한다. G1에서 노드 1과 2는 노드 0의 인접 노드이다.
2. <strong>부속(Incident)</strong>: 무방향 그래프에서 간선 (0, 1)은 노드 0과 1에 부속되었다고 한다. 노드 1의 관점에서는 부속된 간선이 (0, 1), (1, 2)이다.
3. <strong>차수(Degree)</strong>: 무방향 그래프에서 노드에 부속된 간선의 개수이다. G1에서 노드 1의 차수는 2이다(간선 (0, 1), (1, 2)).
   - 방향 그래프에서는 노드가 간선의 머리(Head) 쪽이면 <strong>진입차수(In-Degree)</strong>, 꼬리(Tail) 쪽이면 <strong>진출차수(Out-Degree)</strong>로 나눈다. G2의 노드 1은 0→1, 2→1이 들어오고 1→2가 나가므로 진입차수 2, 진출차수 1이다(<FigRef n={2} />).
4. <strong>경로(Path)</strong>: 두 노드 사이에서 인접한 노드를 순서대로 나열한 것이다. 상황에 따라 여러 경로가 생길 수 있다. G1의 노드 1에서 4까지는 1-2-3-4, 1-0-2-3-4, 1-2-3-5-4, 1-0-2-3-5-4 등의 경로가 있다.
   - 경로를 이루는 간선의 개수가 경로의 길이이다.
   - <strong>단순 경로(Simple Path)</strong>: 경로상에 중복되는 노드가 없는 경로. 방향 그래프에서는 단순 방향 경로(Simple Directed Path)라 부른다.
   - <strong>사이클(Cycle)</strong>: 시작 노드와 마지막 노드가 같은 경로
   - <strong>연결(Connected)</strong>: 그래프의 모든 노드 사이에 경로가 존재하는 경우. G1은 모든 노드 사이에 경로가 있으므로 연결 그래프이다.

#### 그래프의 동일성

얼핏 보면 다른 그래프처럼 보여도, 시각적 표현과 상관없이 V(G)와 E(G) 집합이 같으면 같은 그래프이다.

#### 루프

자기 자신으로 이어지는 간선을 루프(Loop)라 부르며, 노드 2의 루프는 간선 (2, 2)로 표현한다.

#### 노드와 간선의 추가/제거

간선을 추가/제거할 때는 간선의 양 끝에 부속된 노드 2개를 입력받는다. 간선은 노드 사이의 연결을 담당하므로 부속된 노드는 항상 2개이다. 무방향 그래프는 `(Vi, Vj) = (Vj, Vi)`이므로 방향을 신경 쓰지 않아도 되지만, 방향 그래프는 이를 구분해야 한다.

노드를 제거할 때는 그 노드에 부속된 모든 간선을 함께 제거해야 한다.

## 5. 그래프 구현 — 인접 행렬

그래프는 두 가지 방식으로 구현한다.

1. 인접 행렬(Adjacency Matrix) — 배열을 통한 구현
2. 인접 리스트(Adjacency List) — 연결 리스트를 통한 구현

#### 무방향 그래프의 인접 행렬

G1을 인접 행렬로 나타내면 다음과 같다. `GA[1][0]`과 `GA[0][1]`이 모두 1인 것은 간선 (0, 1)이 존재한다는 표시이고, 무방향이므로 두 칸 모두 1이 된다.

<div class="tbl">

| G1 | 0 | 1 | 2 | 3 | 4 | 5 | 계 |
|---|---|---|---|---|---|---|---|
| <strong>0</strong> | 0 | 1 | 1 | 0 | 0 | 0 | 2 |
| <strong>1</strong> | 1 | 0 | 1 | 0 | 0 | 0 | 2 |
| <strong>2</strong> | 1 | 1 | 0 | 1 | 0 | 0 | 3 |
| <strong>3</strong> | 0 | 0 | 1 | 0 | 1 | 1 | 3 |
| <strong>4</strong> | 0 | 0 | 0 | 1 | 0 | 1 | 2 |
| <strong>5</strong> | 0 | 0 | 0 | 1 | 1 | 0 | 2 |
| <strong>계</strong> | 2 | 2 | 3 | 3 | 2 | 2 | 14 |

</div>

인접 행렬에서 좌표 `[Row][Col]`의 방향은 Row → Col이다. 그래서 Row의 합계는 그 노드에서 출발하는 간선의 개수(Out-Degree), Col의 합계는 들어오는 간선의 개수(In-Degree)가 된다. 정리하면 다음과 같다.

1. 무방향 그래프의 인접 행렬은 `GA[i][j] = GA[j][i]`가 성립하므로 간선 하나가 두 칸에 표시된다.
2. 같은 이유로, 루프가 없다면 대각선을 기준으로 대칭 구조를 이룬다.
3. 일반적으로 Row 합은 Out-Degree, Col 합은 In-Degree인데, 무방향 그래프에서는 둘이 같으므로 어느 한쪽만 보면 그 노드의 차수가 된다.

#### 방향 그래프의 인접 행렬

방향 그래프는 간선에 방향이 있으므로 인접 행렬이 대칭이 아니다. 또한 Row 합(진출차수)과 Col 합(진입차수)이 다를 수 있으며, 둘을 더해야 그 노드에 부속된 간선의 개수가 된다. G2의 인접 행렬은 다음과 같다.

<div class="tbl">

| G2 | 0 | 1 | 2 | 3 | 4 | 5 | 계 (진출) |
|---|---|---|---|---|---|---|---|
| <strong>0</strong> | 0 | 1 | 0 | 0 | 0 | 0 | 1 |
| <strong>1</strong> | 0 | 0 | 1 | 0 | 0 | 0 | 1 |
| <strong>2</strong> | 1 | 1 | 0 | 1 | 0 | 0 | 3 |
| <strong>3</strong> | 0 | 0 | 1 | 0 | 1 | 0 | 2 |
| <strong>4</strong> | 0 | 0 | 0 | 0 | 0 | 1 | 1 |
| <strong>5</strong> | 0 | 0 | 0 | 1 | 0 | 0 | 1 |
| <strong>계 (진입)</strong> | 1 | 2 | 2 | 2 | 1 | 1 | 9 |

</div>

#### 방향 가중 그래프의 인접 행렬

방향 가중 그래프는 방향 그래프의 특성에 더해 각 간선에 가중치라는 수치가 포함된 그래프이다. 행렬에 0, 1로 유무를 표시하는 대신 가중치를 넣어 간선의 존재와 수치를 함께 나타낸다. 그래서 Row/Col의 합계도 간선의 개수가 아니라 가중치의 합이 된다. 차수를 구하고 싶다면 0이 아닌 칸의 개수를 세면 된다.

직접 구현한 코드에서는 간선 추가 시 무방향이면 두 칸을, 방향이면 한 칸만 채운다.

<Editor file="MyArrayGraph.cpp" fn="CMyArrayGraph::AddEdgeDir(...) / AddEdgeUndir(...)">

```cpp
bool CMyArrayGraph::AddEdgeDir(const int &iFromVertexID, const int &iToVertexID)
{
	if (m_ppAdjEdge[iFromVertexID][iToVertexID] >= USED)
		return false;

	m_ppAdjEdge[iFromVertexID][iToVertexID] = USED;
	return true;
}

bool CMyArrayGraph::AddEdgeUndir(const int &iFromVertexID, const int &iToVertexID)
{
	if (m_ppAdjEdge[iFromVertexID][iToVertexID] >= USED ||
		m_ppAdjEdge[iToVertexID][iFromVertexID] >= USED)
		return false;

	m_ppAdjEdge[iFromVertexID][iToVertexID] = USED;
	m_ppAdjEdge[iToVertexID][iFromVertexID] = USED;
	return true;
}
```

</Editor>

노드를 제거할 때는 부속된 간선을 함께 지운 뒤 노드를 사용하지 않음으로 표시한다.

<Editor file="MyArrayGraph.cpp" fn="CMyArrayGraph::RemoveVertex(...)">

```cpp
bool CMyArrayGraph::RemoveVertex(const int &iVertexID)
{
	if (!m_pVertex || !m_ppAdjEdge)
		return false;
	if (iVertexID < 0 || iVertexID >= m_iMaxVertexCount)
		return false;
	if(m_pVertex[iVertexID] <= UNUSED)
		return true;

	for (int iCol = 0; iCol < m_iMaxVertexCount; ++iCol)
	{
		if (m_ppAdjEdge[iVertexID][iCol] >= USED)
		{
			RemoveEdge(iVertexID, iCol);
			RemoveEdge(iCol, iVertexID);
		}
	}

	m_pVertex[iVertexID] = UNUSED;
	--m_iCurrentVertexCount;
	return true;
}
```

</Editor>

## 6. 인접 행렬의 메모리 사용

인접 행렬은 노드가 n개일 때 <strong>n² 크기의 메모리</strong>가 필요하다. 또한 간선의 유무와 상관없이 노드 개수에 따라 <strong>고정적인 메모리</strong>를 쓴다. 간선을 최소한으로 써도 최대로 쓴 것과 메모리 사용량이 같다는 것이다.

이런 이유로 노드 수에 비해 간선이 상대적으로 적은 그래프라면 인접 리스트를, 간선이 많은 그래프라면 인접 행렬을 쓰는 것이 바람직하다.
