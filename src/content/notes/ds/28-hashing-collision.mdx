## 1. 충돌과 군집화

일단 해싱 함수를 잘 선택해서 충돌 발생을 최소화해야 하지만, 그럼에도 충돌이 발생했다면 효율적으로 해결해야 한다.

- <strong>군집화(Clustering)</strong>: 해싱 함수에 따라 해시 테이블에 저장되는 자료들이 특정 주소들 주위로 뭉치는 현상

군집화는 충돌에 의해 나타나는데, 한 해시 테이블에서 군집화 현상이 많이 발생하면 <strong>검색 효율이 급감</strong>한다. 그래서 군집화를 최소화하도록 설계해야 한다. 충돌 해결 방법은 크게 두 가지이다.

1. <strong>개방 주소법</strong>: 충돌이 일어난 키 값을 다른 비어 있는 주소에 저장한다.
2. <strong>체이닝</strong>: 여러 개의 항목을 저장할 수 있도록 해시 테이블 구조를 변경한다.

## 2. 개방 주소법(Open Addressing)

조사법(Probing)이라고도 한다. 해싱 함수로 산출된 주소에 자료를 저장할 때 자료가 있으면 다음 주소, 또 있으면 그다음 주소를 조사하기를 반복한다. 하지만 모든 주소가 가득 차 있다면 자료를 저장할 수 없다. 개방 주소법은 선형 조사법, 제곱 조사법, 이중 해싱 등으로 나뉜다.

아래 세 방법을 같은 예제로 비교해 보자. 테이블 크기 5, 나머지 함수(`mod 5`)를 쓰고 키 1, 3, 8, 13을 차례로 저장한다. 1은 1, 3은 3에 저장되지만 8과 13은 모두 3으로 계산되어 충돌이 발생한다(<FigRef n={1} />).

<Fig n={1} src="/img/notes/ds/hashing-collision/probing.png" caption="선형 조사, 제곱 조사, 이중 해싱으로 같은 키를 저장한 결과" max={760} />

#### 선형 조사법(Linear Probing)

충돌이 발생했을 때 주소를 <strong>일정한 상수만큼 증가</strong>시켜 다시 조사하는 방법이다. `h(k) = (k + 조사 횟수) mod M`이므로 충돌할 때마다 `k → k+1 → k+2 → …` 순서로 조사한다.

가장 접근하기 쉬운 방법인 것 같다. 다만 충돌이 발생하는 주소 주위로 자료가 뭉치는 군집화 현상이 발생할 가능성이 높다.

예제에서 8은 4로 한 칸 이동하고, 13은 4까지 차 있으므로 다시 한 칸 더 이동한다. 더하고 배열의 크기로 mod를 해 주니 13은 0번으로 간다.

#### 제곱 조사법(Quadratic Probing)

충돌이 발생할 경우 주소를 <strong>조사 횟수의 제곱만큼 증가</strong>시켜 조사하는 방법이다. 1차 충돌이면 1, 2차 충돌이면 4(2×2), 3차 충돌이면 9(3×3), n차 충돌이면 n²만큼 이동한다.

예제에 적용하면 검색 키 8은 `(8 + 1×1) mod 5 = 4`가 되고, 검색 키 13은 1차 충돌 뒤 2차 충돌까지 이어져 `(13 + 2×2) mod 5 = 2`에 저장된다.

#### 이중 해싱(Double Hashing)

충돌이 발생할 경우 원래의 해싱 함수와는 다른 <strong>추가적인 해싱 함수</strong>로 주소를 증가시켜 조사하는 방법이다. 다양한 기법이 있지만 간단한 방법으로 <strong>조사 간격</strong>을 이용하는 방법이 있다.

조사 간격을 구하는 연산 `M - (k mod M)`에 주목하자. 처음 한 번 조사 간격을 정해 두고, `(충돌이 발생한 주소 + 조사 간격) mod M`을 충돌이 나지 않을 때까지 반복한다.

예제에서 8과 13의 조사 간격은 모두 `5 - 3 = 2`이다. 8은 `(3 + 2) mod 5 = 0`에 저장되고, 13은 0에서 다시 충돌해 `(0 + 2) mod 5 = 2`에 저장된다.

## 3. 구현

해시 테이블은 다음과 같은 구조로 구현했다.

1. 해싱 함수는 나머지 함수로 구현한다.
2. 키 값은 호너의 방법으로 정수로 변환한다. 자릿수마다 일정한 수를 곱하므로 오버플로를 조심해야 한다.
3. 충돌 해결은 선형 조사법으로 구현한다.

테이블은 크기, 현재 원소 개수, 원소 배열 포인터를 가지고, 각 원소(`HashElement`)는 검색 키, 저장 값, 버킷 상태(`EMPTY`, `USED`, `DELETED`)를 가진다.

#### 호너의 방법으로 문자열을 정수로

각 문자의 아스키 코드에 임의의 값을 곱하는데, 주의할 점은 항상 <strong>기존 값에 아스키 코드 값을 더한 뒤 임의 값을 곱하는</strong> 형식이라는 것이다. 그리고 <strong>마지막 문자는 곱하지 않고 더하기만</strong> 한다.

<Editor file="HashingArray.cpp" fn="CHashingArray::HonerHashFunc(...)">

```cpp
int CHashingArray::HonerHashFunc(const char *pKey_in)
{
	if (!pKey_in)
		return FAIL_NUM;

	int iSize = MyStrLength(pKey_in);

	const char *pSearch = pKey_in;
	int iHonersMethodResult(0);
	int i(0);
	for (; i < iSize-1; ++i)
	{
		iHonersMethodResult = (iHonersMethodResult + pSearch[i]) * HONER_NUM;
	}
	iHonersMethodResult += pSearch[i];

	return iHonersMethodResult;
}
```

</Editor>

이렇게 문자열을 정수로 변환하고 간단한 나머지 연산으로 index를 만드는데, 결과가 0보다 작은 음수라면 오버플로가 발생한 것이다. `unsigned int`를 써서 음수가 나오지 않게 하는 방법도 있겠다.

#### 선형 조사로 저장 위치 찾기

나머지 연산으로 구한 index에 자료를 저장하는데, 그 자리가 비어 있거나(`EMPTY`) 삭제된 상태(`DELETED`)라면 해당 index를 바로 반환하고, 사용 중이라면 다음 주소로 넘어간다. 그 전에 동일한 key 값의 자료가 이미 저장되어 있다면 실패를 반환한다. 또한 버킷 수만큼 순회했는데도 자리가 없다면 가득 찬 것이므로 실패를 반환한다.

가득 찼는지는 매번 순회해서 알아내기보다 `IsHashTableFull()` 같은 함수나 현재 원소 개수와 버킷 개수를 비교해 먼저 검사하는 편이 좋다. 그래서 `AddElement` 시작 부분에서 미리 체크하는 것이 올바른 것 같다.

<Editor file="HashingArray.cpp" fn="CHashingArray::LinearProbing(...)">

```cpp
int CHashingArray::LinearProbing(const int &iIndex_in, const char *pKey_in)
{
	int iSrc = iIndex_in;
	for (int i = 0; i < m_iBucketSize; ++i)
	{
		int iProbe = (iSrc + i) % m_iBucketSize;

		switch (m_pHashTable[iProbe].m_eState)
		{
		case HASHSTATE::EMPTY:
		case HASHSTATE::DELETED:
		{
			std::cout << '<' << iIndex_in << " => " << iProbe << " >\n";
			return iProbe;
		}
		break;
		case HASHSTATE::USED:
		{
			if (MyStrCmp(pKey_in, m_pHashTable[iProbe].m_pKey))
			{
				std::cout << "해당 주소에 같은 키값 존재, LinearProbing()\n";
				std::cout << "오류 Key: " << pKey_in << '\n';
				return FAIL_NUM;
			}
		}
		break;
		}
	}
	return FAIL_NUM;
}
```

</Editor>

## 4. 검색과 삭제 표시

<Fig n={2} src="/img/notes/ds/hashing-collision/deleted.png" caption="삭제된 자리를 만났을 때 검색을 이어가야 하는 이유" max={700} />

LinearProbing으로 자료를 검색하기 전에, 계산된 index가 비어 있다면(`EMPTY`) 실패한 경우이므로 바로 실패 처리를 한다. 그리고 해당 index에 동일한 key 값이 있다면 성공이다.

이 외에는 크게 2가지 케이스로 나눌 수 있다.

1. <strong>다른 키 값을 가지는 경우</strong>: 충돌이 일어나 다른 주소에 자료가 있다는 뜻이므로 다음 주소에 그 키 값을 가지는 자료가 있는지 확인해야 한다.
2. <strong>삭제된 경우</strong>: 저장할 때는 비어 있는 주소든 삭제된 주소든 저장해도 됐지만, 검색하는 입장에서 찾아간 주소의 상태가 "비어 있음"이 아니라 "자료가 있었다가 삭제됨"이라면, 충돌 때문에 다른 주소에 저장된 경우를 생각해야 한다(<FigRef n={2} />).

처음에는 2번 경우를 생각하지 못하고, LinearProbing 함수에 진입하기 전 `EMPTY`와 `DELETED` 상태 모두를 실패 처리했었다. 기억해 두자.

<Editor file="HashingArray.cpp" fn="CHashingArray::FindElement(...)">

```cpp
HashElement *CHashingArray::FindElement(const char *pKey_in)
{
	if (!pKey_in || m_iCurElementSize == 0)
		return nullptr;

	HashElement *pReturnElement = nullptr;

	int iHash = HonerHashFunc(pKey_in);
	int iIndex = DivideHashFunc(iHash);
	if (iIndex == FAIL_NUM)
		return nullptr;

	if (m_pHashTable[iIndex].m_eState == HASHSTATE::EMPTY)
		return nullptr;

	return FindByLinearProbing(iIndex, pKey_in);
}
```

</Editor>

## 5. 정리

- 개방 주소법은 충돌 시 테이블 안의 다른 빈 주소를 찾아 저장한다.
- 선형 조사는 +1, 제곱 조사는 +n², 이중 해싱은 키마다 다른 조사 간격으로 이동한다. 선형 조사는 군집화가 생기기 쉽다.
- 삭제는 `DELETED` 표시로 남겨 두고, 검색은 `DELETED`를 건너뛰며 계속 조사해야 한다.
