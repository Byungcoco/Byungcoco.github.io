## 1. 신장 트리 (Spanning Tree)

그래프 G가 노드 V와 간선 E의 집합으로 정의되어 있다는 걸 보았다. G = (V, E)

그래서 신장 트리란? 그래프 G에 대한 신장 트리는 G의 모든 노드 V를 포함하는 트리를 말한다. 여기서 신장이란 모든 노드를 포함한다는 의미다.

신장 트리는 <strong>트리의 일종</strong>으로 <strong>순환 구조가 없어야 한다</strong>는 제약에 주의하자. 그렇다는 건? 그래프가 가진 모든 노드를 순환이 이루어지지 않게 연결시킨 트리를 뜻한다. 그리고 그래프의 모든 간선을 사용하지 않아도 된다는 것이다.

<Fig n={1} src="/img/notes/ds/spanning-tree/spanning.png" caption="하나의 그래프에서 여러 신장 트리가 나온다 — 고른 간선에 따라 가중치 합이 다르다" max={740} />

하나의 그래프에서 노드를 연결하는 방법은 여러 가지이고, 순환 없이 모든 노드를 잇는 방법이라면 모두 신장 트리에 포함된다고 할 수 있다.

G의 노드 개수가 6개라면 간선은? 트리의 속성에 따라 n-1, 5개가 된다.

이러한 신장 트리는 마치 경로를 나타내는 것과 같은데, 그래프상의 모든 노드를 한 번씩 방문하는 탐색 방법인 DFS, BFS로 깊이 우선 신장 트리(DF Spanning Tree), 넓이 우선 신장 트리(BF Spanning Tree)를 구할 수 있다.

## 2. 최소 비용 신장 트리

전국의 모든 도시를 연결하는 인터넷망을 설계한다고 보자. 각 도시의 거리, 상황이 서로 달라 인터넷 선로 설치 비용에 차이가 생긴다. 어떤 도시는 강을 끼고 있고, 어떤 도시는 단순 평지라 싸게 깔 수 있고...

어떤 도시를 어떻게 서로 연결하느냐에 따라 비용이 달라진다. 어떻게 하면 적은 비용으로 연결할 수 있을까?

그림 1의 그래프는 간선에 가중치(Weight)가 존재하는 가중 그래프로, 각 가중치는 비용이라 할 수 있다. 오른쪽 두 신장 트리 아래에는 고른 간선의 가중치 총합을 적었다.

아! 신장 트리는 그래프의 노드를 연결하며 트리의 특성을 살려 순환 구조가 일어나지 않게 만들었었구나. 그렇다는 건 가중치 또한 똑같이 표현 가능하겠구나!

여기서 <strong>최소 비용 신장 트리</strong>는 가중 그래프의 신장 트리 중 가중치의 <strong>합이 최소</strong>인 신장 트리를 뜻한다. 이 최소 비용 신장 트리를 구하는 대표적인 방법이 Prim, Kruskal 알고리즘이다.

## 3. Kruskal 알고리즘

간선을 비용 순으로 정렬한 후 낮은 비용을 가지는 간선을 차례대로 선택 → 신장 트리 완성!

1. 초기화: 그래프 G의 모든 간선을 가중치 오름차순으로 정렬한다.
2. 정렬된 간선 중 가중치가 가장 작으면서 순환을 발생시키지 않는 간선을 추출한다. 순환을 발생시키는 간선은 제외한다.
3. 모든 노드가 연결될 때까지 2를 반복한다.

<Fig n={2} src="/img/notes/ds/spanning-tree/kruskal.png" caption="정렬된 간선을 차례로 꺼내며, 순환을 만드는 (0, 1)은 제외한다" max={680} />

정렬한 첫 번째 간선부터 추출을 시작한다. (2, 3)을 꺼내면 그 간선에 부속된 노드 2, 3도 함께 트리에 담아 둔다.

일련의 과정으로 (0, 2)까지 온 상황에서 (0, 1)은 제외한다. 0과 1은 이미 2를 통해 연결되어 있어서 순환이 발생하기 때문이다. 순환이 발생하는 간선은 아예 추가 처리를 하지 않는다. 왜? 트리는 순환 구조를 이루지 않으니까!

<Editor file="MyListGraph.cpp" fn="CMyListGraph::GetMinimalSpanningTreeByKruskal()">

```cpp
CMyListGraph *CMyListGraph::GetMinimalSpanningTreeByKruskal()
{
	if (!m_ppAdjEdge || !m_pVertex)
		return nullptr;

	CMyListGraph *pReturnGraph = new CMyListGraph;
	pReturnGraph->CreateListGraph(m_iMaxVertexCount, GRAPHTYPE::UNDIRECTED);
	for (int i = 0; i < m_iMaxVertexCount; ++i)
	{
		pReturnGraph->AddVertex(i);
	}

	CArrayHeap *pMinHeapTree = nullptr;
	HeapNode *pOutMinNode = nullptr;
	pMinHeapTree = OrderEdge();

	while (pReturnGraph->m_iCurEdgeCount != (m_iMaxVertexCount-1))
	{
		pOutMinNode = pMinHeapTree->DeleteNode();
		

		if (!CheckCycle(pReturnGraph->m_ppAdjEdge, pOutMinNode->m_iFromtVertexID, pOutMinNode->m_iToVertexID))
		{
			pReturnGraph->AddEdgeWithWeight(pOutMinNode->m_iKey, pOutMinNode->m_iFromtVertexID, pOutMinNode->m_iToVertexID);
		}

		delete pOutMinNode;
		pOutMinNode = nullptr;
	}

	delete pMinHeapTree;
	pMinHeapTree = nullptr;
	return pReturnGraph;
}
```

</Editor>

직접 구현한 코드를 보면 해당 그래프의 간선들을 기준으로 최소 힙 트리를 생성해 낸다. Delete를 통해 최솟값을 반환받아 Cycle을 검사하고, 순차적으로 만들어 둔 Vertex들에게 연결한다.

Kruskal의 경우 이처럼 트리에 순환이 발생하는 것을 막기 위해 <strong>Cycle을 검사하는 알고리즘이 추가로 필요</strong>하다. 새 간선 (u, v)를 넣었을 때 순환이 생기는 경우는, 지금까지 만든 트리에서 이미 u와 v가 경로로 이어져 있을 때다. 구현에서는 DFS를 활용해 자식 노드 우선 탐색을 하며, 끝까지 가기 전에 시작 노드와 같은 VertexID를 만나면 Cycle이 일어난다고 판단했다. 하지만 이는 간선마다 DFS를 돌리므로 O(E(V+E))로 비효율적인 검사라고 한다. <strong>Union-Find</strong>처럼 효율이 좋은 알고리즘이 있다니 시간 될 때 한번 보자.

## 4. Prim 알고리즘

Prim은 임의의 시작 노드를 지정하면, 해당 노드의 부속 간선 중 가중치가 작은 간선을 선택하여 연결한다. 그리고 노드가 늘어날수록 해당 노드들에 부속된 간선을 모두 체크해 본다. 이렇게 트리의 노드가 G의 노드와 같아질 때까지 반복한다.

1. 초기화: 시작 노드 r을 선택해 신장 트리 T를 초기화한다. V(T) = `{r}`, E(T) = 없음
2. V(T)에 부속된 모든 간선 중 가중치가 가장 작으면서 순환을 발생시키지 않는 간선 e를 골라, e와 e의 반대쪽 노드 w를 T에 추가한다.
3. G의 모든 노드가 V(T)에 포함될 때까지 2를 반복한다.

<Fig n={3} src="/img/notes/ds/spanning-tree/prim.png" caption="노드 1에서 시작한 Prim의 처음 세 단계" max={760} />

노드 1이 입력되고, 해당 노드와 인접한 간선 (1, 0), (1, 2) 중 가중치가 적은 (1, 2)를 선택한다. 다음으로 노드 1, 2에 부속된 간선 (1, 0), (2, 0), (2, 3) 중 가장 낮은 가중치 1을 가진 (2, 3)을 선택하게 된다.

이처럼 가장 낮은 가중치를 선택하는 건 맞지만, Prim 알고리즘은 특성상 순환을 따로 체크하지 않는다. 임의로 시작하는 노드에서 부속된 간선 중 낮은 가중치의 간선을 고르며, <strong>아직 추가하지 않은 Vertex로 향하는 간선</strong> 위주로 선택하기 때문이다. 정리하자면

1. Prim 알고리즘은 순환 체크를 하지 않아도 된다.
2. 노드들에 부속된 간선을 고르는 과정에서 트리에 없는 정점으로 나가는 최소 간선만 골라서 추가하기 때문이다.

간선을 선택해 가며 노드를 늘려 가는 방식이므로, 사이클이 일어나려면 이미 트리에 있는 Vertex끼리 간선이 연결되어야 하는데 그런 간선은 애초에 고르지 않는다.

```cpp
CMyListGraph *CMyListGraph::GetMinimalSpanningTreeByPrim(const int &iStartVertexID)
{
	if (!m_ppAdjEdge || !m_pVertex)
		return nullptr;

	CMyListGraph *pReturnGraph = new CMyListGraph;
	ListGraphNode *pGraphNode = nullptr;
	//LGNode *pSearchNode = nullptr;
	pReturnGraph->CreateListGraph(m_iMaxVertexCount, m_eType);
	pReturnGraph->AddVertex(iStartVertexID);

	

	while (pReturnGraph->m_iCurVertexCount != m_iCurVertexCount)
	{
		int iFrom(0);
		int iTo(0);
		int iWeight(999999);

		for (int i = 0; i < m_iMaxVertexCount; ++i)
		{
			LGNode *pSearchEdge = nullptr;
			if (pReturnGraph->m_pVertex[i] >= USED)
			{
				pSearchEdge = m_ppAdjEdge[i]->GetHeadNode()->m_pLink;
				for (; pSearchEdge; pSearchEdge = pSearchEdge->m_pLink)
				{
					if (iWeight > pSearchEdge->m_tData.m_iWeight)
					{
						// Prim 알고리즘에서는 CheckCycle을 하지않는다.
						//if (CheckCycle(pReturnGraph->m_ppAdjEdge, i, pSearchEdge->m_tData.m_iVertexID))
						//	continue;
						if (pReturnGraph->m_pVertex[pSearchEdge->m_tData.m_iVertexID] <= UNUSED)
						{
							iWeight = pSearchEdge->m_tData.m_iWeight;
							iTo = pSearchEdge->m_tData.m_iVertexID;
							iFrom = i;
						}
					}
				}
			}
		}

		pReturnGraph->AddVertex(iTo);
		pReturnGraph->AddEdgeWithWeight(iWeight, iFrom, iTo);
	}
	
	return pReturnGraph;
}
```
