## 1. 프로그램과 자료구조

컴퓨터 프로그램은 크게 두 가지 공통점을 가진다.

1. 컴퓨터에 의해서 실행되는 명령어들의 집합이다.
   - 예) 윈도우 탐색기 → 내부적으로 실행되는 명령어에 의해 파일의 복사, 이동, 삭제 기능 등이 제공된다.
2. 명령어를 수행하기 위해 내부적으로 여러 자료를 저장한다.
   - 예) 윈도우 탐색기 → 파일 및 폴더의 계층 구조 정보를 저장한다.

즉, 정상적으로 작동하는 하나의 프로그램은 <strong>데이터와 알고리즘</strong>으로 이루어진 구조이다.

#### 자료구조란?

컴퓨터에 자료를 효율적으로 저장하는 방식이다. 프로그램 실행 메모리를 절약하고 수행 시간을 최소화하는 기능을 수행한다.

컴퓨터 명령 자체의 효율성을 증가시키기 위한 절차를 알고리즘이라 한다. <strong>효율적인 알고리즘이 가능하려면 효율적인 자료구조가 선행</strong>되어야 한다.

프로그램을 잘 만들기 위해서는 목적 및 기능에 따라 해당하는 자료구조를 설계해야 한다. 그래서 다양한 프로그램의 목적과 기능에 적합한 자료구조가 각각 존재한다. 자료의 형태에 따른 자료구조의 분류 방법은 다음과 같다(<FigRef n={1} />).

1. <strong>단순구조</strong> — 정수, 실수, 문자, 문자열
   - 언어에서 제공하는 기본적인 데이터 타입으로, 자료구조는 아니다.
2. <strong>선형구조</strong> — 리스트, 스택, 큐, 덱
   - 단순구조를 활용하여 만들며, 자료들 사이의 앞뒤 관계가 1:1인 경우이다.
3. <strong>비선형구조</strong> — 트리, 그래프
   - 단순구조를 활용하여 만들며, 자료들 사이의 앞뒤 관계가 1:1이 아닌 계층구조 혹은 망구조이다(1:2, 2:1이 될 수 있음).
4. <strong>파일구조</strong>
   - 보조기억장치에 저장되는 파일에 대한 자료구조이다. 선형·비선형 구조는 컴퓨터 메모리상에 저장된다는 가정을 둔다.
   - 반면 파일구조는 메모리가 아닌 디스크에 저장된다는 가정에 기반하기 때문에, 메모리에 한 번에 올릴(Loading) 수 없는 대용량 자료들을 대상으로 한다.

## 2. 추상 자료형(ADT)

자료구조를 기술하는 데 추상 자료형(Abstract Data Type, ADT)이 필요한 일반적인 이유는 <strong>정보 은닉</strong>이다. 중요한 정보만 나타내고, 중요하지 않은 정보는 숨기는 것이다.

사용자의 관점에서 불필요한 정보를 제거하고, 필요한 것만 심플하게 제공하여 효율성을 높인다. 예를 들어 개발자 B가 개발자 A의 자료구조를 사용하기 위해 내부 구현 소스까지 알아야 한다면 비효율적이다. 그래서 바로 사용할 수 있도록 자료구조의 인터페이스를 제공한다.

1. 자료(Data) — 프로그램에서 처리되는 특정한 값
2. 연산(Operation) — 자료를 처리하기 위한 명령 혹은 연산

<strong>"자료형"은 이 둘을 합친 것</strong>이다. 자료와 자료형은 구분해야 한다. 정수 자료형은 정수형 데이터와 더하기, 빼기, 곱하기, 나누기, 나머지 연산이라는 기능 명령이 합쳐진 것이다.

#### 자료형의 추상이란?

1. 세부적이고 복잡한 것을 생략한다.
2. 대표적인 것, 중요한 것만 나타낸다.

사실을 있는 그대로 나타내기보다는 필요에 의해 핵심적인 내용만을 재해석하여 표현하는 것을 의미한다.

GPS 프로그램을 작성한다면, 저장해야 하는 Data는 지도에서의 위치 Data이며 x좌표와 y좌표로 구성된다. 연산은 다음과 같은 기능으로 이루어진다.

1. 위치 자료의 변경
2. 위치 자료 사이의 거리 계산
3. 두 개의 위치 자료 사이의 비교 연산

이렇게 지도에서의 위치를 나타내는 MyPosition은 자료와 연산으로 정의된 추상 자료형이다.

사용자는 각 기능의 이름, 입력, 출력, 설명만으로 자료형을 활용하며 세부적인 로직은 신경 쓰지 않아도 된다. 그 이유는 다음과 같다.

1. 기본적인 명령마다 이름, 입력, 출력, 설명이 표현되어 있고
2. 자료와 명령이 함께 전달되었기 때문이다.

즉, 추상 자료형은 명령마다 <strong>명령을 식별할 수 있는 이름, 명령을 호출하기 위해 필요한 입력, 호출 결과인 출력</strong>으로 구성된다.

사용자가 아닌 공급자 입장에서는 추상 자료형을 기반으로 자료구조의 세부 기능과 로직을 구현할 수 있기 때문에, 어떤 기능을 구현해야 할지 미리 설계할 수 있다. 이를 기반으로 자료구조의 인터페이스가 유지된다고 가정하면 개발자와 사용자 사이의 간섭 문제가 해결된다. 공급자의 소스 변경으로 인한 사용자 측의 소스 변경이 필요 없으므로 간섭이 발생하지 않는다.

추상 자료형이 외부에서 호출할 수 있는 일종의 인터페이스를 정의한 것이라면, <strong>자료구조는 인터페이스뿐만 아니라 모든 내부 변수 및 구현 연산을 포함</strong>한다.

추상 자료형이 필요한 이유를 정리하면 다음과 같다.

1. 자료구조의 핵심적인 내용을 간략하게 나타낸다.
2. 복잡한 내부 구현 부분을 감춘다.

실제 프로그램에 사용되는 복잡한 자료형을 구체적, 세부적으로 정의하면 상당히 어려울 뿐 아니라, 구현 내용이 변경될 때마다 자료형의 정의도 변경되어야 한다.

## 3. 알고리즘

컴퓨터에 의해서 실행되는 명령어들의 집합으로, 프로그램이 저장하는 다양한 자료를 이용하여 원하는 결과물을 만들어 내는 기능을 수행한다. 컴퓨터 공학적 측면에서는 <strong>어떠한 문제를 해결하기 위한 절차</strong>이다.

알고리즘은 주어진 문제를 반드시 해결해야 하므로, 다음 조건이 필요하다.

1. 입력: 외부에서 제공되는 자료가 0개 이상
2. 출력: 적어도 1개 이상의 결과를 만들어야 함
3. 명백성: 명령어는 의미가 모호하지 않고 명확해야 함
4. 유한성: 한정된 수의 단계 뒤에는 반드시 종료. 무한히 동작해서는 안 된다.
5. 유효성: 실행 가능한 연산이어야 함. 0으로 나누는 연산은 불가

#### 알고리즘을 표현하는 대표적인 4가지 방법

<div class="tbl">

| 방법 | 내용 | 특성 |
|---|---|---|
| 자연어 | 사람이 사용하는 일반적인 언어로 표현 | 기술하는 사람에 따라 일관성과 명확성이 달라지기 때문에 알고리즘 표현으로 부적절하고, 컴퓨터가 이해할 수 없다. |
| 순서도(Flow Chart) | 알고리즘을 그림으로 도식화해서 표현 | 알고리즘 단계를 직관적으로 표현할 수 있으나, 복잡한 알고리즘에서는 비효율적이다. |
| 의사코드(Pseudo Code) | 프로그래밍 언어가 아닌 가상의 언어로 표현 | 프로그래밍 언어보다 덜 엄격한 문법이지만 자연어보다 체계적으로 기술할 수 있다. 가상코드, 유사코드, 슈도코드라고도 불린다. |
| 프로그래밍 언어 | 특정 프로그래밍 언어로 표현 | 구체적인 소스로 나타내기 때문에 추가적인 구현 단계가 필요 없으나, 자세하고 엄격하게 기술해야 해서 비효율적인 경우가 있다. |

</div>

이런 특성 때문에 알고리즘 서적에서는 의사코드 혹은 순서도를 많이 사용한다. <strong>간단하다면 순서도, 복잡하다면 의사코드</strong>를 쓴다. 의사코드는 자연어와 프로그래밍 언어의 중간이라 어느 정도의 명백성과 체계적인 알고리즘 기술이 가능하기 때문이다.

#### 순서도

순서도에서는 처리와 판단 기호가 가장 빈번하게 사용된다(<FigRef n={2} />).

<Fig n={2} src="/img/notes/ds/overview/flowchart.png" caption="순서도에서 사용하는 기호" max={620} />

#### 의사코드

1. 지정문 — 변수에 특정 값을 대입하는 명령으로, 화살표 기호(`<-`)를 사용한다. `sum = sum + 10;`을 `sum <- sum + 10`으로 쓴다.
2. 조건문 — `if then else`, `else if`로 나타낸다.
3. 반복문 — `for`, `while`, `do while`로 나타낸다.

## 4. 알고리즘의 성능 분석

주어진 문제에 대해서 여러 개의 해법이 있기 때문에, 가장 효율적인 알고리즘을 선택하기 위해 성능 분석이 이뤄진다.

- 1부터 100까지 일일이 더하는 연산(100번의 덧셈 연산)
- vs `100 * (1 + 100) / 2`로 해결하는 연산(덧셈, 곱셈, 나눗셈 3번의 연산)

#### 공간 복잡도와 시간 복잡도

공간에 대한 비용과 시간에 대한 비용이다.

- 공간 복잡도는 알고리즘 실행에 얼마만큼의 저장 공간(메모리 혹은 디스크)이 필요한지 나타낸다.
- 시간 복잡도는 알고리즘 실행에 얼마만큼의 시간이 걸리는지 나타낸다.

공간 복잡도보다 시간 복잡도가 더 중요한 평가 기준이어서, 대부분 시간 복잡도를 대상으로 분석한다.

#### 시간 복잡도의 빅-O 표기법

n에 대해 가장 큰 영향력을 주는 항만 표시하는 것이 일반적이며, 계수를 생략하여 표시한다. 그래서 상수의 경우 `O(1)`이 된다.

<div class="tbl">

| 표기 | 이름 |
|---|---|
| `O(1)` | 상수 |
| `O(log n)` | 로그 |
| `O(n)` | 1차, 선형 |
| `O(n log n)` | 선형 로그 |
| `O(n²)` | 2차 |
| `O(n³)` | 3차 |
| `O(2ⁿ)` | 지수 |
| `O(n!)` | 계승 |

</div>
