## 1. 최단 경로

최단 경로란? 두 노드 사이의 경로 중 최소 비용으로 이동할 수 있는 경로를 찾는 문제이다. 앞서 두 노드 사이의 간선을 통해 인접한 노드들을 나열하며 경로라는 것을 알게 되었다. 여기서 최단 경로를 표현해 내려면 각 간선에 비용에 해당하는 가중치가 부여되어야 하므로, 가중 그래프를 대상으로 구하게 된다.

1. 단일 시작점에서 최단 경로 구하기 — 특정 노드에서 모든 노드까지의 최단 경로 구하기
2. 모든 최단 경로 구하기 — 그래프상의 모든 노드에서 모든 노드를 대상으로 한 최단 경로 구하기
3. 도달 가능성 구하기 — 방향 그래프 기준, 특정 노드에서 다른 노드 사이에 경로가 존재하는지 판단

노드 r에서 s까지의 경로를 나타내면, 간선으로 인접한 노드들의 순서를 리스트로 나열한다.

- 간선으로 나타내면: (r, v1) → (v1, v2) → … → (vn, s)
- 여기서 중복을 없애면: r → v1 → v2 → … → vn → s

## 2. 다익스트라(Dijkstra) 알고리즘의 아이디어

단일 시작점에서 최단 경로를 구하는 알고리즘이다. 모델링하는 시스템에 따라 노드 사이의 거리가 음수인 경우가 있는데, 이 경우는 다익스트라로 최단 경로를 구할 수 없다.

<Fig n={1} src="/img/notes/ds/dijkstra/relax.png" caption="v까지의 최단 거리를 알 때, v를 거쳐 w로 가는 길이 더 짧으면 w의 거리를 고친다" max={640} />

시작 노드부터 v까지의 최단 경로는 알고 있다고 가정하자. 그다음은 w까지의 최단 경로를 구하고 싶은 상황이다.

- 시작 노드에서 최단 거리인 v 노드까지의 거리 y<sub>v</sub>
- 시작 노드에서 w 노드까지의 (지금까지의) 거리 y<sub>w</sub>
- v 노드에서 w 노드까지의 거리 c<sub>vw</sub>

정리하자면, 시작 노드에서 최단 거리인 v 노드를 알고 있는 상태에서 w 노드의 최단 거리를 구하려 할 때, 아직은 y<sub>w</sub>(최단 거리)를 알지 못하는 상태이다. 이때 v에서 w로 연결한 새로운 경로가 더 짧다면 w의 경로를 다음과 같이 수정한다.

> y<sub>w</sub> = y<sub>v</sub> + c<sub>vw</sub>,  if y<sub>v</sub> + c<sub>vw</sub> &lt; y<sub>w</sub>

<Fig n={2} src="/img/notes/ds/dijkstra/relax-example.png" caption="0 → 2 직행(4) 대신 0 → 1 → 2(3)로 거리를 수정한다" max={520} />

시작 노드 0에서 1까지의 최단 경로를 알고 있는 상태(y<sub>1</sub> = 1)에서, 2를 목적지로 한 간선 하나로는 y<sub>2</sub> = 4라는 결과를 낸다. 그런데 기존 최단 경로 y<sub>1</sub> = 1에 c<sub>12</sub> = 2가 있으므로, 기존 y<sub>2</sub>를 y<sub>1</sub> + c<sub>12</sub>로 변경하여 새로운 최단 거리를 도출해 낸다.

이렇게 되면 비용이 3으로 단축되어, 경유하는 노드와 간선은 증가하지만 최종적인 비용 측면에서 가장 적은 경로라 할 수 있다.

## 3. 진행 과정

알고리즘을 단계로 정리하면 다음과 같다.

1. 초기화: 집합 S에 모든 노드를 넣는다. 시작 노드 r에서 다른 노드 w까지의 거리 y<sub>w</sub>를 초기화하는데, r과 직접 연결되지 않은 노드의 거리는 모두 ∞(무한히 큰 수)로 둔다.
2. 집합 S에서 최단 거리를 가진 노드 v를 찾아 S에서 제거하고, v에 인접한 노드 w(S에 남아 있는 노드)에 대해 위의 경로 수정을 실시한다.
3. 집합 S에서 모든 노드가 제거될 때까지 2를 반복한다.

아래 그래프(그림 3)에서 시작 노드 0으로 진행해 보면, 각 루프에서 제거되는 노드와 거리 y는 다음과 같이 바뀐다.

<div class="tbl">

| 루프 | 제거한 노드 | y1 | y2 | y3 | y4 | y5 |
|---|---|---|---|---|---|---|
| 초기화 | 0 | 1 | 4 | ∞ | ∞ | ∞ |
| 1 | 1 | 1 | <strong>3</strong> | ∞ | ∞ | ∞ |
| 2 | 2 | 1 | 3 | <strong>4</strong> | ∞ | ∞ |
| 3 | 3 | 1 | 3 | 4 | <strong>12</strong> | <strong>7</strong> |
| 4 | 5 | 1 | 3 | 4 | <strong>11</strong> | 7 |
| 5 | 4 | 1 | 3 | 4 | 11 | 7 |

</div>

- 초기화: 0과 인접한 노드 1, 2를 제외한 모든 노드의 거리를 무한대로 표시한다. 그리고 집합 S에서 최단 거리를 가진 노드는 1이므로 1을 제거한다.
- 1을 제거한 후 노드 2의 거리를 계산한다. c<sub>12</sub>는 2이므로 y<sub>1</sub> + c<sub>12</sub> = 3이 기존 4보다 작아 3으로 수정된다. 집합 S에 노드가 아직 남아 있으므로 계속 진행한다.
- 이제 집합 S에서 가장 짧은 거리를 가지는 노드는 2이다. 2를 제거하고 인접 노드를 검사한다. y<sub>2</sub>는 3, c<sub>23</sub>은 1이고, 시작 노드 0과 3은 연결되어 있지 않으므로 기존 값은 무수히 큰 수이다. 따라서 y<sub>3</sub> = 4.
- 다음 최단 거리 노드는 3이다. 1, 2는 이미 집합 S에서 사라졌기 때문이다. 3을 제거하며 인접한 노드를 검사한다.

여기서 중요한 것이, 알고리즘 흐름상 시작 노드에서 직접 연결되지 않은 노드는 모두 무한대로 표시된다는 점이다. y<sub>4</sub>, y<sub>5</sub>는 무한대였기 때문에 3에서 인접한 노드를 검사하면

- y<sub>3</sub> + c<sub>34</sub> = 4 + 8 = 12 &lt; ∞ 이니 y<sub>4</sub> 갱신
- y<sub>3</sub> + c<sub>35</sub> = 4 + 3 = 7 &lt; ∞ 이니 y<sub>5</sub> 갱신

이렇게 두 개의 단축 거리가 생기는데, 이 중 작은 거리 7을 가진 노드 5를 제거하며 검사를 실시한다. y<sub>4</sub>는 12였고, 노드 5를 거쳐 다시 계산하면 y<sub>5</sub> + c<sub>54</sub> = 7 + 4 = 11 &lt; 12 이므로 11로 갱신된다. 마지막으로 남은 노드 4를 제거하는데, 집합에 4와 연결된 노드가 남아 있지 않으므로 제거와 동시에 알고리즘이 종료된다.

## 4. 경로 복원

각 노드의 최단 거리는 알겠는데, 다 제거하고 나면 어떤 경로가 구해진 것인지 와닿지 않는다. 그래서 최단 거리와 함께 <strong>이전 연결 노드</strong> 정보를 담아 둔다.

<Fig n={3} src="/img/notes/ds/dijkstra/result.png" caption="최단 거리(y)와 최단 경로 트리 — 4에서 이전 연결 노드를 따라가면 0에 도착한다" max={700} />

<div class="tbl">

| 도착 노드 | 거리 y | 이전 연결 노드 |
|---|---|---|
| 1 | 1 | 0 |
| 2 | 3 | 1 |
| 3 | 4 | 2 |
| 4 | 11 | 5 |
| 5 | 7 | 3 |

</div>

이게 무슨 말이냐? 각 단계의 최단 경로 노드 v에 의해 w의 거리가 변경되면, 해당 v가 w의 이전 노드가 된다. 위에서 최단 거리를 가진 노드 v를 제거하며, 인접한 노드를 통해 무한대였던 w의 거리를 갱신했던 과정을 기억해 내자.

그래서 뭐? 만약 도착 노드 4에 대한 경로를 구한다고 치자. 4의 이전 연결 노드는 5, 5의 이전 연결 노드는 3, 3의 이전 연결 노드는 2, 2의 이전 연결 노드는 1, 1의 이전 연결 노드는 0이므로 4 ← 5 ← 3 ← 2 ← 1 ← 0이 된다.

다익스트라 알고리즘의 시간 복잡도는 O(n²)이 된다. (n-1)번의 루프가 진행되는 동안 내부적으로 최단 거리 노드 탐색과 거리 갱신에 2n에 해당하는 루프가 돌기 때문이다.

{
	// ... 코드 중략
	pSearchNode = nullptr;

	for (int i = 0; i < m_iMaxVertexCount-1; ++i)
	{
		// 삭제하지 않은 노드 중 적은 비용의 간선을 소유하고있는 VertexID 리턴
		iCheckVertexID = GetMinDistance(pReturnArray, pCheckArray);
		if (iCheckVertexID < 0)
			break;
		pCheckArray[iCheckVertexID] = DELETE;

		// pSearchNode는 최소 간선을 부속하고있는 노드의 부속간선 리스트
		if (pSearchNode = m_ppAdjEdge[iCheckVertexID]->GetHeadNode()->m_pLink)
		{
			for (; pSearchNode; pSearchNode = pSearchNode->m_pLink)
			{
				// 간선 중 삭제된 곳을 Head로 두고있는 간선은 건너뜀
				if (pCheckArray[pSearchNode->m_tData.m_iVertexID] <= DELETE)
					continue;

				// 삭제된 곳이 아니라면 경로 갱신 가능한 노드들
				// Yv+ Cvw < Yw
				int iYv = pReturnArray[iCheckVertexID];
				int iYw = pReturnArray[pSearchNode->m_tData.m_iVertexID];
				int Cvw = pSearchNode->m_tData.m_iWeight;

				if (iYv + Cvw < iYw)
				{
					pReturnArray[pSearchNode->m_tData.m_iVertexID] = iYv + Cvw;
				}
				else
				{
					pReturnArray[pSearchNode->m_tData.m_iVertexID] = iYw;
				}
				pPrevNodeArray[pSearchNode->m_tData.m_iVertexID] = iCheckVertexID;
			}
		}
	}

	return pReturnArray;
}

int CMyListGraph::GetMinDistance(const int *const &pReturnArray, int *pCheckArray_in)
{
	int iValue(99999);
	int iIndex(-1);
	for (int i = 0; i < m_iMaxVertexCount; ++i)
	{
		if (pCheckArray_in[i] <= DELETE)
			continue;

		if (iValue > pReturnArray[i])
		{
			iValue = pReturnArray[i];
			iIndex = i;
		}
	}
	return iIndex;
}
