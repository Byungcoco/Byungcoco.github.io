## 1. 배열을 이용한 이진 트리 구현

배열로 이진 트리를 구현하면 <strong>노드의 번호가 인덱스 역할</strong>을 한다. <FigRef n={1} />은 노드가 13개인 완전 이진 트리이다. 루트 노드가 1번이고, 레벨별로 왼쪽에서 오른쪽으로 번호가 부여되는 규칙을 가진다.

이때 계산의 편의를 위해 배열의 0번은 건너뛰고 1번부터 채운다. 예제라서가 아니라 원래 0번을 사용하지 않는다. 또한 완전 이진 트리 구조를 유지하며 노드의 추가/제거가 이루어질 수 있으므로, `n = 2ʰ - 1`을 담을 수 있는 크기로 배열을 잡아 둔다. 높이가 4라면 인덱스를 1번부터 쓰므로 `2⁴ - 1 = 15`번 인덱스까지, 실제 배열 크기는 16이 된다.

이 규칙성 덕분에 부모-자식 노드 사이의 인덱스를 구하는 공식이 생긴다.

1. 노드 i의 부모 노드 인덱스 = `i / 2` (단, `i > 1`)
2. 노드 i의 왼쪽 자식 노드 인덱스 = `2 × i`
3. 노드 i의 오른쪽 자식 노드 인덱스 = `2 × i + 1`

1번의 `i / 2`는 정수 나눗셈이다. `i > 1`인 이유는 결과가 0이 나오는 것도 있지만, 논리적으로 루트 노드에는 부모 노드가 없기 때문이다.

<Fig n={1} src="/img/notes/ds/tree-2/array.png" caption="노드 번호가 곧 배열 인덱스 — 부모·자식을 계산으로 찾는다" max={740} />

배열의 특성인 인덱스 임의 접근으로 공식을 활용해 빠르게 접근할 수 있지만, 완전 이진 트리 형태를 전제로 공간을 잡기 때문에 <strong>빈 공간의 낭비가 심하다</strong>는 단점이 있다. 자식 노드가 늘어나고 담는 데이터 크기가 커질수록 낭비는 더욱 심해진다.

이 낭비를 줄이기 위해 포인터를 활용하면 공간 낭비는 줄어들지만, 메모리 관리 측면에서 구현 난이도가 올라가고 노드 간 탐색이 까다로워 탐색 비용이 증가한다.

## 3. 이진 트리의 순회

이진 트리의 노드 추가/제거를 구현했더라도, 순회하지 않으면 출력해서 눈으로 확인하기 어렵다. 선형 자료구조와 달리 트리는 계층 구조를 가지므로 순회 알고리즘에 따라 여러 순회 방법이 가능하다.

- V: 현재 노드 방문
- L: 왼쪽 "서브트리"로 이동
- R: 오른쪽 "서브트리"로 이동

이 세 가지 구성 요소를 어떤 순서로 쓰느냐에 따라 순회 방법이 나뉜다.

- 전위 순회: V → L → R (현재 노드 방문 → 왼쪽 서브트리 이동 → 오른쪽 서브트리 이동)
- 중위 순회: L → V → R (왼쪽 서브트리 이동 → 현재 노드 방문 → 오른쪽 서브트리 이동)
- 후위 순회: L → R → V (왼쪽 서브트리 이동 → 오른쪽 서브트리 이동 → 현재 노드 방문)

이처럼 <strong>"현재 노드 방문"이 언제 이루어지느냐</strong>에 따라 전위, 중위, 후위로 나뉜다. 이 외에 <strong>레벨 순회</strong>도 있다. 레벨 1인 루트 노드에서 시작해 레벨 2, 3 순서로 해당 레벨의 노드를 전부 방문하며, 같은 레벨에서는 왼쪽부터 오른쪽으로 탐색한다.

<Fig n={3} src="/img/notes/ds/tree-2/traversal.png" caption="같은 트리에 대한 네 가지 순회 결과" max={740} />

#### 전위 순회

현재 노드 방문을 우선으로 V → L → R 순서를 가진다. 여기서 <strong>방문</strong>이란 현재 노드의 자료를 처리한다는 의미이다. 이진 트리를 출력하는 것이 목적이라면 현재 노드 방문에서 노드 내용을 출력한다. 반면 왼쪽/오른쪽 서브트리 이동은 해당 서브트리의 루트 노드로 <strong>이동</strong>하는 것을 의미한다. 전위 순회는 현재 노드를 <strong>방문</strong>한 뒤에 왼쪽 서브트리로 <strong>이동</strong>한다. 이 둘을 구별해야 한다.

<FigRef n={3} />의 트리를 전위 순회하면 다음과 같다.

1. 루트 A를 방문하고, B를 루트로 하는 왼쪽 서브트리로 이동
2. B를 현재 노드로 방문하고, D를 루트로 하는 왼쪽 서브트리로 이동
3. D를 방문하고, H를 루트로 하는 왼쪽 서브트리로 이동
4. 단말 노드 H를 방문하고, D 기준 오른쪽 서브트리로 이동
5. 단말 노드 I를 방문하면 B 기준 왼쪽 서브트리 순회가 끝나므로 오른쪽 서브트리로 이동
6. E를 방문하고, J를 루트로 하는 왼쪽 서브트리로 이동
7. 단말 노드 J를 방문. E의 오른쪽 서브트리는 없으므로 B 기준 오른쪽 서브트리 순회 완료
8. B의 모든 후손을 순회했으니 A의 왼쪽 서브트리 순회가 끝났다. C를 루트로 하는 오른쪽 서브트리로 이동 → …

즉, 현재 노드(V)를 방문한 뒤 왼쪽 자식이 있다면 항상 왼쪽 자식으로의 이동이 우선이다. 왼쪽으로 갈 수 없을 때 비로소 오른쪽 자식으로 이동한다.

#### 중위 순회

왼쪽 서브트리 이동이 우선이므로 A 방문보다 B로의 이동이 먼저 진행된다.

1. B를 방문하기 전, D를 루트로 하는 왼쪽 서브트리가 있으므로 이동
2. D를 방문하기 전, H를 루트로 하는 왼쪽 서브트리가 있으므로 이동
3. 단말 노드 H를 방문하면 D의 왼쪽 서브트리 순회 완료
4. D를 방문하고 I를 루트로 하는 오른쪽 서브트리로 이동
5. 단말 노드 I를 방문하면 D를 루트로 하는 서브트리, 즉 B의 왼쪽 서브트리 순회 완료
6. B를 방문하고 E를 루트로 하는 오른쪽 서브트리로 이동
7. E를 방문하기 전, J를 루트로 하는 왼쪽 서브트리가 있으므로 이동
8. 단말 노드 J를 방문하면 E의 왼쪽 서브트리 순회 완료
9. E를 방문하면 A의 왼쪽 서브트리 순회 완료
10. A를 방문하고 C를 루트로 하는 오른쪽 서브트리로 이동
11. C를 방문하기 전, F를 루트로 하는 왼쪽 서브트리로 이동 → …

패턴을 보면 왼쪽 자식이 더 이상 없을 때까지 계속 이동한다. 처음 방문이 이루어지는 노드가 가장 왼쪽의 단말 노드 H라는 점에서 알 수 있다.

#### 후위 순회

1. 루트 A 기준, B를 루트로 하는 왼쪽 서브트리로 이동
2. D를 루트로 하는 왼쪽 서브트리로, 이어서 H를 루트로 하는 왼쪽 서브트리로 이동
3. 단말 노드 H를 방문하고, 부모 D 기준 오른쪽 서브트리의 루트 I로 이동
4. 단말 노드 I를 방문하고 나서야 D를 방문. B 기준 왼쪽 서브트리 순회 완료
5. B를 방문하기 전 오른쪽 서브트리 E로 이동하고, J를 루트로 하는 왼쪽 서브트리로 이동
6. 단말 노드 J를 방문. E의 오른쪽 서브트리가 없으므로 E를 방문
7. B의 왼쪽·오른쪽 서브트리 순회가 끝났으므로 B를 방문
8. A의 왼쪽 서브트리 순회가 끝났으니, A를 방문하기 전 C를 루트로 하는 서브트리로 이동 → …

#### 레벨 순회

레벨 순회는 낮은 레벨에서 높은 레벨로, 가장 낮은 레벨인 루트부터 이어지며 항상 왼쪽이 우선이다.

- 레벨 1: A
- 레벨 2: B → C
- 레벨 3: D → E → F → G
- 레벨 4: H → I → J → K → L → M

전위·중위·후위처럼 후손으로 파고드는 구조와 다르게, 같은 레벨의 노드를 차례로 방문하는 구조라서 순회 순서를 도출하기가 직관적이다.

## 4. 재귀 호출로 구현

세 순회 모두 "현재 노드 출력" 한 줄의 위치만 다르다.

<Editor file="PointerBinaryTree.cpp" fn="PointerBinaryTree::Recursive...Traversal(...)">

```cpp
void PointerBinaryTree::RecursivePreorderTraversal(PBTNode *pNode_in)
{
	if (!pNode_in)
		return;

	std::cout << pNode_in->_cData << '\n';
	RecursivePreorderTraversal(pNode_in->_pLeftChild);
	RecursivePreorderTraversal(pNode_in->_pRightChild);
}

void PointerBinaryTree::RecursiveInorderTraversal(PBTNode *pNode_in)
{
	if (!pNode_in)
	{
		return;
	}

	RecursiveInorderTraversal(pNode_in->_pLeftChild);
	std::cout << pNode_in->_cData << '\n';
	RecursiveInorderTraversal(pNode_in->_pRightChild);
}

void PointerBinaryTree::RecursivePostorderTraversal(PBTNode *pNode_in)
{
	if (!pNode_in)
		return;

	RecursivePostorderTraversal(pNode_in->_pLeftChild);
	RecursivePostorderTraversal(pNode_in->_pRightChild);
	std::cout << pNode_in->_cData << '\n';
}
```

## 5. 반복으로 구현하기 위한 준비

반복으로 구현할 때는 앞서 만든 연결 리스트 큐와 연결 리스트 스택을 활용할 예정이고, 노드 데이터에 방문 여부를 나타내는 bool 값(`_bVistsed`)을 추가했다.

<Editor file="PointerBinaryTree.h" fn="struct PointerBinaryTreeNode">

```cpp
typedef struct PointerBinaryTreeNode
{
	char _cData = 0;
	bool _bVistsed = false;

	PointerBinaryTreeNode *_pLeftChild = nullptr;
	PointerBinaryTreeNode *_pRightChild = nullptr;

	friend bool operator ==(const PointerBinaryTreeNode &tNode1, const PointerBinaryTreeNode &tNode2)
	{
		return tNode1._cData == tNode2._cData;
	}

	friend bool operator !=(const PointerBinaryTreeNode &tNode1, const PointerBinaryTreeNode &tNode2)
	{
		return !(tNode1._cData == tNode2._cData);
	}
} PBTNode;
```

</Editor>
