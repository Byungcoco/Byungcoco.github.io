## 1. 스택의 개념

선형 자료구조의 하나인 스택은 자료를 쌓아 두는 기능을 수행한다. <strong>Last In First Out(LIFO)</strong>, 가장 나중에 들어간 자료가 가장 먼저 나온다.

선형 자료구조이므로 앞뒤 자료가 1:1 관계이다. 즉, 순차적으로 꺼내야만 처음에 넣었던 자료를 마지막에 꺼낼 수 있다.

스택의 끝은 가장 처음이 아닌 마지막, 삽입과 반환이 이루어지는 가장 높은 곳을 말한다. 리스트에서는 자료의 추가와 삭제가 모든 위치에서 가능했던 반면, 스택은 스택의 끝에서만 가능하다.

수식을 해석하고 계산할 때, 복잡한 미로에서 길을 찾는 알고리즘, 트리나 그래프 같은 복잡한 자료구조의 내부 구현에서도 사용하는 <strong>중요한 자료구조</strong>이다.

## 2. 스택의 연산

<Fig n={1} src="/img/notes/ds/stack/pushpop.png" caption="Push · Pop · Peek" max={720} />

- <strong>Push</strong>: 새로운 자료를 스택에 저장한다.
- <strong>Pop</strong>: 스택에서 자료를 꺼낸다.
- <strong>Peek</strong>: Pop과 달리 자료를 제거하지 않고 해당 자료에 접근만 한다.

스택은 크기를 가지며 새로운 자료가 추가될 때마다 순차적으로 채워 나간다. 크기를 넘어서게 되면 <strong>오버플로우</strong>가 발생한다.

스택의 꼭대기를 가리키는 이름이 <strong>Top</strong>이다. 연결 리스트의 헤드 포인터처럼, 새로운 데이터가 추가될 때마다 Top을 갱신해야 한다.

Pop은 Push와 달리 데이터를 꺼내는데, 이 과정에는 순서가 있다. 먼저 스택에서 자료를 제거하고, 제거한 자료를 전달한다는 점에 주의해야 한다. 또한 아무것도 저장되지 않은 상태를 Empty라 하며, 공백 상태에서 Pop이 호출되면 <strong>언더플로우</strong>가 발생했다고 한다.

Peek는 최상위 자료를 반환한다는 점에서 Pop과 비슷하지만, 자료를 '제거'하지 않고 '반환'만 한다.

## 3. 연결 리스트 스택

일반 연결 리스트를 그대로 써서 스택을 구현하면 비효율적이다. 리스트는 `_pLink`로 선형을 유지하며 뒤로 확장해 나가는 구조라서, Top이 `_iTotalElement - 1`번째 노드가 된다. 즉, Top에 접근하려면 매번 순회가 이루어져야 한다.

그래서 리스트의 시작을 가리키던 헤더 노드의 링크가 <strong>스택의 꼭대기</strong>를 가리키도록 바꾸면 문제가 쉽게 해결된다. 대신 스택이 쌓일 때마다 Top 노드에 대한 포인터를 갱신해야 한다.

일반 리스트에서는 자료가 추가될 때마다 헤더 노드에서부터 순서대로 이어 붙였다면, 스택은 LIFO 성질에 따라 <strong>가장 먼저 추가한 자료가 가장 마지막에 가 있는 역순 구조</strong>를 띤다(<FigRef n={2} />).

```cpp
bool LinkedListStack::Push(const ListStackNode &List_in)
{
	if (!_pHead)
		return false;
	ListStackNode *pNewNode = new ListStackNode(List_in);
	pNewNode->_pLink = nullptr;

	if (_iElementCount == 0)
	{
		_pHead->_pLink = pNewNode;
		IncreaseDataCount();
		return true;
	}

	ListStackNode *pPrevNode = _pHead->_pLink;
	_pHead->_pLink = pNewNode;
	pNewNode->_pLink = pPrevNode;
	IncreaseDataCount();
	return true;
}
```

</Editor>

Pop은 반환할 노드를 동적 할당하여 리턴하기 때문에, 메모리 해제 책임은 호출자에게 있다. 그래서 반환 노드의 `_pLink`를 nullptr로 끊어 줘야 한다. 또한 기존 노드의 값을 반환 노드에 복사한 뒤 기존 노드는 삭제한다.

<Editor file="LinkedListStack.cpp" fn="LinkedListStack::Pop()">

```cpp
ListStackNode *LinkedListStack::Pop()
{
	if(isEmpty() || !_pHead)
		return nullptr;

 	ListStackNode *pReturnNode = new ListStackNode;
	ListStackNode *pLastNode = GetTopNode();
	*pReturnNode = *pLastNode;
	pReturnNode->_pLink = nullptr;

	if(_iElementCount <= 1)
		_pHead->_pLink = nullptr;
	else
		_pHead->_pLink = GetTopNode()->_pLink;

	delete pLastNode;
	DecreaseDataCount();
	return pReturnNode;
}
```

</Editor>

Peek는 Top 노드를 복사해서 전달하거나 포인터로 넘겨 준다.

이런 특성 때문에 스택은 연결 리스트보다 다소 구현이 간단하다. Top에서만 자료를 추가/삭제하고 접근할 수 있다는 제약 때문에 연산의 자유도가 리스트보다 낮기 때문이다.

## 4. 스택 응용

#### 역순 문자열

스택은 후입선출이기 때문에 A, B, C를 넣고 차례로 Pop하면 역순으로 출력된다.

문자열을 입력받으면 `strlen`으로 문자의 개수를 파악한다. 이때 문자열의 끝을 나타내는 `'\0'`은 개수에 포함되지 않는다는 점에 유의해야 한다. 이번 구현에서는 문자열을 새로 만들어 반환하지 않고 스택에 바로 넣어 출력했다. 만약 문자열을 반환해야 한다면 `'\0'`의 존재 유무를 잘 챙겨야 한다.

#### 괄호 검사

수식의 괄호가 올바르게 짝지어져 있는지 오류를 검출하는 데 응용할 수 있다. 여는 괄호는 스택에 넣어 두고, 닫는 괄호를 만날 때마다 하나씩 Pop하여 검사한다.

- Pop할 노드가 없다면 닫는 괄호가 여는 괄호보다 많은 상황이다. 예) `(A + B) * C)`
- 검사가 끝났는데 스택에 노드가 남아 있다면 여는 괄호가 많은 상황이다. 예) `((A + B) * C`
- 스택에 가장 최근에 Push한 괄호는 가장 안쪽의 괄호이므로, 지금 검사하는 닫는 괄호와 종류가 같아야 한다. 그렇지 않으면 괄호 순서에 문제가 있는 것이다. 예) `{(A + B}) * C`

#### 수식 계산

일반적으로 쓰는 것은 연산자가 피연산자 가운데에 오는 <strong>중위 표기법</strong>(`A * B`)이고, 연산자가 피연산자 뒤에 오는 것이 <strong>후위 표기법</strong>(`A B *`)이다.

- 중위 표기법 `A + B * C`는 `B C *`를 먼저 만들고, 여기에 A와 +를 붙여 후위 표기법 `A B C * +`가 된다.
- 중위 표기법 `A - (B + C) * D`는 `B C +` → `B C + D *` → `A B C + D * -` 순서로 후위 표기법이 된다.

후위 표기법은 중위 표기법과 달리 괄호 없이 피연산자와 연산자로만 이루어져 있고, 각 요소를 읽어 가며 바로 계산할 수 있다는 장점이 있다. 아래에서는 피연산자와 연산자를 묶어 <strong>토큰</strong>이라 부른다.

`A B C + D * -`라면 A, B, C를 차례로 스택에 넣고, `+`가 나오면 B와 C를 Pop해서 더한 다음 결과를 Push한다. D를 Push하고 `*`가 나오면 D와 `B+C`를 Pop해서 곱한 결과를 Push하고, `-`가 나오면 A에서 `(B+C)*D`의 결과를 빼면 끝이다(<FigRef n={3} />).

<Fig n={3} src="/img/notes/ds/stack/postfix.png" caption="후위 표기식 계산 중 스택의 변화" max={720} />

즉, 왼쪽에서 오른쪽으로 읽어 가며 토큰을 처리하고, 처리 방향이 일관된다. 규칙은 세 가지이다.

1. 피연산자를 만나면 스택에 Push
2. 연산자를 만나면 연산에 필요한 만큼 피연산자를 Pop
3. 연산 결과를 다시 스택에 Push

노드의 데이터를 구조체로 만들고, enum class로 피연산자와 연산자의 종류를 구분하며, 피연산자일 때는 int로 값을 저장했다. 배열의 크기만큼 반복하면서 피연산자는 바로 Push, 연산자는 피연산자 2개를 Pop해 연산한 뒤 다시 Push한다. 이를 반복하면 마지막에 남은 하나의 토큰이 연산 결과가 된다.

이번에 구현한 스택은 Pop할 때 노드를 새로 할당하기 때문에, 피연산자 2개를 Pop해 연산하고 결과를 Push한 뒤에는 꺼낸 노드의 메모리를 꼭 해제해야 한다.

#### 표기법 변환

중위 표기법을 후위 표기법으로 바꾸는 가장 기본적인 규칙은 <strong>피연산자는 바로 출력, 연산자는 일단 스택에 보관</strong>하는 것이다. 연산자를 보관할 때는 Peek로 스택 꼭대기의 연산자와 우선순위를 비교해서, 꼭대기 연산자를 출력할지 그대로 쌓을지를 결정한다.

- 스택 바깥 연산자의 우선순위가 꼭대기 연산자보다 <strong>작거나 같으면</strong> 꼭대기 연산자를 Pop해서 출력한다. 예) 스택에 `*`, 바깥에 `+`이면 `*`를 출력하고 `+`를 Push
- 반대로 바깥 연산자의 우선순위가 더 높으면 그대로 Push한다. 예) 스택에 `+`, 바깥에 `*`이면 `*`를 Push

괄호는 어떻게 처리할까? 여는 괄호 `(`는 <strong>스택 안에 있을 때는 우선순위가 가장 낮고, 스택 밖에 있을 때는 가장 높다</strong>. 밖에서 들어오는 `(`는 무조건 Push되고, 스택 안의 `(` 위에는 어떤 연산자든 무조건 Push되게 만들기 위해서이다.

<div class="tbl">

| 연산자 | 스택 안 우선순위 | 스택 밖 우선순위 |
|---|---|---|
| `(` | 0 | 5 |
| `*` `/` | 2 | 2 |
| `+` `-` | 1 | 1 |

</div>

switch문에서 `(`일 때 무조건 Push하면 되지 않을까 싶지만, 후위 표기법으로 변환할 때는 결국 스택 안과 밖의 우선순위를 비교하므로 상황에 따라 다른 우선순위를 갖는 편이 로직이 일관된다.

이렇게 `(`는 출력되지 않고 스택 안에 자리 잡아 뒤에 들어오는 연산자들을 담아 둔다. 그리고 닫는 괄호 `)`를 만나면 `(`를 만날 때까지 스택의 연산자를 모두 Pop하여 출력한다. 규칙을 정리하면 다음과 같다.

1. 피연산자를 만나면 바로 출력
2. 연산자를 만나면 일단 스택에 보관
3. 단, 스택에 보관 중인 연산자 중 우선순위가 높은 연산자는 출력
4. (주의) 스택 내부와 외부에서 연산자의 우선순위가 다르다.
5. 닫는 괄호를 만나면 여는 괄호 `(`를 만날 때까지 스택에 저장된 연산자를 모두 Pop하여 출력
6. 수식을 다 읽으면 스택에 남은 연산자를 모두 Pop하여 출력

`A - (B + C) * D`를 변환하는 과정은 다음과 같다.

<div class="tbl">

| 토큰 | 처리 | 스택(아래→위) | 출력 |
|---|---|---|---|
| `A` | 피연산자 출력 | | `A` |
| `-` | 스택이 비었으므로 보관 | `-` | `A` |
| `(` | 밖의 `(`는 우선순위 5 → 보관 | `- (` | `A` |
| `B` | 피연산자 출력 | `- (` | `A B` |
| `+` | 안의 `(`는 0 → 보관 | `- ( +` | `A B` |
| `C` | 피연산자 출력 | `- ( +` | `A B C` |
| `)` | `(`까지 Pop하여 출력 | `-` | `A B C +` |
| `*` | `*`(2)가 `-`(1)보다 높음 → 보관 | `- *` | `A B C +` |
| `D` | 피연산자 출력 | `- *` | `A B C + D` |
| 끝 | 남은 연산자 모두 출력 | | `A B C + D * -` |

</div>

```cpp
void LinkedListStack2::ConvertInfixToPostFix(Token *pTokenArray, const int &iTokenCount)
{
	// ... 코드 중략
	for (int i = 0; i < iTokenCount; ++i)
	{
		Token &tToken = pTokenArray[i];

		if (tToken._eType == PRECEDENCE::NONE)
			continue;

		if (tToken._eType == PRECEDENCE::OPERAND)
		{
			std::cout << tToken._iValue << ' ';
		}
		else
		{
			StackNode *pPrintNode = nullptr;

			switch (tToken._eType)
			{
			case PRECEDENCE::L_PAREN:
			{
				srcStack.Push({ tToken , });
			}
			break;
			case PRECEDENCE::R_PAREN:
			{
				pPrintNode = srcStack.Pop();
				while (pPrintNode && pPrintNode->_tData._eType != PRECEDENCE::L_PAREN)
				{
					TypePrint(pPrintNode->_tData._eType);
					delete pPrintNode;

					pPrintNode = srcStack.Pop();
				}
			}
			break;
			default:
			{
				if (srcStack.Peek())
				{
					if (OutStackPrecedence(tToken._eType) <= InStackPrecedence(srcStack.Peek()->_tData._eType))
					{
						pPrintNode = srcStack.Pop();
					}
				}
				srcStack.Push({ tToken , });
			}
			break;
			}

			if (pPrintNode)
			{
				TypePrint(pPrintNode->_tData._eType);
				delete pPrintNode;
			}
		}
	}

	if (srcStack._iElementCount > 0)
	{
		StackNode *pPrintNode = nullptr;
		while (srcStack._iElementCount != 0)
		{
			pPrintNode = srcStack.Pop();
			TypePrint(pPrintNode->_tData._eType);
			delete pPrintNode;
		}
	}
}
```
